每段原片首先全图搜索；双标签成功解码后，自动确定带余量的活动区域，在区域内逐帧检测。区域随有效观测扩展，每 30 帧回到全图重定位；开始时尚未找到双标签则继续全图搜索，输入尺寸变化会重置区域。标签突然移出区域时，最多等待 29 帧重定位，期间保留缺失值。唯一性在当前搜索区域内判断，定期全图搜索可发现区域外的重复标签。无需手填 ROI，也不把前帧位置作为当帧测量。

完整模式的主检测沿用 main 的双 ArUco 参数；目标缺失时，在当前搜索区域的同帧锐化图上以较小的自适应阈值常量补检。仍缺失时，从两次检测返回的未解码四边形中选择候选区域，保留周围边距后放大 2 倍、3 倍重试，最后尝试锐化的 3 倍图。

detect-width 的快速模式针对小标签使用 7～23 像素、步长 4 的五个阈值窗口，每个解码格子取 8×8 像素并忽略 25% 的格子边缘。主检测的阈值常量为 7，同帧锐化补检使用 2，以保留暗标签边缘；去掉 3 像素窗口减少噪声候选的开销。不模糊或放大源图，不增加检测轮次和纠错位数；高密度格子采样只发生在候选四边形的规范图像内。完整模式和场景宽度提取保持原有阈值设置。两种模式的补检均拒绝给已识别的同一物理标签追加另一个 ID。检测策略改变可能使共有检出帧的中心估计略有变化，测量锚点应使用一致的处理方式核验。

快速补检使用 `2 × 灰度图 − GaussianBlur(灰度图, sigma=2)` 增强局部对比度，使暗标签格子更容易解码；完整模式的 sigma 仍为 1。模糊图仅用于锐化差分，不作为独立的平滑检测输入。该设置无需额外 CLI 参数；单纯放大 --contrast 并非越大越好，应结合实际标签框检查饱和和漏检。

候选区域合并嵌套框，过滤过小、过大和过细的区域，每帧最多处理 96 个；补检仍须通过同一字典的 ID 解码，不放宽编码纠错。局部放大坐标按 OpenCV 像素中心关系 `(scaled + 0.5) / scale - 0.5 + crop_origin` 换回搜索区域，再加活动区域偏移还原原始半幅坐标；只接受中心落在候选附近的结果。重叠裁剪读出的同一物理标签合并，不能给已有标签分配另一个 ID；分离的同 ID 标签仍视为歧义。补检无法保证每帧成功。

分段线性像素—毫米映射继续复用 `width_4k60.py`。使用原片前镜头的完整 1920×1920 半幅，标记字典为 `DICT_4X4_50`，ID 为 0 和 1；不使用缩小/裁切后的 `front.mp4` 估计毫米宽度。

| 文件 | 场景集成职责 |
|---|---|
| `calibration.py` | 校验 anchors 与开口范围 |
| `detection.py` | 共享逐帧标签框、ID、中心距离检测；按原片和检测器缓存原始距离 |
| `preview.py` | 输出叠加定位框、ID、距离和原片时间的 H.264 预览 |
| `monitor.py` | 固定 ROI、按视频时间采样的快速检测、CSV 与采样帧 MP4 输出 |
| `pipeline.py` | 换算毫米、邻近三帧中位数、短缺口插值、内存宽度序列与报告构造 |
| `series.py` | 时间序列、缺失值、来源编码、CSV 与训练时间重采样 |

宽度测量直接保存在套件目录，由 kit.yaml 各手的 gripper.width 引用相对 JSON 路径。run 在输入入口读取文件，并保存副本与内容哈希，episode.json 保留一份规范化测量与宽度报告，修改文件后重跑即可。插值上限、闭合阈值和诊断开关由 scene_parameters.yaml 管理，原片检测缓存不依赖它们或测量 JSON。pipeline 返回对齐后的 WidthSeries 和报告，由场景结果写入器与 TCP 一次合写 trajectory.csv；不单独输出宽度 CSV。开启诊断后才额外写出原片逐帧 CSV。

无标定的任务继续只输出轨迹；已配置的标定缺失、格式无效或检测出错时任务失败，保留上次成功入口。没有找到标记会保存缺失值，不会当作闭合。超出最大标定开口的结果不作为有效测量，不用短缺口插值掩盖。

`legacy/apply_width.py` 的同日单标记拟合，以及 `legacy/pilot.py` / `legacy/split_tasks.py` 的糖果取放标记与切分规则保留为独立分析工具，不自动应用到通用场景。`apply_width.py` 需要额外的 pandas；场景双标记主流程使用已有 OpenCV/ArUco、PyAV 和 NumPy，不依赖 pandas。

像素距离预览入口为 `./umi-calib preview-width INPUT.insv [--out OUTPUT.mp4]`，使用基础环境，无需宽度 JSON 或 Basalt。与场景检测共用解码灰度和检测器，保留原片帧间时间，输出的 960×960 画面标注原始 1920×1920 像素距离；缺失/重复目标 ID 显示 N/A。编码失败不发布半成品，已有目标文件拒绝覆盖。

预览支持 `--roi LEFT TOP RIGHT BOTTOM`，以原始前镜头半幅坐标固定检测区域；先裁剪再检测，恢复活动区域偏移后叠加到完整预览。固定范围不自动扩展或全图重定位。ROI 仅影响此次预览，不写入套件或场景参数。

无界面检测使用 `./umi-calib detect-width INPUT.insv --roi LEFT TOP RIGHT BOTTOM [--hz 30] [--out OUTPUT.csv] [--video-out OUTPUT.mp4 | --no-video] [--benchmark]`。默认按原片 PTS 以目标频率采样，按原速输出；落后时跳过过期采样，缺失值不沿用前帧。`--benchmark` 不等待、不丢弃计划采样，用来测量包含解码和可选编码的吞吐量。CSV 默认写标准输出，统计摘要写标准错误。

CLI 默认在原片旁保存 `<原名>_width_detect.mp4`，可指定视频路径或关闭视频。MP4 与 CSV 共用同次检测，逐帧显示标签框、ID、中心距离、原片时间和蓝色 ROI 框。检测坐标恢复为原始半幅，显示单独缩小至 960×960；采样或丢样的 PTS 保留，首帧时间归零。CSV 和视频均使用临时文件，成功后发布，拒绝覆盖已有输出。Python `monitor.run()` 的 `video_output=None` 可供只需 CSV 的调用者使用。

PreviewWriter 集中处理图像缩小、叠加、原始 PTS 和 H.264 编码，供 preview-width 与 detect-width 共用；快速监测默认使用 veryfast 预设，开启对比度增强时使用 ultrafast 为检测预留时间，两者均为两个编码线程。增强视频可能更大。CSV 的 detect_ms 不包含编码，最终吞吐统计包含编码及文件关闭。

两个宽度 CLI 均支持 `--contrast GAIN`，默认 1，暗光建议先试 2。只对检测区域做线性灰度增益和饱和裁剪，再执行原有检测与同帧锐化，不追加检测轮次；MP4 对相同 ROI 施加显示增益并标注倍率。几何坐标和源文件不变，但解码结果可变化。快速增强模式将最小标记周长提高到 24 原始像素以抑制噪声；未增强时保持原有门限。增益仅用于此次运行，未接入场景宽度配置。

monitor 对 8 位 YUV420 原片先按色度采样边界裁剪三个平面，保留颜色空间和量程，再转换 ROI 灰度并裁到精确范围；支持奇数坐标，其他格式使用标准灰度转换回退。快速检测跳过候选放大，按原始半幅的最小像素周长限制过滤微小噪声。该入口使用 4 个解码线程，运行期间将 OpenCV 限为单线程，结束恢复调用前设置；不修改场景流程的线程策略或测量锚点。输出坐标恢复为原始半幅像素，不使用毫米换算。

配置、标定格式、产物和训练字段见 [训练数据指南](../../docs/训练数据.md#夹爪宽度标定与接入)。主流程不使用历史脚本按固定 FPS 推算任务时间，也不把原片 `2*k` 帧号当成生成视频的帧号。
