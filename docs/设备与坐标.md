# 设备、目录与坐标

本文集中说明全局设备资产、套件、场景批次、地图版本、TCP 几何和坐标约定。

## 设备、套件与目录

[文档导航](README.md) · [场景命令](场景处理.md) · [标定操作](标定.md)

采集层次为 **套件、场景 → 批次 → 任务**。套件配置独立保存，场景批次清单记录所使用的套件；相机标定和夹爪测量按设备全局保存。相同套件可直接用于多个场景，不复制标定文件。

## 目录

```text
registry/                                   全局设备实测资产
├── index.json
├── cameras/<完整序列号>/
│   ├── calibrations/<版本>/
│   └── gripper_width/<版本>/width_calibration.json
└── grippers/<夹爪ID>/
    ├── current.json                         默认几何版本
    └── <三位版本>/                          TCP、遮手图与校验清单

recordings/calibration/<序列号>/<标定批次>/front/   全局标定原片

scenes/<场景>/
├── scene.yaml                              可选的场景参数覆盖
├── .umi/maps/                              自动生成的共享地图
│   ├── current.json
│   └── versions/<地图版本>/
└── <采集批次>/
    ├── batch.yaml                          用户声明套件及可选使用手/复用地图
    ├── mapping/                            本轮建图原片
    ├── pending/                            仅未分组原片的待配对区
    ├── .umi/
    │   ├── manifest.yaml                   当前设备、建图来源和地图的解析记录
    │   └── import.json                     最近一次有变化或问题的导入报告
    └── <任务>/
        ├── left/                           左手操作原片
        ├── right/                          右手操作原片（单手只需对应一侧）
        ├── results -> .umi/runs/<运行>/     当前成功结果
        └── .umi/
            ├── episode.yaml                原片引用；可补充指令与同步
            ├── state.json                  尝试和人工验收引用
            ├── cache/                      可重新生成的缓存
            └── runs/<运行>/                成功产物或失败诊断

kits/<套件>/
└── kit.yaml                                 可跨场景复用的左右设备和测量配置
```

原片以 INSV 内部完整序列号为准，保留原名、内容和 SD 卡源文件。建图原片位于每个批次的 `mapping/`，任务原片直接位于 `take_*/left/`、`take_*/right/`。预先按 take 放好的原片直接引用，外部原片在确定任务后复制到对应任务的左右手目录。只有尚未明确任务归属的原片留在批次 `pending/`，清单保存成功后将已分配的 pending 副本清除。放好 batch.yaml 和视频后，umi-scene run 自动登记。

旧任务的 `take_*/videos/left/`、`right/` 仍支持原地读取；已有原片和清单引用不会因目录规范变更自动搬动。后续导入的新原片直接使用任务下的 `left/`、`right/`，旧任务可继续处理和补片。


`.umi/state.json` 只保存处理尝试和人工验收记录，运行引用固定本次尝试，错误原因和失败检查报告路径从运行目录读取；身份与使用手从清单读取。状态需与任务清单、成功结果一起保留；`.umi/cache/` 是可重建数据。`results` 只在新运行成功后更新，失败不会覆盖旧成功结果。成功运行目录包含统一的 `episode.json`、`report.txt`、各手 `traj_tcp.txt` 与 `front.mp4`，双手任务另有 `bimanual.csv`；检查全文保存在 `episode.json` 的 `preflight` 中。失败目录用 `error.json` 集中保存错误摘要和调用栈；相同输入、相同原因的失败去重，通过原片检查后算法失败也保留独立的 `preflight_report.json`。

套件可用 `--width-left` / `--width-right` 固定各手的宽度标定，已有批次不随之改变。配置后，各手新增 `gripper_width.csv` 和检测报告；无标定继续仅处理轨迹。详见 [宽度标定与接入](训练数据.md#夹爪宽度标定与接入)。

场景任务的展示地图只保存在 `.umi/maps/versions/<地图版本>/map.json`，任务 `episode.json` 的 `map` 保存相对运行目录的路径与内容哈希，左右手共享。移动场景数据时应保留地图和任务之间的相对结构。

## 身份和版本

| 对象 | 固定内容 | 何时新增 |
|---|---|---|
| 标定版本 | 相机测量、验收与资产哈希 | 重新标定并手动 install |
| 夹爪版本 | TCP、遮手图、测量来源 | 安装几何或夹爪改变 |
| 宽度标定版本 | 对应相机与夹爪安装的像素—毫米锚点、核验状态 | 重新测量或安装变化 |
| 套件配置 | 当前各手序列号、标定、夹爪版本及宽度标定 | 换设备、换手或采用新测量时更新 `kits/<套件>/kit.yaml` |
| 批次 | 当前套件选择、采集轮次与原片 | 新采集活动；配置调整可重跑原批次 |
| 地图版本 | 米制场景坐标、地图资产 | 显式重新建图 |
| 任务 | 一次操作的原片与预期使用手 | 重新录制一次操作 |

套件可以只有左手或右手。任务允许使用批次所声明手的非空子集，必须显式声明。双手任务缺片保持不完整，不会降为单手。

场景名称和当前套件 ID 从目录读取；批次和任务不保存可推导的上级清单路径。批次默认使用当前套件中的全部手，任务默认继承批次；只有改变预期使用手时才写 `expected_arms`。原片缺失不会改变这个默认值。单手不写 `synchronization`，双手未配置同步时保持零偏移、未经确认。

空备注和未设置的覆盖项省略。批次仍完整保存套件 ID、相机与测量版本快照，本轮建图完成后写入固定地图版本及校验值；原片引用仍包含序列号和 SHA256。

`registry/index.json` 只记录设备状态、默认标定编号，以及偏离全局 `default_gripper` 的夹爪覆盖。设备序列号取自键名，不重复写入条目；标定来源保存在对应标定的 `manifest.json`，不在索引重复写备注。读取时程序自动补齐序列号和默认夹爪，登记、停用和启用版本都维持这个精简格式。

日常配置 kit.yaml 和 batch.yaml，再用 `./umi-scene run <批次>` 处理；手动选版本时查看 `kits/<套件>/kit.yaml`。`registry/` 中的测量矩阵和 `manifest.json` 属于程序管理的资产，不需要同时编辑。夹爪几何只保存一种方向的变换，推导依据见 [TCP 坐标系](设备与坐标.md)。

登记套件时读取当前默认标定和几何，写入唯一的 `kits/<套件>/kit.yaml`。创建批次时校验测量资产并自动保存设备快照到 `.umi/manifest.yaml`；run 始终读取当前套件；修改后重跑即生效，移除套件会明确报缺少配置。历史运行保存当时使用的测量版本，实际测量资产仍需保留并通过哈希校验。

一轮建图及后续多个 take 组成一个批次。`batch.yaml` 选择套件，`kit.yaml` 选择设备与测量版本。每次 run 都读取这两份配置和当前 mapping/ 中的原片，更新 `.umi/manifest.yaml` 的解析记录。单段建图直接保存 serial、path、sha256，没有 left/right 标签；实际相机按 INSV 序列号匹配。dual 才按左右两段记录。

换标定或替换建图原片后重跑当前批次即可；程序核对地图的录像、测量、参数和算法身份，匹配才复用。宽度标定等与建图无关的变化复用原地图。历史成功结果及失败记录保存当时的输入，重新计算不会改写其测量和轨迹。明确复用已有地图时，使用 batch.yaml 的 map_version。

```bash
./umi-calib install <calibration_result目录>
./umi-calib install-rear <rear_calibration.json>
./umi-calib install-gripper handheld_v1 <TCP与遮手图目录>
./umi-calib devices
./umi-calib retire <完整序列号>
```

停用设备不能用于新的套件或批次；历史批次仍可用已固定测量处理与查看。资产哈希始终校验，不退回当前默认值或样例后镜头。

## 命名与跨场景使用

清单由命令生成，实际设备和地图版本由程序固定。

前镜头标定编号按每台相机独立递增为 `001`、`002`……；重复登记相同标定沿用编号，文件内容仍校验完整 SHA256。YAML 中写成 `calibration: '001'`，保留引号以免被读成数字。

夹爪几何同样按夹爪型号独立编号为 `001`、`002`……，直接放在 `registry/grippers/<夹爪ID>/<编号>/`，不再嵌套 `versions/`。相同 TCP 和遮手图重复登记沿用编号；更新内容则新增版本，并更新 `current.json`。套件中的 `gripper_version: '003'` 固定实际版本，修改套件中的版本后重跑当前批次即可生效；历史运行保持原版本。

套件 ID 在项目内唯一，批次名在场景内唯一，任务名在批次内唯一。批次推荐 `20261025_001`，任务推荐 `take_001`。相同套件跨场景使用时，批次清单明确记录套件；系统不猜拍摄场景。


内部逐段轨迹引擎仅供标定 C 验证与开发使用，日常从场景批次发起处理。


## 旧标定包升级

旧 v1 包仍可只读使用，其中脚本不参与计算。需要整理为仅含测量与来源元数据的 v2 包时，先预览，再新增版本：

```bash
./umi-calib upgrade-device CAMERA_SERIAL --dry-run
./umi-calib upgrade-device CAMERA_SERIAL
# 按上一条命令返回的 version 显式启用；不需要切换时停在上一步
./umi-calib activate-calibration CAMERA_SERIAL 002
```

升级保留原标定版本，不自动修改设备默认值或历史套件/批次。显式启用只改变设备默认标定；新建或更新套件才采用新值。样例借用设备不能通过升级变为实测设备。

## TCP 坐标系

当前默认采用与 Genie omnipicker 机器人一致的机械轴向约定，标识为 `genie_omnipicker_axes_v1`。左右手使用相同的工具自身轴向定义。

## TCP 原点和三轴

原点仍是**夹爪闭合时，两指尖接触位置的中点**。本次只改轴向，保留原相机到指尖的平移。

| 轴 | 正方向 |
|---|---|
| +X | 从外侧指指向内侧指，用户确认内侧指位于前镜头画面左侧 |
| +Z | 从夹爪本体指向指尖 |
| +Y | 按右手规则确定，即 `Y = Z × X` |

三轴固定在夹爪上并随它运动。+Z 使用本项目既有 CAD 中的本体到指尖方向，与前镜头光轴约有 21.5° 倾角，不再与镜头朝向重合。位置和倾角仍是 CAD 名义值；轴向约定的统一不构成新的物理标定。

## 机器人依据与相机坐标

轴向依据 `genie_robot_description/urdf/G2_t2_crs/G2_t2_crs_omnipicker.urdf` 的 `gripper_l_center_link`、`gripper_r_center_link`：二者相对夹爪基座均绕 Z 转 −90°，因此 +X 沿基座 −Y、+Y 沿基座 +X、+Z 沿基座 +Z。基座中内侧指在 −Y，外侧指在 +Y。

URDF 中的 `camera_link` 是机械 link，其三轴与夹爪基座平行，并非本项目 X3 的光学坐标系。这里使用本项目的相机—指尖 CAD 外参和用户确认的手指方向计算旋转；没有将 URDF 的 `Rz(-90°)` 直接当作光学相机到 TCP 的旋转。

## 与 wholebody VR 数采的区别

wholebody 当前记录的是 `arm_l_end_link` / `arm_r_end_link` 的**末端法兰位姿**，尚未自动换算到 `gripper_*_center_link`。本项目 `traj_tcp.txt` 则已经通过相机到指尖的几何换算为**夹爪 TCP 位姿**。工具轴向约定相同，不代表两套输出记录了同一个参考点。

机器人实测与目标都需要先使用实际安装的 `T_end_tcp` 换算法兰到 TCP；随后再统一父坐标系或转换为一致的相对位姿表示。wholebody 新录制已将 VR 目标转换到 `base_link`；修复前的 `arm_base_link` 目标数据需单独核对和转换，字段定义见 wholebody 项目的 `docs/user/collect/schema.md`。

对于 `G2_t2_crs_omnipicker.urdf`，左右 `T_end_tcp` 的平移均为法兰系下 `[0, 0, 0.14918]` m；左侧旋转为单位阵，右侧旋转为 `diag(-1, -1, 1)`，即绕法兰 Z 转 180°。这里比较的是各侧法兰与该侧夹爪 TCP，左右夹爪自身仍采用相同的机械轴向定义。完整矩阵、固定关节来源、四元数顺序及正反换算见 wholebody 项目的 `docs/user/collect/schema.md`。

## 程序怎样计算

采用 `T_a_b` 将 b 系坐标变换到 a 系的约定。当前相机到 TCP 外参约为：

```text
R_camera_tcp ≈
[ -1   0           0          ]
[  0  -0.93041757 -0.36650123 ]
[  0  -0.36650123  0.93041757 ]

t_camera_tcp = [-0.0001815, 0.0369877, 0.1650461] m

T_scene_tcp = T_scene_camera × T_camera_tcp
```

旋转从原机械 CAD 定义导出：保留 +Z，将原 CAD 的 X、Y 同时反向以匹配“内侧指在画面左侧”的确认。相机中的指尖位置保持原值。资产只保存 `T_camera_tcp` 的旋转矩阵和平移；逆变换、四元数及杆臂长度在需要时计算，不重复保存。

## 与场景坐标系的关系

场景坐标系固定在环境中，+Z 朝上；TCP 坐标系随夹爪运动。

- `traj_tcp.txt` 的 `x y z` 是 TCP 原点在场景中的位置，单位米。
- `qx qy qz qw` 是 TCP 自身三轴相对于场景三轴的朝向。
- 双手使用同一地图版本时共享场景坐标。独立 内部逐段轨迹引擎 的世界坐标每段分别建立。

本次统一工具轴向不提供场景到机器人基座的外参，也不改变机器人控制器的 TCP 配置。部署仍需确认控制器实际使用的工具坐标系。

## 旧结果与新结果

旧资产不可覆盖，各版本按自己的定义读取：

| 版本或约定 | TCP 轴向 |
|---|---|
| `001` | 原机械 CAD 轴，开合方向正负未与机器人对应 |
| `002` / `front_optical_parallel_v1` | 与前镜头平行，+X 图像右、+Y 图像下、+Z 镜头前方 |
| `003` / `genie_omnipicker_axes_v1`（当前默认） | 本文定义的机器人机械轴，+X 外侧指向内侧指、+Z 本体指向指尖 |

这些版本直接保存在 `registry/grippers/handheld_v1/001/`、`002/`、`003/`，`current.json` 指定默认编号。TCP 原点位置相同，姿态约定不同。默认版本改变后，独立 内部逐段轨迹引擎 的新运行读取新默认；已有场景套件和批次仍固定原版本。已有结果不会改写。

已有套件需要采用新约定时，用实际序列号更新套件，再创建新批次：

```bash
./umi-scene kit kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL
./umi-scene session scenes/shelf --name 20261026_003 --kit kit_001
```

新批次继续复用场景地图，无需因工具换轴重新建图。新运行的实际 `tcp_frame` 写入轨迹文件头和场景 `episode.json` 的 `tcp_frames`，并随导出保留；各手实际 TCP 外参保存在 `arm_results.<手>.T_camera_tcp`。

## front.mp4 的来源

程序从 X3 原始 `.insv` 中提取前镜头画面并生成 `front.mp4`，用于查看和核对手指方向。双手场景结果分别位于 `<任务>/results/left/front.mp4` 和 `<任务>/results/right/front.mp4`；独立轨迹结果位于 `<输出目录>/front.mp4`。原片无需另行拍摄或上传这个 MP4。

## 资产位置

几何的唯一资产来源是 `registry/grippers/<夹爪ID>/<版本>/t_tcp_camera.json`，例如 [handheld_v1/003](../registry/grippers/handheld_v1/003/t_tcp_camera.json)。新采集通过 `current.json` 选择默认版本，已有批次使用自己的固定版本。轨迹计算和来源报告都必须接收已选择的几何路径，缺失时直接报错，不再另找内置几何。坐标轴展示文字也从该资产的 `tcp_frame` 字段生成。

几何文件只保存 `status`（测量状态）、`units`（米）、`tcp_frame`（工具坐标约定）和 `T_camera_tcp`（TCP 点到相机坐标的变换）。版本号来自目录；日期、推导及依据统一记录在下文。`manifest.json` 由程序保存型号、版本和完整资产 SHA256，用于校验；它不是日常配置，不需要手动维护。

## CAD 测量与轴向依据

以下是从几何文件归入本文的工程记录，不参与运行时配置。

- `001` 的 CAD 定义日期为 2026-08-28；`002`、`003` 的轴向定义日期为 2026-10-26。三者的指尖位置完全相同：`[-0.0001815, 0.0369877, 0.1650461]` m；杆臂约 169.14 mm。`002` 只将工具轴改为前镜头平行；`003` 保留原 CAD 的 +Z，翻转 X/Y 并将原 CAD 四舍五入后的旋转投影到 SO(3)。
- 原始来源为 SolidWorks 装配 `hardware/修改夹爪/夹爪整体装配.SLDASM`（2026-08-28 12:49）和 `Insta360 X3.SLDPRT`，分别以 TCP 和 CAM0 为输出坐标导出 `handheld_closed_in_TCP.step`、`handheld_closed_in_CAM0.step`。使用 7 个顶层部件锚点，通过集合差、成对距离特征匹配和不带缩放的 Umeyama 刚体拟合求解，历史复算脚本名为 `solve_t_tcp_camera_final.py`；STEP 文件 SHA256 记录在原运行日志中，当前仓库未附这些源文件。
- 原拟合 RMS 为 `5.355e-6` mm，最大残差 `7.525e-6` mm，尺度 `1.000000001`，旋转行列式为 1，正交误差 `1.33e-15`，往返误差 `1.11e-16` m。这些数值仅验证 CAD 坐标换算，不能代表实物精度。
- 相机系为前镜头光学约定：+X 图像右、+Y 图像下、+Z 镜头向外。光学原点采用裸镜片外顶点后方 2.5 mm。依据是用户卡尺测得前后裸镜片顶点间距 31.1 mm，与 CAD 球面顶点 `z=+2.5000/-28.6000` mm 一致；INSV 厂家有效视点基线取 26.10 mm（field54 为 26.345 mm，field53 为 25.851 mm），深度按 `(31.1-26.10)/2=2.50` mm 估计。前镜片 CAD 球面半径为 24.7115 mm，球心位于 `z=-22.2115` mm，轴线偏差小于 `1e-4` mm。
