# 轨迹抽取

[文档导航](../README.md) · [任务录制](录制.md) · [结果说明](结果.md) · [三维查看](../查看.md)

运行前完成[安装](../安装.md)，并为录像所属相机[标定并手动启用](../标定/说明.md)。输入为原始 X3 360 4K60 `.insv`，包含可读的时间戳与 IMU；默认拒绝丢帧录像。

## 运行命令

从项目根目录执行，序列号和日期按实际替换：

```bash
# 处理目录直接包含的全部 .insv，不递归进入子目录
./umi-traj recordings/IAQEB26097M4CP/tasks/20261023

# 只处理一段
./umi-traj recordings/IAQEB26097M4CP/tasks/20261023/VID_20261022_225713_00_005.insv
```

结果默认写入第一项输入旁的 `umi_traj_out/<录像名>/`。也可以指定多个视频或目录；同一批中的录像名称不能重复，避免覆盖结果。设备和夹爪选择见 [设备与目录](../设备与目录.md)。

## 参数

`./umi-traj --help` 显示全部选项。

| 选项 | 作用 |
|---|---|
| `--out DIR` | 指定输出根目录，每段仍使用 `<录像名>/` 子目录 |
| `--mode handheld` | 默认：前镜头与 IMU，适合手持录制 |
| `--mode dual` | 前后镜头与 IMU，适合后镜头能看到环境的场景；当前安装方式的完整实录回归证据以 handheld 为主 |
| `--jobs N` | 同时处理的录像数，默认 1；每段通常使用约 4 个核 |
| `--cores 0-7` | 限制使用的 CPU；建议与 `--jobs 1` 配合 |
| `--max-tries N` | 整轮重建尝试的总次数上限，默认 3；1 表示不重试 |
| `--keep-work` | 保留数据集、共享镜头视频与全部重建中间数据 |
| `--force` | 强制重新处理，不检查旧结果能否复用；仍先校验输入与标定 |
| `--allow-irregular` | 允许丢帧录像并使用真实帧时间，该路径尚未验证 |
| `--device SERIAL` | 显式选择设备档案，覆盖录像内部序列号，供工程对照 |
| `--gripper ID` | 覆盖设备档案中的夹爪选择 |

## 终端进度与重试

主流程显示四步：

1. 读取录像时间戳和 IMU。
2. 准备镜头视频，供所有重建尝试共用。
3. 重建轨迹：建图 → 逐图定位与合并 → IMU 融合。
4. 生成相机/TCP 轨迹、视频与报告。

重建内部会显示 `[第 1 次] 建图` 等阶段。执行失败，或结果中独立地图放置多于一次、地图位置约束帧比例低于 95% 时，按 `--max-tries` 重试完整的建图、定位和融合。视频只裁切一次；重试共用这份视频。优先选择地图放置次数少、地图位置约束比例高的一轮。

`[完成]` 表示成功生成产物，不表示已测量真实精度。`[跳过]` 表示复用已有成功结果；`[失败]` 显示阶段和原因。进入处理后的完成或失败会给出报告与日志路径；输入和标定预检查失败时尚未生成新报告。

## 再次运行会发生什么

复用要求录像路径、大小、修改时间，标定/夹爪等资产内容，以及模式、丢帧处理选项和最大尝试次数一致，且必要产物完整。修改这些输入后重跑同一命令会重新计算，终端说明原因。

复用判断不重新计算整个大视频的哈希。人为替换视频却保留大小和修改时间，或升级轨迹算法、外部二进制后，应加 `--force`。已有结果复用时会整理历史目录布局，轨迹数值保留，已有独有中间数据保留。

## 查看结果与排错

先看每段结果的 `report.txt`，文件和字段见 [结果说明](结果.md)。成功后默认保留结果、根目录视频与日志；失败、中断或 `--keep-work` 时保留中间数据。

| 现象或失败阶段 | 下一步 |
|---|---|
| 尚未安装、依赖不完整 | 按[安装指南](../安装.md)检查依赖目录和安装日志 |
| `profile` 或帧率不支持 | 核对是否原始 360 4K60 录像 |
| IMU 无法读取 | 从相机重新拷贝原始 `.insv`，核对是否完整、是否经过导出或剪辑 |
| 相机尚未登记、已停用、哈希不一致 | 核对[设备档案](../设备与目录.md)，确认应使用的标定 |
| 帧时间不规则 | 重录，或显式加 `--allow-irregular` 试算 |
| 未生成地图、建图失败 | 检查画面清晰度、纹理和开头扫图是否带平移；见[录制步骤](录制.md#4-怎么录最重要的一节) |
| IMU 融合失败；引擎日志出现 `NO_USABLE_LENS` | 检查录像长度、平移激励及视觉与 IMU 一致性，查看融合日志 |
| 重建质量检查失败 | 查看具体指标文件和原始异常，确认融合产物是否完整 |
| 轨迹尺度明显异常、地图约束覆盖低 | 核对标定与录法，查看 `notes`；有板参考时再做独立误差验证 |
| 清理中间数据失败 | 结果仍已生成，查看清理提醒和 `debug/logs/cleanup_error.log` |

提交问题时附 `report.txt`、`details/summary.json` 和 `debug/logs/`；说明录像、相机序列号和命令。安装问题附安装日志。

## 算法配置与预检

默认值来自 `config/trajectory.yaml`。`--config 文件.yaml` 显式覆盖，常用 CLI 选项只有显式传入时才覆盖文件值。`--dry-run` 展示输入、选中标定和有效参数，不创建输出或启动算法。配置指纹决定是否重算，质量提醒规则可以独立重新评估，详见 [参数管理](../../config/README.md)。
