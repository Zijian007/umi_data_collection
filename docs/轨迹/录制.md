# 任务录像怎么录

[场景流程](../场景.md) · [独立轨迹抽取](使用.md) · [标定指南](../标定/说明.md)

## 相机与文件

使用 Insta360 X3 的 **360 视频、4K60** 模式，保留原始 `.insv`，不要剪辑、改内容或经 Studio 导出。尽量保留原始文件名，自动双手配对需要其中的开始时间。

固定安装相机、夹爪与 TCP。记录完整序列号和左右手归属，登记到套件。双手尽量同时开始、同时结束录制。训练数据需要核验共同事件的时间差，并检查首尾是否漂移；人工偏移配置见 [训练数据指南](../训练数据.md)。当前不自动估计同步，不要求制造碰撞脉冲。

尽量锁定曝光，光线允许时使用 1/240 秒或 1/120 秒快门，减少运动模糊。确认镜头干净、无遮挡，保留有纹理且相对静止的背景。原片模式和曝光检查规则见 `config/scene_parameters.yaml`；缺少曝光信息会标为 UNKNOWN。

## 一段任务

1. 开始后尽量静止约 2 秒，帮助惯性初始化；当前场景检查中不够静止给出 WARN。
2. 自然完成操作，让背景特征持续可见，避免长时间只看到白墙、手或移动的人。
3. 结束前适当静止，再同时停止双手机位。

独立 `umi-traj` 需要每段建图，宜包含带平移的环视和足够长度；纯转动难以恢复尺度。共享场景任务复用已有地图，不要求每段重新完成建图动作。场景的建图参考录像仍需要平移、旋转与足够环境覆盖。

## 采完之后

每次场景采集分别建立批次，按批次向 `umi-scene ingest` 提交原片。套件跨场景采集时不要将不同场景文件混成一个批次；软件无法仅靠序列号判断场景。缺手任务留待补齐，确实只采一手需显式声明 `--arms left` 或 `--arms right`。

```bash
./umi-scene ingest /media/sd/this_session --session scenes/<场景>/kits/<套件>/sessions/<批次>
./umi-scene run scenes/<场景>/kits/<套件>/sessions/<批次>
./umi-view scenes/<场景>
```

原片自动按场景、批次、完整序列号归档，SD 卡源文件保留。录制时记下操作指令和异常情况，处理后结合视频、轨迹、地图检查结果。

## 安装变化

更换相机要完成该设备标定并手动登记。相机相对夹爪的位置、TCP 或遮手区域改变，要更新夹爪几何与遮手图并登记新版本，再更新套件；不要直接修改已固定的历史资产。原有 TCP 采用 CAD 名义值，标定报告不能替代 TCP 几何测量。
