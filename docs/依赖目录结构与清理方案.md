# `.deps` 目录结构与清理方案

## 现状

`.deps` 是项目的部署根目录，不是单一 Python 虚拟环境。安装器把 Python、标定依赖、C++ 源码、原生库、工具和安装日志都放在这里，因此顶层看起来比较平。

当前目录及用途：

| 路径 | 大小约 | 是否运行时需要 | 用途 |
|---|---:|---|---|
| `.deps/env/` | 2.4 GB | 是 | 主运行环境，Python 3.11、FFmpeg、OpenCV、GTSAM、ORB-SLAM3 的依赖库 |
| `.deps/calib_env/` | 242 MB | 标定命令需要 | 标定专用 Python 环境；`umi-calib` 和标定测试使用 |
| `.deps/src/` | 446 MB | 重编译时需要 | ORB-SLAM3、Pangolin 等原生依赖的源码树和构建目录 |
| `.deps/pangolin/` | 2.7 MB | 是 | Pangolin 安装后的头文件和动态库 |
| `.deps/basalt/` | 84 MB | 标定时需要 | 标定用的 Basalt 预编译工具 |
| `.deps/bin/` | 18 MB | 安装/升级时需要 | micromamba 可执行文件 |
| `.deps/logs/` | 2.5 MB | 运行时不需要 | 安装和构建日志，可归档或清理 |
| `.deps/env.sh` | 很小 | 启动时需要 | 统一设置 `UMI_DEPS`、Python、ORB-SLAM3 和动态库路径 |
| `.deps/BUILD_INFO.txt` | 很小 | 排查时需要 | 记录安装时间、版本和构建产物哈希 |

## 当前不能直接删除的目录

以下目录虽然体积大，但属于有效依赖：

- 不要删除 `.deps/env/`：所有主流水线和 `insv_organizer` 的共享环境都使用它。
- 不要删除 `.deps/calib_env/`：`umi-calib` 和标定测试会使用它。
- 不要删除 `.deps/src/`：重新编译 ORB-SLAM3 或 Pangolin 时需要源码和构建目录。
- 不要删除 `.deps/pangolin/`：轨迹运行时通过 `ORB3_EXTRA_LD` 加载其中的动态库。
- 不要删除 `.deps/basalt/`：标定运行时需要 Basalt 工具。
- 不要删除 `.deps/bin/micromamba`：安装器重跑、更新或修复环境时需要它。

## 当前可以安全处理的内容

安装日志不参与运行：

```bash
find /home/zijianwang/umi_data_collection/.deps/logs \
  -type f -mtime +30 -print
```

确认不再需要后，可以只清理旧日志：

```bash
find /home/zijianwang/umi_data_collection/.deps/logs \
  -type f -mtime +30 -delete
```

不要删除最新一次安装和构建日志，出现环境问题时需要它们定位失败步骤。

## 推荐的目标布局

下一次重构安装器时，可以把部署物按职责分组：

```text
.deps/
├── runtime/
│   ├── trajectory/       # 当前 env/
│   └── calibration/      # 当前 calib_env/
├── native/
│   ├── sources/          # 当前 src/
│   ├── pangolin/         # 当前 pangolin/
│   └── basalt/           # 当前 basalt/
├── tools/
│   └── micromamba        # 当前 bin/micromamba
├── logs/
├── env.sh
└── BUILD_INFO.txt
```

这只是目标布局。当前代码、启动脚本和测试仍然使用旧路径：

```text
.deps/env
.deps/calib_env
.deps/src/ORB_SLAM3
.deps/pangolin
.deps/basalt
.deps/bin/micromamba
```

在没有完成路径适配和兼容迁移之前，不要手工移动目录。

## 后续迁移顺序

1. 把所有依赖路径集中到一个路径解析模块，不再让脚本和 Python 代码分别拼接 `.deps/...`。
2. 增加 `.deps/manifest.yaml`，记录运行环境、原生库、工具和日志位置。
3. 安装器支持新布局，并在升级时生成旧路径兼容链接。
4. 更新 `umi-scene`、`umi-calib`、`umi-view`、测试和文档，全部通过路径解析模块取目录。
5. 通过 `umi-scene check`、`umi-calib check` 和全量测试后，再删除旧兼容路径。

## 与 `insv_organizer` 的关系

`insv_organizer` 可以复用：

```text
.deps/env/bin/python
```

它只需要 Python、`ruamel.yaml` 和系统 `ffmpeg`，不需要加载 ORB-SLAM3、Pangolin 或标定环境。推荐通过：

```bash
source /home/zijianwang/umi_data_collection/.deps/env.sh
cd /home/zijianwang/insv_organizer
pip install -e . --no-deps --no-build-isolation
```

不要把 `insv_organizer` 的索引、缩略图或代理视频写到 `.deps`，这些运行数据应留在它自己的 `.workspace/` 中。
