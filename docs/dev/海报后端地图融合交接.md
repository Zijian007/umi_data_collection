# 海报后端地图融合交接（2026-11-27）

两种海报后端都已接入工作镜头 ORB 地图，使用实测 KB4 标定。独立后端的 `backends.poster_independent.front_map.pixel_weights` 和 VIO 的 `backends.poster_vio.front_map.enabled` 默认关闭。`poster_independent` 按每帧像素匹配的可信度加权地图位姿。`poster_vio` 联合估计每张子图的尺度和放置，只有位置、朝向、尺度和位姿残差通过检查的地图观测才能填补位置支持缺口。增强解验收失败时，用同一批冻结观测重算基础 VIO，沿用原有质量门限。[实现与配置说明](../03-场景处理.md#海报后端的工作镜头地图像素权重)

## 运行与查结果

在仓库根目录运行。单独验证某个后端时，将批次 `collection.yaml` 的 `backend.mode` 设为 `poster_independent` 或 `poster_vio`。

```bash
./umi-scene run scenes/test_shelf2 --force --expert-config docs/examples/poster_front_map_pixels.yaml
```

查看 `take_*/results/data/episode.json` 的 `scene.reconstruction_backend`。对启用地图且生成了子图的 VIO 任务，`scene.front_map_selection.selected` 为 `with_front_maps` 表示发布增强解，为 `without_front_maps` 表示发布基础解。回退原因在同一对象的 `rejected_reason`；被拒解的逐手证据在对应运行目录的 `poster_vio/front_map_attempt.json`。

针对原先 `test_shelf2` 上 `poster_vio` 回退的问题，已对 `front_map` 因子和求解流程完成三项收敛打磨：
- `front_map` 因子改用下降型 `Cauchy(8.0)` 鲁棒核，保留正常帧像素权重的同时避免单目地图局部漂移持续拉坏海报标签；
- `map_support.py` 在 6D 马氏距离与不确定度边界检查中叠加 `shared.visual` 单目地图漂移底噪（`effective_covariance`），同时仍拒绝大偏移异常帧；
- `propose_cull` 改用当前轮优化后位姿重三角化，并在含 `front_map` 且启用剔除时将收敛轮数上限放宽至 `max(max_rounds, 6)`（累计 15% 预算与留出集门限不变）。

更新后 `test_shelf2` 的两段 `poster_vio` 均直接发布增强解（`with_front_maps`，不再回退）：`take_001` 左/右手地图支持通过 `131/142` 与 `139/139`，最长视觉缺口降至 `0.63 s / 0.13 s`；`take_002` 左手在 7 轮内几何级数收敛归零，左/右手地图支持通过 `247/247` 与 `264/267`，最长视觉缺口均降至 `0.13 s`。

在保持数值零漂移（`golden` 位置最大差 `0.0 m`、旋转 `<= 1.15e-7°`，双板真值指标不变）的前提下，已完成全链路耗时优化：`FrontMapFactor` 迁入 C++ 扩展、`front_map` 提前到检测前并于后台可中止并行重叠、默认模式下 `front.mp4` 与特征跟踪并发预渲染、双手并行初始化、双镜头自然特征跟踪流水线并发、`KB4`/Rodrigues 预积分/`position_support_metrics`/`_natural_evidence` 批量向量化、冻结惯性子图跨轮缓存、以及非关键帧条件惯性恢复延后至收敛后单次执行。`golden` 端到端由 `67.7 s` 降至 `57.6 s`；`test_shelf2/take_001` 总耗时由 `157.0 s` 降至 `75.6 s`（联合优化 `5.3 s`，地图主线程等待 `25.1 s`）；`take_002` 总耗时由 `408.3 s` 降至 `145.6 s`（7 轮联合优化由 `110.6 s` 降至 `16.3 s`，地图主线程等待由 `99.2 s` 降至 **`2.9 s`**），二次复用 `复用 2 · 失败 0`。完整测试 `./test.sh --all` 已通过。[隔离验收目录（本机）](../../umi_traj_out/polish_eval_20261127) · [历史验收报告（本机）](../../umi_traj_out/poster_vio_map_support_uz4skeq_/release/validation.json)

## 单进程建图与重定位

`poster_vio` 开启工作镜头像素融合时，支持 `inprocess_localization` 的 `x3_mono_slam` 在建图期间缓存 ORB 特征。建图与全局 BA 完成后，驱动用同一遮罩下的特征逐子图重定位并导出 `camera_information`。旧驱动继续使用两遍流程。`front_map/logs/tracking.json` 中的 `inprocess` 字段记录实际执行路径。

重定位首帧的历史记录处理放在缓存回放入口，建图初始化失败时显式记录无位姿帧。`take_001/left` 与 `take_002/right` 恢复为单图，建图分别跟踪 `682/702`、`1314/1328` 帧。同一图集上的单进程与独立重定位 CSV 逐字节一致，涵盖 2,030 帧位姿和 409 份 `camera_information`。

`take_002/right` 在同一驱动、视频、遮罩、标定与 CPU 核上实测，ORB 建图加定位由 `69.15 + 28.47 = 97.62 s` 降为 `80.26 s`（少 `17.36 s`，约 `18%`）。建图与定位 CSV 均逐字节一致，峰值 RSS 由约 `703 MiB` 增至 `992 MiB`。[配对计时与输出（本机）](../../umi_traj_out/inprocess_acceptance_jq46v582/paired_orb)
