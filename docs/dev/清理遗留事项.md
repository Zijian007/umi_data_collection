## 当前处理约定

- 宽度、中心距快速扫描、海报角点共用首次顺序解码，各自缓存；ffmpeg 镜头视频和按需补检仍独立执行。
- 单任务调度下，双手有至少 8 个可用核心时并行重建并拆分子进程 CPU 集合；多任务调度、单手或核心不足时按手串行。任何一手失败不发布部分结果。
- 同次批量运行每批只构建/校验并绑定一次地图，后续任务核对自身标定并复用；配置变化阻止后续任务复用，已开始的任务按冻结配置完成；原片或固定地图变化会阻止发布。
- 批次入库发现损坏、设备不匹配、待配对或待补齐原片时整批停止建图及轨迹处理；显式任务入口同样适用，修正后重跑。
- 批次只保存当前清单，地图和任务各自保留输入及设备副本，不再生成 `.umi/snapshots/`。原有 26 份归档已移至 `/tmp/umi-clean-final-snapshots/` 并逐文件验证哈希。
- Python 代码指纹使用去除注释、位置和文档字符串的 AST；算法变化仍失效，资产哈希继续严格按字节校验。
- rear 推导的 front 数据只读一次，由同一份字节解析并计算身份；成果导出直接核对已验收清单中的哈希。

## 已核对后保留

| 位置 | 保留原因 |

| `registry/cameras/*/calibrations/<旧版本>` 与旧包读取 | registry 已改为按镜头/参数来源保存固定当前目录；历史运行读取自己的参数快照，旧编号目录仅作迁移读取；已退役手动升级/激活入口 |

| `hardware/UMI_ArU..an.pdf` | 海报布局按文件路径和 SHA256 引用 |

只有 `tag_distance` 的套件仍缺少训练 `gripper` 开合通道。两标签中心距与夹持面开口不是同一测量，需要实物宽度标定；此项已移至当前待办，不通过改字段或伪造标定消除 `training_ready: false`。
