### 4. 独立轨迹图构建仍混合所有因子职责

`software/trajectory/algorithms/fusion/graph.py:42` 的 `optimize_trajectory()` 约 210 行，静态复杂度约 67，同时创建 IMU 预积分、视觉因子、连续性因子、静止因子、杆臂先验、节点初值、优化器和证据报告。内部仍大量使用 `m`、`k`、`i`、`p_m` 等短名，镜头、帧索引、段索引和观测应改成 `lens`、`frame_index`、`segment_id`、`lens_pose` 等领域名。

建议按“参数与噪声模型、段变量与先验、节点与 IMU 因子、视觉因子、优化和证据”拆成私有构建器；优化因子插入顺序必须由回归测试锁定。

### 命名审计

高优先级文件名与目标名：

| 当前 | 问题 | 建议 |
|---|---|---|
| `config.py` | 同时负责配置加载、参数校验、请求解析和 YAML 输出 | `configuration/loader.py` |
| `parameters.py` | 四个领域的参数模型混在根目录 | `configuration/parameter_models.py`；稳定后再按领域拆分 |
| `settings.py` | 运行时配置与算法配置名称容易混淆 | `configuration/operational_settings.py` |
| `registry.py` | 实际是相机标定注册表，却位于根目录 | `camera/registry.py` |
| `pose_io.py` | 实际只读写 TUM 位姿格式 | `trajectory/io/tum.py` |
| `dataset/source.py` | `source` 不能表达“已验收任务输入” | `dataset/accepted_episodes.py` |
| `scene/management/processing.py` | 同时发现、准备、建图、epoch、运行和清理 | 已按阶段拆分，`processing.py` 只保留编排 |
| `trajectory/algorithms/fusion/graph.py` | 文件名只说 graph，实际负责完整优化 | 当前保留算法内核，入口已使用领域命名 |

类名总体已经比文件名清楚，只有两个值得优先处理：

- `Configuration` → `AlgorithmConfiguration`，避免和 `SceneOverrides`、`Settings` 混淆；
- `OptimizedGraph` → `TrajectoryOptimizationResult`，因为对象包含优化值、节点、证据和计时，不是图本身。

函数名优先处理领域边界：

- 配置模块的 `load/current/values` 在迁移时改为 `load_configuration`、`load_operational_settings`、`current_operational_settings`、`operational_values`；
- 相机注册表的 `get/pin/register/retire/validate_id` 改为带 `camera` 或 `calibration` 语义的名称；
- `scene.management.processing` 的 `build/run/clean` 是 CLI 外部契约，外层名称保持不变，内部改为 `build_batch_maps`、`run_batch_tasks`、`clean_batch_artifacts`。

变量名只改跨多行、承载领域对象的短名：

- `fusion/graph.py` 中 `m` → `lens`，帧循环中的 `k`/`i` → `frame_index`/`sample_index`，`p_m`/`R_m` 保留为数学符号；
- `poster_scale.py` 的 `data` → `poster_observation_bundle`，并用类型对象替代裸二元组；
- `dataset/source.py` 的 `item` → `accepted_episode`、`source` → `accepted_episode`；
- `scene/management/processing.py` 的 `item`/`result` 按上下文改为 `scan_error`、`episode_record`、`map_result`、`run_summary`。

不应机械改名的内容包括 CLI 约定的 `main/run/build`、短作用域数学循环变量、GTSAM 的 `X/V/B` 符号、EuRoC 的 `data.csv`、发布协议中的 `data` 字段以及测试夹具中的外部 schema 键。这样可以降低心智负担，同时不破坏缓存、结果协议和外部数据格式。
