### 2026-11-12：未绑定 rear 时的工厂兜底

共享场景建图/任务、独立 handheld/dual 与单手回退统一支持：正式 rear 绑定优先；未绑定且需要海报/dual 时，从当前 X3 INSV 的 offset_v3 读取 rear 内参与双镜头外参，通过 `T_imu_rear = T_imu_front × T_front_rear` 组合本设备 front B。rear 沿用 front 时差，依据是两半幅共享原片帧时间戳，未测量 rear 独立延迟。没有海报/dual 的普通 front 任务不读取这些参数。

工厂 MEI→KB4 使用现有转换误差与单调性门槛；坐标转换遵循 specialist 的 YPR、平移符号和 index0 旋转约定。兜底标记 `umi_rear_factory_fallback` / `NOT_EVALUATED`，冻结工厂原值、front 哈希、转换误差及时间假设，参与缓存身份但不写登记表。正式绑定损坏或来源错误不触发兜底。front B 仍必须有效；rear B 可以暂缺，精度需实拍评估。`status --require-rear` 仍检查正式登记资产，不凭空声明工厂兜底可用。详细操作见[标定指南](../标定.md#双镜头标定与海报接入)。

## 1. 一句话概括

**采集前建好共享地图；抽取任务轨迹时，将工作镜头的地图定位、IMU 和环境镜头看到的 ArUco 海报一起用于融合。** 这是 2026-11-11 明确的实际使用场景：采集前会建图，建图录像和任务录像中环境镜头都经常能看到标签，希望两段录像中的标签信息都得到利用。标签载体在建图后或任务之间可能移动，因此不能把同一 ID 当成跨录像位置不变的固定锚点。

实际标签载体是一张放在环境镜头视野内的大海报，并有排版文件可确定标签尺寸和相对位置。已提供规格：**ArUco `DICT_4X4_100`，纸张 1000 × 1500 mm，标签边长 100 mm，7 × 11 共 77 个不同 ID（12–88），中心间距 130 mm、标签间空隙 30 mm。** 主方案按已知几何的刚性多标签板处理：板内布局固定，每段录像只估计整张海报的位姿，不为每个 ID 分别设置自由位姿。已核对用户提供的 [PDF](../../hardware/UMI_ArU..an.pdf)：ID 从左到右、从上到下依次为 12–88，朝向一致、黑边 1 格；页边距左右各 60 mm、上下各 50 mm。已生成 [布局资产](../../hardware/calibration_targets/environment_poster.json)，记录各 ID 的米制角点及 PDF 哈希。打印后实测尺寸仍未确认，资产标为 `pdf_design`。

不改 ORB-SLAM3 内部，在现有场景融合中借鉴 specialist 的标签角点重投影约束，让轨迹与本任务的海报位姿一起求解。地图提供共享坐标参照和连续定位，IMU 提供运动约束，海报上已知的角点几何补充米制约束。标签的作用不限于定位丢失时：有地图定位的帧也一起参与求解；实际改善程度取决于观测几何和各来源的误差模型。标签不可见的片段仍使用地图定位与 IMU。

**主线是任务中的标签融合。** 标签检测、初值求解和校验是接入融合的准备工作；建图录像中的尺度修正是另一项增强（保留决策 7.7），无共享地图的任务仍是可选扩展。建图时没有拍到标签，不妨碍任务录像中的有效标签参与融合。若还要让任务标签纠正地图整体尺度，需要阶段 4 放开尺度变量，不能只靠固定地图下的阶段 3。

两段录像的标签分别使用：**建图时估计地图尺度和该建图录像中的海报位姿，将尺度及依据随地图发布；任务时重新估计该任务中的海报位姿，与轨迹联合求解。** 复用的是 ID 到海报局部坐标的几何布局，不复用海报在场景中的位置。布局版本和哈希随结果记录；建图阶段的海报位姿不作为后续任务的位置先验。整张海报可在录像之间移动；若单个标签被重新粘贴，板内布局改变，必须更新布局资产。

实施顺序是**先整理现有融合代码并留好接口，再分阶段加功能**。阶段 0、1 不改变任何现有轨迹。阶段 2 默认只记录标签诊断；完成建图尺度修正的验证并显式开启后，建图录像里得到有效标签尺度估计的场地，地图尺度由 IMU 和标签两个估计按不确定度加权合并。未开启或没有有效标签估计时保持现状。建图尺度修正的验证可单独推进，不作为阶段 3 接入任务标签约束的前置条件。

标签相关的做法**以 specialist 为参考实现**（`~/specialist`，同类硬件上的标签锚定方案）：标签检测、角点重投影因子、噪声模型、多标签处理和诊断量都有现成的对应代码，各阶段应先读对应部分再动手，对照表见 4.4。


### 当前代码的使用与边界（2026-11-11）

在 `scenes/<场景>/scene.yaml` 中声明布局；相对路径以该文件目录为基准：

```yaml
schema_version: 3
tags:
  layout: ../../hardware/calibration_targets/environment_poster.json
parameters:
  tag_fusion_enabled: false
```

只配置布局时，任务流程自动检测并在有 rear 标定时估计海报位姿，输出诊断但保留原轨迹。改为 `true` 后，使用本设备正式 rear 标定或上述工厂兜底，将海报角点加入固定地图 + IMU 因子图。每手每段录像重新估计一个 `T_scene_board`，不读取建图时的海报位置。未配置布局不执行海报路径。

- 先通过原有地图 + IMU 验收，再初始化海报。使用 KB4 反投影与平面 PnP 候选，在多帧固定基线轨迹上优化一个板位姿；检查正深度、基础退化、多解和像素 RMS。
- 工作镜头节点与有效环境观测的真实 IMU 时刻取并集（仅合并不超过 1 ns 的数值舍入差）；在新增节点间重新积分 IMU，地图先验仅按原工作节点重编号。输出仍采样到工作镜头时间轴，不把环境角点贴到最近帧。
- 一个 ID 的四角点组成八维重投影因子，带径向噪声和 Huber 核；板内 77 个 ID 共享一个板位姿变量。默认至少 3 个时刻、最短边 8 px、初始化/最终角点 RMS 上限 5 px；这些只是未实测调参的初值。
- 无有效观测或不足 3 个时刻时原样保留基线。诊断模式的几何拒绝只记录原因；启用融合后的几何矛盾明确失败，不触发单手定位失败的独立建图回退。尚不能保证识别所有海报移动或打印误差。
- `fusion.environment_poster` 记录布局身份、时刻范围、帧数、前后重投影 RMS、海报位姿和状态；原片采样可见性在每手 `environment_tags.json`。布局冻结到结果 `devices/environment_poster.json` 并参与资产哈希。`tracked` 仍表示地图定位支持，不冒充标签覆盖率。

已验证合成几何、解析导数、时间偏移、任意外参、部分 ID 可见、录像间移动、录像内冲突及无观测退回。**尚未验证真实海报任务精度与运行耗时，实际打印尺寸也未测量。** 任务融合仍不改变已发布地图尺度；建图可通过下述独立开关修正尺度。不以标签弥补未通过原地图验收的任务，不实现逐帧可信等级或自适应来源权重；`actual_error` 仍为 `not_measured`。

### 建图海报尺度入口（2026-11-11）

在同一份 `scene.yaml` 的 `parameters` 中设置：

```yaml
tag_mapping_enabled: true        # 建图录像中的海报尺度诊断
tag_mapping_scale_enabled: false # true 才应用加权尺度并重新做惯性验收
```

两项默认均为 `false`，与任务的 `tag_fusion_enabled` 独立。需要 `tags.layout`；启用修正要求建图设备可解析正式 rear 标定或工厂兜底。未绑定正式 rear 时先尝试兜底，无法读取/转换工厂参数则预检失败。每次建图冻结布局和原始角点观测到版本目录，身份含布局内容与相关门槛；仅改变任务融合开关不会要求重建地图。

当前尺度估计固定原视觉地图的形状，联合优化一个对数尺度和一个本录像海报位姿；环境观测只在连续地图跟踪段内按实际 IMU 时刻插值，不跨丢帧。地图镜头与环境镜头间的米制杆臂不随视觉地图缩放。默认至少 6 个时刻、移动范围 0.15 m、板面两个轴各覆盖 0.08 m，统计相对标准差不超过 0.15；这些为未实测调参的暂定门槛。

相容时按对数尺度和方差加权，IMU/海报相对标准差地板暂取 0.03/0.02；同时要求归一化差不超过 3、尺度比偏离 1 不超过 0.20。修正开启后，通过精确消元固定合并尺度，重估重力和零偏，并复核全部可检查运动段的惯性残差。原尺度估计必须先通过现有验收；海报不用于救回原本无法定标的地图。

观测不足/几何退化/统计不确定度过大时保持原尺度；有效来源冲突在诊断模式仅记录，修正模式拒绝该候选。没有通过验收的候选时不发布新地图，也不替换已有指针。各地图 `placement.evidence.environment_poster` 保存状态、独立尺度、统计不确定度、地板项、权重、合并结果和诊断板位姿；后续任务只复用地图尺度与板内布局，不读取此位姿先验。默认布局仍是 PDF 设计尺寸，尚需成品尺寸与真实录像验证。

### 独立轨迹与单手回退入口（2026-11-11）

独立逐段流程已接入同一张海报的原始角点，支持 `handheld` 与 `dual`。使用本设备已登记的环境镜头参数来源（`umi-calib install` 更新 `rear/<参数来源>/`），明确指定布局：

```bash
.deps/env/bin/python -m software.trajectory run /path/to/task.insv \
  --tag-layout hardware/calibration_targets/environment_poster.json \
  --rear-calibration rear_<实际版本> --config /path/to/trajectory_override.yaml
```

覆盖配置内容：

```yaml
environment_tags:
  tag_fusion_enabled: true
```

仅指定资产、不开融合开关时做诊断；启用却缺资产会在预检拒绝。阈值位于 `trajectory.yaml` 的 `environment_tags`，默认与场景相同。rear 的序列号、验收、内参来源必须匹配工作镜头。正式 rear 已与海报解耦：独立 `--mode dual --rear-calibration measured` 无需海报；未指定 rear 时尝试工厂兜底，不再使用样例。rear 测量独立冻结于 `devices/rear/`，海报布局和观测仍保存在 `environment_poster/`；两者均进入结果复用检查。

独立流程先完成原有惯性初始化和融合，再将海报角点加入原生图；轨迹、分段地图尺度/旋转/平移以及一个本录像海报位姿一起优化。保留原地图规范先验和质量门槛；没有实现只靠海报绕过 IMU 初始化或外部绝对坐标。额外节点按 `rear_offset - front_offset` 换到独立引擎的工作镜头视频时钟，重积分 IMU，恢复输出时不跨过海报节点。dual 的 rear 地图定位也会换时钟，禁止跨丢帧或地图切换插值。

单手共享定位质量失败时，原有独立回退会继承 `scene.yaml` 的海报布局、`tag_fusion_enabled` 和对应阈值，复用冻结的 rear 标定。回退结果仍是本录像的局部坐标；双手不启用这种单手回退。海报本身的几何冲突仍不会触发绕开标签的静默回退。

空观测/观测不足或仅诊断时保留基线位姿；对独立 dual，这个基线已经使用显式 rear 标定和正确的镜头时差，不能与旧样例 dual 冒充同一输入比较。`fusion.environment_poster` 及报告显示是否真正融合，`tracked` 仍表示地图定位来源。

### 标定流程与资产管理配套（2026-11-11）

海报功能的交付不仅包括融合因子，还包括 **每设备 front/rear 测量 → 各自 A/B/C/D 验收 → 显式登记版本 → 套件或独立命令绑定 → 海报成品几何核对 → 实拍联合验证 → 运行冻结与追溯**。操作步骤见[标定指南](../标定.md#双镜头标定与海报接入)，资产职责与变更规则见[设备与坐标](../设备与坐标.md#环境海报资产的职责与变更)。

| 项目 | 当前能力 | 后续缺口 |
|---|---|---|
| 环境镜头求解与验收 | `run <rear目录>` 共用标定生命周期，支持 measured/factory；仍要求 A/B/C/D | 补充本设备真实环境镜头验收数据 |
| 登记与绑定 | 统一 `install` 生成并更新 front/rear 当前资产；`devices/status` 只读列出 front/rear 当前版本、来源和哈希状态；`--kit` 检查固定绑定，`--require-rear` 对缺 rear 返回失败，支持 JSON | 状态检查不覆盖原片匹配、夹爪安装资产或真实组合误差；不得把资产完整等同于实际精度已验证 |
| 双镜头组合 | 每个镜头分别给出相对于同一 IMU 的外参和时差；流程应用两者时差 | 新增真实组合使用的诊断报告；独立通过不等于组合误差已量化 |
| 海报资产 | PDF 来源、显式 ID 角点、几何/资产哈希；支持 `pdf_design` / `physically_measured` 状态 | 成品测量记录及其引用格式尚未实现；未实测不改变状态 |
| 校验边界 | C 显式覆盖为单镜头、关闭任务海报；rear C 同时关闭场景海报开关；已增加配置隔离回归 | 仍需真实组合验证；不得让同一观测同时修正和验收 |
| 结果追溯 | 地图、共享任务、独立运行冻结实际使用的海报和标定；回退沿用快照 | 统一展示各入口实际使用/仅诊断/缺失/拒绝状态 |

保持 registry 保存机身测量、kit 选择参数来源、scene 选择海报的现有分工，不新增隐式 rear 默认指针，不把海报位置注册成永久锚点。front/rear 的当前标定目录独立保存；front/rear 配对或组合验收格式若要新增，需另行设计兼容性与身份规则，不能用目录名称相同代替兼容检查。

A/B/C 相机标定目前仍使用 tag36h11、2 格黑边的 AprilGrid；海报是 DICT_4X4_100、1 格黑边。将海报直接用于相机标定是另一项检测器/求解器适配，不在已完成能力中。`--tag-size-mm` 不填海报的 100 mm。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 工作镜头 | 朝向指尖和工作区的镜头。代码和配置键里是 `front`，4K60 原片的右半幅 |
| 环境镜头 | 背向工作区的镜头。代码和配置键里是 `rear`，原片的左半幅 |
| 标签 | 海报上的 ArUco `DICT_4X4_100` 标记，由环境镜头检测 ID 和四个角点 |
| 海报 / 标签板 | 尺寸和标签相对位置已知的平面刚性目标，按一个整体求解位姿 |
| 布局 | 各 ID 的四个角点在海报局部坐标系中的米制坐标；可跨录像复用的物理资产 |
| 海报位姿 | `T_scene_board`，海报在场景坐标系里的位置和朝向；每段建图或任务录像各自求解，不跨录像冻结（决策 7.3） |
| 标签位姿 | 由海报位姿与固定的板内标签变换相乘得到，不是独立的优化变量 |
| 来源 | 向融合提供约束的一类信息：IMU、地图定位、标签角点、静止检测 |
| 地图摆放 | 视觉地图到米制场景坐标系的相似变换：尺度、旋转、平移 |
| 逐段引擎 | `software/trajectory`，每段录像独立建图、定位、融合，用于标定 C 段验证和开发 |
| 场景流程 | `software/scene`，批次共享地图，任务在固定地图中定位后融合 |

## 3. 目标与非目标

### 3.1 目标

1. **已有地图上的多来源融合**：近期流程保留采集前慢扫得到的共享地图，在任务轨迹抽取时加入环境标签约束。参与几何求解的环境镜头需要有效的内参、相机–IMU 外参和时间偏移；没有环境镜头标定或有效标签观测时保留现有路径。无地图模式单独放在阶段 5，不是本次主线。
2. **校验**：单个来源是否可用；来源之间是否矛盾；融合结果是否自洽。
3. **自适应融合**：标签观测多且质量好时，轨迹更多受标签约束；少或没有时，退回现有行为。
4. **可信等级**：每个任务的结果标明用了哪些来源、各自覆盖多少、是否经过标签核对。

### 3.2 非目标

- 不修改 ORB-SLAM3 内部的建图和优化。
- 不去掉共享地图，也不把"每个任务各自建图"作为近期目标（见阶段 5，可选）。
- 不把"跨批次、跨地图版本的世界原点一致"作为目标。训练使用相对动作，世界原点不影响训练数据（见 4.3）。场景原点沿用地图原点；标签位姿每个任务各自求解（决策 7.3），不用来定原点，只有没有地图的任务（阶段 5）才由标签定原点。
- 相机到指尖的几何（目前为 CAD 名义值）和双手时间同步（目前人工填写）是独立的问题，标签帮不上，不在本计划内。

## 4. 背景

### 4.1 现有场景流程的数据流

```text
建图（每批次一次）                      software/scene/spatial/mapping.py
  工作镜头视频 → ORB-SLAM3 单目建图
  → 在地图中重定位 → metric_alignment()：用 IMU 估一个尺度、重力方向、加速度计零偏
  → placement = {scale, T_scene_metric_map（仅重力对齐旋转，平移为零）}
  → 冻结地图和 placement，写入地图 manifest

任务（每只手一次）                      software/scene/pipeline/reconstruction.py: reconstruct_arm_in_scene()
  工作镜头视频 → 在冻结地图中定位 → VisualObservations（地图单位）
  → .placed(placement) → T_scene_camera（米制，场景系）
  → fusion.fuse()：与 IMU 融合 → T_scene_imu
  → 乘相机–IMU 外参、相机–TCP 几何 → TCP 轨迹
```

场景融合 [`fuse()`](../../software/scene/spatial/fusion.py) 当前的图：

| 内容 | 实现 |
|---|---|
| 节点 | 工作镜头每一帧一个：位姿 `X(k)`、速度 `V(k)`、零偏 `B(k)`。节点时刻 = 视频帧时间 + 工作镜头的 `cam_time_offset_ns` |
| IMU | 相邻节点间 `ImuFactor`，另加 `BetweenFactorConstantBias` 作零偏随机游走 |
| 地图定位 | 每个有定位的节点一个 `PriorFactorPose3`，位置 σ = `front_position_sigma_m`（默认 0.015 m），旋转 σ = `visual_rotation_sigma_deg`（默认 1°），Huber 核 |
| 静止 | 检测到静止的节点加零速先验 |
| 求解 | GTSAM Levenberg–Marquardt |
| 验收 | 函数内部直接 `raise`：定位覆盖率低于 `minimum_localization_fraction`、最长无视觉超过 `maximum_visual_gap_s`、融合与定位的位置 RMS 超过 `maximum_placement_rms_m` |
| 输出 | `FusionResult(T_scene_imu, tracked, front_tracked, evidence)`，其中 `evidence['actual_error'] = 'not_measured'` |

左右手各调用一次，彼此之间没有联合约束。

### 4.2 现有代码里妨碍目标的四点

| 现状 | 位置 | 后果 |
|---|---|---|
| 有两套独立的融合图 | 场景：[scene/spatial/fusion.py](../../software/scene/spatial/fusion.py)；逐段：[trajectory/algorithms/fusion_graph.py](../../software/trajectory/algorithms/fusion_graph.py) | 新约束要加两遍，或只有一边有 |
| 场景融合把地图当真值 | `fuse()` 里固定的位姿先验 | 地图尺度偏了，几千条一致但都偏的先验会压过少量标签观测 |
| "已标定的镜头"等于"做地图定位的镜头" | `reconstruct_arm_in_scene()` 遍历 `camera.measurements`；`Scene.role()` 为每个镜头找地图 | 环境镜头一有标定就必须有自己的地图，无法只用来看标签 |
| `fuse()` 是一个整体函数 | 同上 | 检查输入、建图、求解、验收混在一起，难以插入新来源和新检查 |

两套融合图的来历（见 [PROVENANCE.md](PROVENANCE.md) 和 [scene/NOTICE.md](../../software/scene/NOTICE.md)）：逐段引擎的融合随仓库首次提交从实验室仓库迁入，原为单个脚本 `kiwi_fuse3s.py`；场景融合是做共享场景流程时参考 KIWI 公开实现 0.1.0 另写的。两者假设不同：场景融合信任冻结的地图，图很简单；逐段引擎不信任地图，为每个跟踪段带着尺度、旋转、平移变量。共享地图的尺度估计已经改为调用逐段引擎一侧的公共求解器，说明两者本来就在走向共用。

两套图之间还有几处不一致，合并时需要处理：

- IMU：场景融合用 `ImuFactor` 加单独的零偏随机游走因子；逐段引擎用 `CombinedImuFactor`。
- 视觉噪声参数：场景在 [scene_parameters.yaml](../../config/scene_parameters.yaml)，逐段在 [trajectory.yaml](../../config/trajectory.yaml) 的 `fusion`。
- 节点：场景每帧一个；逐段可按 `node_stride` 抽稀，之后恢复全帧率。

### 4.3 标签能改善什么

| 误差来源 | 标签能否改善 | 说明 |
|---|---|---|
| 地图尺度（靠 IMU 估；发布门槛为相对不确定度 ≤ 20%） | **能，收益最大** | 相机相对标签的位移是米制的，与地图中的位移一比即得尺度，不经过 IMU |
| 定位丢失的片段（靠 IMU 衔接） | 能 | 标签位姿由有定位的帧确定后，丢失期间看得到标签的帧就多一个约束 |
| 双手相对位姿 | 能核对 | 两只手各自解出的同一海报位姿应当一致，可看到不同 ID 子集；差值还包含布局、标定和观测误差。两只手联合求解不在本计划内 |
| 地图内部的缓慢变形 | 部分 | 需要多个标签分散布置 |
| 跟踪良好帧的逐帧抖动 | 基本不能 | 地图定位用几百个特征点，单个远处标签不如它准 |
| 相机到指尖的几何、双手时间同步 | 不能 | 与环境无关 |

对训练数据而言重要的是：米制尺度、短时间内的轨迹形状、无跳变、双手同一时刻的相对位姿、时间对齐、相机到指尖的几何、夹爪开口。跨任务一致的世界原点在相对动作表示下完全抵消，因此不是目标。尺度误差的特点是不会让轨迹变形或抖动，只会整体等比例缩放，从轨迹图上看不出来，却直接影响每个动作的大小，这是标签最值得解决的问题。

### 4.4 参考实现：specialist

specialist（`~/specialist`）用同类硬件（夹爪上的 Insta360 双鱼眼加机内 IMU），目标相同，结构不同：没有可复用的地图，每段录像把环境特征点、IMU 预积分、标签角点放进一张图联合优化；米制尺度和世界原点来自环境镜头看到的锚点标签，要求至少四分之一的关键帧看到锚点。它相当于"标签为主、地图为辅"的一端，本项目现状是"地图为主、没有标签"的另一端，本计划是从后者向中间走。

本计划借鉴它的四个核心做法：

- 标签约束用**角点重投影**，不用 PnP 位姿当先验。远处标签的距离不准、方向很准，重投影因子自动体现这一点。
- 角点噪声随离图像中心的距离增大，边缘观测降权而不是丢弃。
- 重投影因子带 Huber 核。
- 允许多个标签；其中一个定原点，其余的位姿由优化解出。

各部分对应的 specialist 代码（路径相对 `~/specialist`，对照的版本为提交 `da29719`，2026-11-08）：

| 本计划的部分 | 用于阶段 | specialist 中的对应实现 | 借鉴什么 |
|---|---|---|---|
| 标签检测 | 1 | `src/specialist/vi_ba/tag_detection.py`：`detect_all_tags()`、`detect_tags_following()` | 逐帧检测；多数帧只在上一帧标签位置附近开窗检测、定期全图重检，用于提速 |

借鉴时要注意的差别：

- **码族不同。** specialist 的环境锚点用 AprilTag；实际海报用 ArUco `DICT_4X4_100`。借鉴的是角点重投影融合方法，不要求更换海报。检测改用 OpenCV 对应字典；码族、黑边和角点顺序进入检测身份与自检。
- **同一张海报上的标签共享一个位姿变量。** specialist 的环境锚点各自有自由位姿；本项目已知海报上的相对布局，改用一个海报位姿和固定角点坐标。沿用其角点重投影、鲁棒噪声和初始化思路，但不直接照搬“每个 ID 一个变量”的图结构。
- **留出验证是本计划额外提出的设计。** 2026-11-11 核对本地 specialist 的 `da29719` 版本：`_add_anchor_factors()` 将已配置且成功初始化世界位姿的环境标签加入联合图，未见专门的 `holdout` 标签机制。本文的留出标签、建图时 IMU 与标签尺度加权合并、可信等级均为本项目提出的扩展，不能视为已由 specialist 验证。是否保留专门的留出标签、留出范围是否覆盖建图尺度估计，仍待讨论；下文相关条目是提案，尚未定案。
- **相机模型不同。** specialist 直接用出厂 MEI；本项目下游统一用 KB4，内参来源可选实测或工厂 MEI 拟合，B 均实测。来源开关没有改变因子的模型要求，投影函数及其导数仍要用 KB4 重写。
- **语言不同。** specialist 的因子是 C++ 扩展；本项目的自定义因子是 Python（`fusion_factors.py`）。先按本项目的方式写，速度不够再考虑。
- **标签不需要持续可见。** 本项目有冻结的地图，看不到标签时仍有地图定位，所以标签是加分项而不是必需品；specialist 里"四分之一关键帧"的硬性要求不适用，只在阶段 5 才有类似约束。
- **镜头命名相反。** specialist 的 `rear` 是工作镜头，`front` 是环境镜头。读它的代码时，锚点相关逻辑都在 `front` 上。
- **来源记录。** specialist 以 MIT 许可发布。如果改编其代码而不只是参考做法，按 [scene/NOTICE.md](../../software/scene/NOTICE.md) 对 KIWI 的处理方式记录来源、提交号和许可。本项目已有先例：`software/camera/x3/factory.py` 注明其 MEI 公式与 specialist 一致。

## 5. 方案

### 5.1 结构：五层

每层只依赖上一层的输出。

| 层 | 职责 | 新增或改动 |
|---|---|---|
| 观测 | 每个来源产出统一格式的观测，带时间戳和有效性 | 新增标签观测 |
| 场景资产 | 随地图冻结的东西 | 地图尺度在有有效标签估计时与 IMU 尺度加权合并，manifest 记录依据；标签位姿不在此冻结 |
| 校验 | 三层检查，输出结构化度量和结论 | 新模块 |
| 融合 | 一张图，约束由各来源分别添加 | `fuse()` 拆分；新增标签因子；地图摆放变为变量 |
| 结果 | 逐帧约束来源、可信等级、证据 | `frames.csv` 加列，`episode.json` 加字段，报告加段落 |

### 5.2 接口草案

以下签名是讨论用的草稿，名称可改。原则：普通函数加少量数据类，不引入继承或插件注册。

**镜头角色**（解除"有标定即要建图"的耦合）：

    measurements: dict[str, dict]   # 有实测标定的镜头；不再隐含"要做地图定位"

**度量与判定分开**：

```python
# software/scene/spatial/checks.py（新）
def evaluate(measurements: dict, parameters: SceneParameters) -> Evaluation:
    """把现有 fuse() 内部的三处 raise 和后续新增的检查集中到这里。

```

`fuse()` 不再自行抛出验收类异常；调用方先拿到度量，再由 `evaluate()` 判定。输入非法（时间不递增、IMU 未覆盖）仍由 `validate_inputs()` 直接报错。

**逐帧约束记录**：`FusionResult.tracked` / `front_tracked` 两个布尔数组改为一张表（来源名 → 布尔数组），原两个字段作为兼容属性保留。[`frames.csv`](../../software/scene/pipeline/results.py) 现有的 `constraint` 和 `front_lens_tracked` 两列保持原含义，新增列放在后面。

### 5.3 标签因子

对节点 `k`、海报上的标签 `i`、角点 `j`（`q_ij` 为排版布局给出的海报局部米制坐标，平面布局的 z 为 0）：

```text
p_cam    = T_cam_imu(环境镜头) · X(k)⁻¹ · T_scene_board · q_ij
残差     = π_KB4(p_cam) − 观测像素(k, i, j)          （2 维）
```

- `X(k)` 是节点位姿 `T_scene_imu`。`T_cam_imu` 取环境镜头标定的 `imu_from_camera()` 的逆。
- `T_scene_board` 是**本任务内的变量**，同一张海报只有一个，所有帧、所有可见 ID 共享；不带建图录像中的位置先验（决策 7.3 选 B）。因子连接 `X(k)` 和 `T_scene_board` 两个键。初值的来历见 5.5。
- 已知的标签大小、间距和方向共同定义一个刚性路标；它约束所有观测帧彼此一致并带入米制尺度。场景坐标系仍由地图定位的先验确定；没有地图时（阶段 5）由海报上的参考点和水平朝向固定坐标规范，竖直方向取 IMU 重力。
- 不要求整张海报或同一个 ID 始终可见：不同帧可以看到不同子集，通过已知布局连接到同一个海报位姿。单帧观测不足或平面两解不能可靠区分时，不强行输出 PnP 位姿；可在整段海报位姿已有可靠初值时使用有效角点因子。
- 噪声：基础像素 σ，按角点离主点的距离放大；Huber 核。初值可参考 specialist（锚点角点基础 σ 约 1 px），最终值要用本项目的检测残差统计来定。
- 筛选：点在相机后方、角点超出标定裁切范围、标签边长小于阈值的观测不建因子。
- 雅可比：对 `X(k)` 和 `T_scene_board` 的解析导数，需要 `π_KB4` 对相机系点的导数。写法和自检方式照 `fusion_factors.py`。
- 像素坐标系：环境镜头标定基于 1920 半幅的中心 1440 裁切。检测在原片 1920×1920 左半幅上做，角点减去裁切偏移（每边 240 px）后进入因子。**不使用 720 的 SLAM 视频做检测。**
- 时间：环境镜头有自己的 `cam_time_offset_ns`，与工作镜头不同。任务融合已采用两镜头 IMU 时刻并集建节点，仅合并不超过 1 ns 的舍入等价时刻；建图尺度估计在连续地图段内插值到环境观测时刻，禁止跨丢帧。

### 5.4 地图摆放作为变量（阶段 4）

现状是 `T_scene_camera(k) = placement ∘ 地图定位(k)`，placement 为常数。改为：

- 每张参与的地图一组变量：对数尺度 `λ`、旋转 `R`、平移 `t`。
- 地图定位因子换成逐段引擎已有的 `make_lens_factor_map()`：位置残差在地图单位下计算。
- 先验：以建图时冻结的 placement 为中心。尺度先验的宽度取自建图时地图尺度的不确定度：与标签加权合并时（5.5）取合并后的 `σ`，否则取 IMU 一侧的不确定度（含地板项）。旋转和平移先验较紧。
- 效果：标签观测充足时，尺度和摆放由标签决定；没有标签时由先验决定，结果应与现状在数值容差内一致。

这一步等价于把场景融合变成"摆放先验很紧的逐段融合"，因此是合并两套图的自然时机（见 7.1）。

### 5.5 海报位姿：每段录像各自求解，板内布局复用

已定（决策 7.3 选 B）：**海报在场景中的位姿不在建图时冻结，每个任务用自己的观测解出。** 保存和复用的是海报内部的已知布局，不是海报在房间中的位置。

2026-11-11 补充确认：建图和任务期间都经常看到同一张多标签海报，有排版文件可确定尺寸和相对位置，但建图后或任务之间可能移动标签载体，因此维持每段求解。海报整体移动不使已估出的地图尺度失效。每段录像中海报应静止并保持平整，所有标签相对海报的几何关系不变；录像内移动或变形属于异常，按 5.6 的冲突检查处理。板内标签若单独移动，不能继续沿用旧布局。

这样定的理由和代价：

| | 每个任务各自解（采用） | 建图时冻结（未采用） |
|---|---|---|
| 对海报位置的要求 | 每段录像内保持静止、平整；录像之间可以整体移动，板内布局不变 | 从建图到使用该地图的最后一个任务都不能整体移动 |
| 建图录像 | 不需要为任务保存海报的位置；若用于修正尺度，需有有效海报观测和运动 | 需要足够观测确定海报在地图中的位姿，不要求每个 ID 都单独充分可见 |
| 提供米制尺度 | 能 | 能 |
| 任务内的一致性约束、衔接定位丢失的片段 | 能 | 能 |
| 每个任务需要的标签观测 | 需足够确定共享海报位姿，可由不同 ID 子集共同提供 | 有已知海报场景位置作为先验时通常较少 |
| 发现"整段任务相对地图有固定偏移" | 不能 | 能 |
| 发现"任务中途定位跳变、偏差随时间变化" | 能 | 能 |

倒数第二行是主要的代价。它在本计划的目标下可以接受：整段轨迹的固定刚性偏移在相对动作表示下不影响训练数据（4.3），而会影响训练数据的中途跳变和尺度错误仍然能发现。

**任务内的求解步骤**（每只手各做一次）：

1. 环境镜头逐帧检测标签（5.2 的 `TagObservations`）。
2. 先按现状做一次不含标签的融合，得到初始轨迹。
3. 将一帧内通过质量筛选的多个 ID 的角点与布局对应，求 `T_cam_board` 初值；结合初始轨迹和外参得到 `T_scene_board` 候选，跨帧取一致解。不得把所有角点当成互不相关的独立位姿测量。
4. 单次角点观测按质量筛选；整段海报的使用条件按所有 ID 的联合观测评估，不要求每个 ID 都单独达到视角和帧数门槛。候选不一致时保留冲突证据，不能直接认定海报移动并静默弃用。
5. 阶段 2：轨迹固定，精化本段海报位姿并输出残差和尺度比。阶段 3 起：一个海报位姿变量与轨迹一起求解，各 ID 的有效角点连接这个共享变量（5.3）。

写入任务结果（`episode.json`）的字段草案（数值仅示意，不是现有海报实测）：

```json
"tags": {
  "board_id": "environment_poster",
  "layout_hash": "...", "T_scene_board": [[...]],
  "board_sighting_frames": 184, "view_extent_m": 0.41,
  "used": {"12": {"sightings": 120, "median_side_px": 62.0, "role": "constraint"},
           "13": {"sightings": 95, "median_side_px": 58.0, "role": "constraint"}},
  "unused": {"14": {"reason": "side_px", "sightings": 12}}
}
```

若后续启用 `holdout` 实验，留出 ID 的观测不用于任务初值、海报位姿精化或任务融合；用最终轨迹、共享海报位姿和已知布局预测留出角点。它衡量未参与求解角点的重投影一致性，仍共享海报布局、相机标定及可能的建图尺度误差，不能称为独立的真实精度；是否也从建图尺度估计中排除仍待讨论。不再为留出 ID 单独拟合一个自由位姿。没有外部真值时保留 `actual_error = not_measured`，留出残差单独记录。

**建图时对标签的使用：修正地图尺度**（决策 7.7，已定）。标签位姿不冻结，但地图尺度是所有任务共用的，在建图时用标签把它定准，之后每个任务都受益，包括任务中完全看不到标签的。这只用到"相机相对标签的位移"和边长，不需要保存标签位姿，与每任务求解不冲突。

这项增强不替代任务中的标签融合，也不是其前置：已有地图仍可用于阶段 3，任务标签来自各自的任务录像；建图尺度修正未启用时，地图沿用原有 placement。

标签**不能**提高地图的形状精度：特征点之间的相对位置由 ORB-SLAM3 用工作镜头的画面算出，标签在环境镜头里，且本计划不改 ORB-SLAM3 内部。能提高的只是尺度。

建图时的步骤：

1. 照现状用 IMU 做米制对齐，得到尺度 `s_imu`、重力方向和加速度计零偏。
2. 在建图录像上检测海报标签。保持地图轨迹的形状不变，以“地图尺度”和“本段海报位姿”为未知量，使用布局中固定的角点坐标做小规模重投影最小二乘，得到 `s_tag` 及其不确定度。
3. 判断标签估计是否有效：有效帧数、看到海报期间相机的移动范围、有效角点的空间分布和标签像素大小要过最低门槛，`s_tag` 的不确定度不超过上限。可按海报区域或时间段作一致性诊断，但同一海报上的多个 ID 共享打印、布局和标定误差，不能把它们当成多个独立尺度来源重复加权。
4. 有效且 `s_tag` 与 `s_imu` 相容：地图尺度取两者**按不确定度加权的平均**（见下）。然后以该尺度为固定值重做惯性对齐，重新得到重力方向和零偏，并复核惯性位置方程的残差，残差仍需满足 `maximum_alignment_rms_m`。现有的 `fusion_alignment.fixed_map_residuals()` 已能在给定尺度、重力和零偏下计算各段残差，可直接用于复核；"固定尺度、只解重力和零偏"的对齐需要在现有求解器上加一个固定尺度的入口，改动应当不大，实施时确认。
5. 有效但两者不相容，或第 4 步的残差复核不过：两个来源矛盾，按决策 7.4 处理，不做平均。两个互相矛盾的估计取平均没有意义。
6. 无效：沿用 `s_imu`，与现状完全相同；地图 manifest 中标签一项记为 UNKNOWN。

**合并方式：按不确定度加权平均**（已定，2026-11-10）。尺度是乘性的量，在对数上做：

```text
x_imu = ln s_imu，σ_imu = IMU 尺度的相对标准差
x_tag = ln s_tag，σ_tag = 标签尺度的相对标准差
w_imu = 1/σ_imu²，w_tag = 1/σ_tag²

ln s   = (w_imu·x_imu + w_tag·x_tag) / (w_imu + w_tag)
σ      = 1 / sqrt(w_imu + w_tag)            合并后的相对标准差

相容的判据：|x_imu − x_tag| ≤ k·sqrt(σ_imu² + σ_tag²)，且不超过绝对的失败界限 tag_scale_fail
```

这样标签观测越好（`σ_tag` 越小）占的比重越大，观测差时自动少占，不需要在"用标签"和"用 IMU"之间硬切换，这与任务融合里的自适应是同一个原则。合并后的 `σ` 写入地图 manifest，并作为阶段 4 任务融合中地图尺度先验的宽度（5.4）。

**加权平均的前提是两个不确定度都如实。** 这是这种做法最需要小心的地方：

- `σ_imu` 现在取自对齐给出的 `relative_scale_std`。它是线性最小二乘的形式不确定度（残差方差乘以法方程的逆，见 `fusion_alignment.py`），假设各方程的误差相互独立、没有共同的偏差。相机–IMU 外参或时间差的偏差会让各段尺度一致地偏向同一边，这种系统误差不会体现在离散度里，所以它很可能偏小，导致 IMU 的比重被高估。
- `σ_tag` 来自最小二乘的协方差，同样不包含边长测量误差和环境镜头标定误差。
- 因此两边都要加一个下限（地板）项，再参与加权：`σ² = σ_统计² + σ_地板²`。标签一侧的地板可以由"边长测量误差除以边长"加上标定误差的估计给出；IMU 一侧的地板没有先验依据，要由实测确定。
- 检验办法：阶段 2 先只记录不生效，在多个场地上统计归一化差值 `(x_imu − x_tag) / sqrt(σ_imu² + σ_tag²)`。两个不确定度都如实时，它应当大致服从标准正态分布（多数在 ±2 以内）。如果普遍偏大，说明至少一方的不确定度被低估，据此调整地板项。分布合理之后再让修正生效。

地图 manifest 记录 `s_imu`、`s_tag`、各自的统计不确定度和地板项、权重、合并结果及其不确定度，或未合并的原因。

建图录像不强制拍到标签，没拍到就退回第 6 步。但拍到了有实际好处，所以采集上建议拍（5.9）。相比"建图时冻结标签位姿"的方案，这里不要求每个标签都近距离多角度拍清楚：有一个标签给出有效的尺度估计就能参与修正。

**使用条件。** 单个标签的检测质量与整张海报的几何可观测性分别评估。允许一个 ID 只在少量帧出现，由其他 ID 帮助确定共享海报位姿。统计有效帧时按时间戳去重：同一帧看到 20 个 ID 是 1 帧，不是 20 个独立时刻；更多角点不能消除共同的打印、标定和卷帘误差。需同时观察三个维度：

| 维度 | 度量 | 作用 |
|---|---|---|
| 数量 | 海报有效帧数、每帧有效 ID 数与角点数 | 区分时间覆盖和单帧观测量 |
| 几何覆盖 | 有效角点在板面和图像中的分布、看到海报期间相机的移动范围及视角变化 | 判断局部可见、远距离及近平面正视时的薄弱方向 |
| 一致性 | 共享海报位姿下各 ID、各时段的重投影残差，以及海报位姿初值的一致性 | 检查布局错误、误检、变形及来源冲突；不单凭残差认定哪方有错 |

单帧质量筛选（标签像素边长、标定区域、ID 唯一性）在计数之前进行，未使用的观测记录原因。没有可用海报约束时，原有地图流程通过验收的任务仍可成功。进入融合的门槛与核对尺度的门槛分开：整板几何已充分约束位姿时，不要求每个 ID 单独有大范围运动；地图尺度比的估计仍需足够的相机相对位移。具体门槛在阶段 1、2 实测后确定。

**海报的一致性要求。** 海报在每段建图或任务录像期间保持静止、平整，板内几何不变；整板可在录像之间移动。局部 ID 残差异常要检查误检、粘贴和布局，全部 ID 同时出现轨迹相关残差则可能是整板移动，也可能是地图或标定问题。不能仅因有 77 个 ID 就认定有 77 个独立静态参照。

**顺带得到的两项诊断**（不作为要求，标签没被动过时才有意义）：

- 同一个任务里，左右手各自解出的海报位姿之差。两只手可看到不同 ID 子集，只要都能可靠估计同一海报的位姿即可比较；这是双手一致性诊断，包含布局、标定及观测误差，不是双手真实误差的直接测量。
- 同一批次不同任务解出的海报位姿之差，只在已知海报未移动时反映重复性；允许整板移动的日常采集中不据此判定轨迹错误。

标签配置中进入建图身份的是影响“建图时尺度修正”的部分：字典、黑边格数、完整海报布局及实测尺寸、检测参数和修正门槛，完整清单见 5.8。布局须按内容记录身份，不能只记录文件路径。其余只影响任务。参照 [`mapping.definition()`](../../software/scene/spatial/mapping.py) 现有的划分方式。

### 5.6 校验

| 层 | 检查 | 度量 | 不通过时 |
|---|---|---|---|
| 融合前，单来源 | 标签观测质量 | 每个标签的可见帧比例、边长像素中位数、最长连续不可见时长、标定区域外的比例 | 该来源不使用，记录原因 |
| | 地图定位 | 覆盖率、最长无视觉（现有） | 现有行为 |
| 融合前，来源之间 | 尺度一致 | 相机相对标签的位移与地图中位移的尺度比（`umeyama`） | 见决策 7.4 |
| | 海报是否符合静态刚性模型 | 按 ID、板面区域和时间段统计共享海报模型的重投影残差 | 记录异常及来源冲突，不自动归因于海报移动 |
| | 任务内定位是否自洽 | 以标签为参照，地图定位推出的相机位置是否随时间或位置出现跳变、漂移 | 见 5.11 |
| | 双手一致（双手任务） | 左右手各自解出的同一海报位姿之差 | 超限告警；结合观测不确定度解释 |
| 融合后 | 各来源残差 | 地图先验残差、标签重投影像素残差的 RMS 和分位数 | 超限为 FAIL 或 WARN |
| | 留出验证（可选实验） | 用共享海报位姿预测 `holdout` ID 的角点，统计残差（见 5.5） | 单独记录留出重投影残差；没有外部真值时 `actual_error` 仍为 `not_measured` |

因为标签位姿是每个任务自己解的（5.5），任务与地图之间的**固定**刚性偏移无法由标签发现；能发现的是尺度错误和任务内随时间变化的不一致。前者不影响相对动作形式的训练数据，后两者会影响，所以检查集中在后两者。

来源矛盾时，IMU 可作裁判：分别按两个来源的位移计算相邻节点间的预积分残差，哪一方与 IMU 更吻合。

**任务录像对标签观测量不设硬性要求。** 标签在任务里是加分项，看不到也照常出结果。但各项用途所需的证据量不同，证据不足时该项结论为 UNKNOWN，既不算通过也不算失败（与原片检查中曝光信息缺失记为 UNKNOWN 的做法一致）：

| 用途 | 所需的观测量 | 不足时 |
|---|---|---|
| 进入融合作为约束 | 共享海报位姿有可靠初值和足够约束，单次标签观测通过质量筛选 | 不使用不能可靠约束的观测，记录原因 |
| 核对尺度 | 共同有效帧数不少于下限，且期间相机相对标签的移动范围不小于下限 | 尺度检查记为 UNKNOWN |
| 留出标签重投影诊断 | 留出观测通过质量筛选，且帧数和几何覆盖足够 | 留出检查记 UNKNOWN，不改变 `actual_error` |
| 判断任务内定位是否自洽 | 标签在任务的前后不同时段都有观测 | 该检查记为 UNKNOWN |
| 双手一致 | 两只手在同一任务里都可靠解出了同一海报位姿，不要求看到相同 ID | 该检查记为 UNKNOWN |

相比冻结海报场景位姿的做法，每个任务需要自行提供足够的海报观测。已知布局允许多个 ID 合并约束，不要求同一 ID 持续出现；需要的观测量取决于板面覆盖、距离和视角，尺度检查还要求运动范围。实际满足比例由阶段 1、2 的统计回答。

这组门槛的结构直接取自标定 C 段的板参考验证（[calibration.yaml](../../config/calibration.yaml)）：`minimum_comparison_frames`（默认 30，不足则不计算误差）、`minimum_board_frames`（默认 100，不足给提醒）、`minimum_board_extent_m`（默认 0.15，移动范围不足则结论为不完整）。标签的对应数值在阶段 1、2 实测后确定。

阈值的初值待阶段 2 的实测分布确定，不预设。

### 5.7 可信等级

写入 `episode.json` 和报告，供验收和训练导出筛选：

| 等级 | 条件 | 含义 |
|---|---|---|
| 失败 | 无足够的视觉或标签约束 | 不输出轨迹 |
| 仅地图 | 没有标签观测 | 与现状相同，真实误差未测 |
| 地图，尺度经标签核对 | 有少量标签观测，尺度比在容差内 | 尺度有独立证据 |
| 地图与标签共同约束 | 标签实际进入融合，覆盖及质量达到门槛 | 输出标签约束覆盖和融合残差；是否有独立验证另行记录 |
| 仅标签（阶段 5） | 没有地图 | 标签消失超过约 1 秒的片段标记为不可靠 |

具体的比例门槛由阶段 1、2 的统计确定。等级只在对应检查有明确结论时才提升：尺度检查为 UNKNOWN（标签观测不足，见 5.6）时停在"仅地图"，任务本身照常成功。

### 5.8 配置与资产改动

配置按"谁的事实"分三处，沿用现有约定：设备写在套件，场地写在场景，算法数值写在参数文件。以下键名和默认值都是提案；标"待定"的数值在阶段 1、2 拿到实测分布后确定。所有新键都要有默认值，保证现有的 `scene.yaml` 和未贴标签的场地不需要任何改动。

**套件 `kit.yaml`（设备）**：不新增字段。每手已有的可选字段 `rear_calibration` 现在只在 `dual` 模式下使用；改为 `shared_front` 模式下也可填写，填写后只启用标签，不建环境镜头地图。[kits/README.md](../../kits/README.md) 的说明相应更新。

**场景 `scene.yaml`（场地的物理事实）**：新增可选的 `tags` 块，引用海报布局资产；省略即表示不启用环境标签。布局资产、独立检测、任务融合和建图尺度入口已实现；`holdout` 仍为待讨论实验，目前不接受此键。

```yaml
tags:
  layout: environment_poster.json  # 相对 scene.yaml 的布局文件路径
  # holdout: [88]                  # 可选验证实验，使用范围仍待讨论；日常采集不要求留出
```

布局资产保存 `board_id`、字典 `DICT_4X4_100`、黑边格数、每个 ID 的四个海报局部角点坐标（米）、坐标轴和角点顺序约定，以及排版文件和实测尺寸的来源。当前规格为 1000 × 1500 mm 纸张、100 mm 标签、130 mm 中心间距、7 × 11 网格、ID 12–88；已核对 PDF 矢量坐标和 77 个渲染标签，ID 按行递增、全部同向，有效标签矩形为 880 × 1400 mm，居中页边距为左右各 60 mm、上下各 50 mm。运行时读取显式角点，不靠 ID 范围猜测坐标；这些仍是设计尺寸，不是打印后实测记录。

允许的 ID 直接来自布局，不另设默认 ID 范围；检测到未登记 ID 或同一帧重复 ID 时记录并拒绝相应观测。各帧只需观测布局中的部分标签，不要求 77 个全部可见。原方案中独立的 `size_m`、`id_range`、可选 `ids` 改由布局统一表达，避免尺寸与几何来源冲突。模板对“场景只保存模式和算法选项”的注释需同步调整。

**参数 [scene_parameters.yaml](../../config/scene_parameters.yaml)（算法数值）**：该文件是扁平键、未知字段会被拒绝，现有分组靠前缀区分（如 `gripper_width_`）。新增键统一用 `tag_` 前缀，并在 `SceneParameters` 中加对应字段。下表仍含候选参数；实际已接受的键和暂定默认值以配置文件为准，未实现项不能直接写入配置。

### 5.9 采集侧要求

- **海报**：使用现有 1000 × 1500 mm、77 个 ArUco 标签的海报；标签设计边长 100 mm。固定在平整硬背板或等效平整支撑上，实测横纵方向的标签边长及跨多个标签的距离，核对打印缩放和粘贴位置。整张海报可在录像之间移动；单个标签重新粘贴或打印尺寸变化需要更新布局，不能沿用旧几何。
- **位置**：按实际布置放在环境镜头视野内，避开人体遮挡、反光和折皱。阶段 1 统计真实操作姿态下可见的 ID 数和角点分布；不要求改成墙面、天花板分散标签，也不要求专门留一个标签验证。
- **建图时的工作区**：只留不会动的东西。会被操作的物体不要出现在建图视频里，这样它们不会进入地图，任务中被移动也不影响定位（5.11）。
- **何时重新建图**：场景重新布置、大件物体移动或光照明显变化后，开新批次并重新建图。
- **建图录像**：照现在的方式慢扫。**建议**在扫的过程中让环境镜头看到至少一个标签，并且边看边移动（前后、左右各几十厘米），这样建图时能用标签把地图尺度定准，之后所有任务受益。对着标签静止不动不算数。这不是硬性要求：没拍到时地图尺度照旧由 IMU 估计，建图不会失败。不需要每个标签都拍，也不需要近距离多角度拍清每一个。
- **任务录像**：保持海报静止、平整，允许不同帧只看到海报的不同部分。整板位姿由本任务的联合观测估计，单个 ID 不必反复可见；静止时的角点观测仍可约束相机相对海报的位姿，但不能单靠静止观测核对地图尺度。看不到海报时沿用通过原有验收的地图与 IMU 路径。
- **环境镜头参数**：优先按 [标定指南](../标定.md) 完成正式 rear 标定并登记；未绑定时可用当前 X3 INSV 工厂参数 + front B 兜底，独立 rear 精度尚未验收。

### 5.10 IMU 的角色变化

IMU 进入融合图的方式基本不变，变的是它承担的责任：从"唯一的尺度来源"变成"尺度来源之一"，并新增裁判角色。

各阶段都不变的部分：

- 相邻节点之间用 IMU 预积分约束运动。
- 零偏作为变量在融合中估计。
- 检测到静止时加零速约束。
- 定位丢失时由 IMU 衔接。
- **重力方向始终只由 IMU 提供**，标签不含重力信息。
- 工作镜头的相机–IMU 标定照旧需要。

变化的部分：

| IMU 的角色 | 现状 | 之后 | 起始阶段 |
|---|---|---|---|
| 定地图尺度 | 唯一来源：建图时 `metric_alignment()` 估一个尺度，之后固定 | 建图时 IMU 尺度与标签尺度按不确定度加权合并，再由 IMU 在合并后的尺度下重新估重力和零偏并复核；没有有效的标签估计时仍由 IMU 单独定。任务中标签与地图尺度先验共同决定 | 建图时修正：2；任务中共同决定：4 |
| 来源间的裁判 | 无 | 标签与地图矛盾时，比较哪一方推出的运动与 IMU 预积分更吻合（5.6） | 2 |
| 零偏估计 | 加速度计零偏与尺度在对齐中相互纠缠 | 有米制的标签约束后，零偏更容易估准 | 3–4 |
| 因子形式 | 场景融合用 `ImuFactor` 加零偏随机游走因子，逐段引擎用 `CombinedImuFactor` | 合并时统一为一种（4.2） | 4 |
| 独自衔接 | 仅在定位短暂丢失时 | 没有地图的任务里，两次标签观测之间全靠 IMU | 5（可选） |
| 关联的标定 | 工作镜头到 IMU 的外参和时间差 | 另加环境镜头到同一 IMU 的外参和时间差 | 2 |

尺度责任被分担是其中最重要的一条。现状下尺度完全依赖 IMU：外参、时间差、零偏的误差都会变成尺度误差；建图录像必须有足够的平移和加速度变化；尺度估出后没有独立核对。阶段 2 起，建图录像里有有效的标签估计时，地图尺度由 IMU 和标签两个估计按不确定度加权合并（5.5），IMU 再在合并后的尺度下估重力和零偏，并以惯性残差复核；没有有效的标签估计时退回现状。IMU 的尺度估计仍然参与，比重由它的不确定度决定。阶段 4 起，任务融合里尺度也成为变量，由地图尺度先验和任务内的标签观测共同决定。这相当于向 specialist 靠拢一半：specialist 把尺度完全交给标签，IMU 只负责重力和平滑运动，因此不需要用户标定 IMU；本计划保留 IMU 定尺度的能力，只是不再让它单独负责。

两条明确不做的调整：

- **不放宽建图时的运动激励要求。** 理论上标签能定尺度后可以放宽，但现有的尺度不确定度、重力大小和可观测性检查全部保留，没贴标签的场地仍需要它们。是否放宽等标签一路的实测数据积累后再议。
- **不降低 IMU 标定要求。** 重力方向、丢失片段的衔接和裁判角色都依赖它；环境镜头还要标定到同一个 IMU 上，标定工作是增加而不是减少。

### 5.11 地图过期与信息退化

两类情况都属于"某个来源的信息不够用或不可信"，处理原则相同：**能发现；不让它参与表决；剩余的不确定性如实上报；宁可明确失败，不输出看似正常的错误结果。**

#### 地图过期：任务时的场景与建图时差别大

任务定位是拿当前画面匹配冻结地图里的特征点。场景变化后有两种后果：

| 后果 | 表现 | 现有流程能否发现 |
|---|---|---|
| 匹配不上 | 定位覆盖率下降，出现长时间无定位 | 能：覆盖率低于 `minimum_localization_fraction` 或无视觉超过 `maximum_visual_gap_s` 即失败 |
| 匹配错了 | 带有大量地图点的物体被整体挪动，定位锁在它身上，相机位姿整体偏移 | 不一定：仅当偏移与 IMU 明显矛盾时才暴露 |

第二种更危险，结果平滑完整但位置是错的。海报固定在工作物体之外，在单次任务内保持静止，可以作为任务内的参照。由于海报位姿每个任务自己解（5.5），能发现的范围是：

| 情形 | 能否由标签发现 | 对训练数据的影响 |
|---|---|---|
| 任务中途定位跳到被挪动的物体上，或偏差随位置、时间变化 | 能：以标签为参照，地图定位的位置出现跳变或漂移（5.6 的"任务内定位是否自洽"） | 有，会产生错误的动作 |
| 整段任务从头到尾都锁在同一个被挪动的物体上，相对地图有一个固定偏移 | 不能：标签位姿会跟着一起偏 | 相对动作表示下没有影响；双手任务中若两只手偏移不同，由"双手一致"检查发现 |

同一海报上的多个 ID 不构成独立的静态参照：整张海报移动时，板内相对位置仍然不变。仅凭它们一致地偏离地图，无法区分整板移动与地图定位错误，应报告来源矛盾（决策 7.4）。局部 ID 异常可以提示粘贴、检测或布局问题；区分整板运动与地图问题需要额外独立证据，不能把板内刚性一致误当成海报在房间中静止的证明。

按严重程度处理：

| 程度 | 例子 | 处理 |
|---|---|---|
| 轻微 | 桌上几个小物件换了位置 | 不处理；定位自身把对不上的点当外点剔除 |
| 中等 | 部分区域认不出，定位断续 | 断开的片段由 IMU 和标签约束衔接（阶段 3 起）；可信等级降低 |
| 严重 | 大件物体移动、重新布置、光照剧变 | 该任务判失败并写明"地图可能过期"，走下面的出路 |

严重时的出路，按推荐顺序：

1. **重新建图。** 录新的建图视频生成新地图版本。批次的设计本来就是"一轮建图加几次操作"，场景重新布置后应开新批次。现有机制已支持，无需新代码。
2. **该任务自己建图，用标签放回场景。** 对失败的任务走逐段引擎，以它自己的画面建图，再由标签确定尺度和摆放。这是阶段 5 的具体用途之一；阶段 4 合并两套融合图之后，它与正常路径是同一套代码，区别只是地图是临时的、摆放先验放松。前提是该任务自身有足够视差并看到了标签。
3. **环境镜头参与定位（`dual` 模式）。** 工作镜头看的工作区正是最容易变的地方，被操作的物体每个任务都在动；环境镜头看的是房间背景，稳定得多。`dual` 模式需要的环境镜头标定本计划本来就要做，场景变化频繁的场地长期应考虑它。

不做：让地图在任务过程中自动更新。这会破坏地图冻结、版本固定、结果可复现的设计。

#### 信息退化：某个来源在某些方向上没有约束力

退化是指数据在，但几何上定不住某些量。各来源的典型情形：

| 来源 | 退化情形 | 定不住的量 | 怎么发现 |
|---|---|---|---|
| IMU | 静止、匀速、只转不移 | 尺度、加速度计零偏 | 现有：`_observability_matrix()` 的秩和条件数（`maximum_alignment_condition`），不过即拒绝发布地图 |
| 视觉建图 | 只转不移（无视差）、纹理稀少 | 地图点深度，进而整张地图 | 现有：建图跟踪比例、初始化失败、逐段引擎的重试与尺度一致性检查 |
| 地图定位 | 画面被手和物体遮挡、特征点集中在一小块或一个平面上 | 部分方向的位姿 | 现有只有"是否定位成功"；可补每帧的匹配点数和分布（需 ORB 一侧输出，待评估） |
| 单个标签，距离远 | 标签在画面里很小 | 沿视线方向的距离 | 标签边长像素；重投影因子自动弱化该方向 |
| 海报，远距离近平面正视 | 平面位姿可能存在两个相近的解，多 ID 仍然共面 | 倾斜和深度方向 | 联合板面覆盖、多视角及惯性信息判断；不能仅按 ID 数量宣布消除歧义 |
| 标签，相机静止时才看到 | 没有相对位移 | 尺度比 | `tag_minimum_comparison_extent_m` |
| 只有一张海报 | 所有 ID 共享整体运动，缺少独立静态参照 | 整板移动与定位错误的归因 | 报告来源冲突，不能用板内 ID 数代替独立参照数量 |
| 海报只露出窄条或局部区域 | 有效角点的二维分布不足 | 部分朝向和距离 | 可见角点在板面和图像中的分布 |
| 海报位姿由不足的观测估计 | 海报位姿本身不准，对轨迹约束随之变弱 | 海报的位置和朝向 | 5.5 的整板使用条件，不逐 ID 分别拒绝 |
| 全部来源同时缺失 | 既无定位也无标签 | 位置（IMU 单独积分很快发散） | `maximum_visual_gap_s` |

处理退化的四条规则：

1. **区分坐标规范、观测约束与物理先验。** 阶段 4 的地图摆放有建图结果的先验；海报只有一个本段位姿变量，由轨迹与固定布局的有效角点约束，不能为稳定求解而套用可能已经移动的建图海报位姿。整板观测不足时不声称可观测。没有地图时（阶段 5）必须固定海报上的参考位置和水平朝向，消除全图自由平移及偏航；可参考 specialist 的 `anchor_gauge_prior()`，倾斜仍由惯性重力约束。
2. **退化的来源不参与表决。** 证据不足的检查记为 UNKNOWN（5.6），不拿它去判定别的来源对错。例如相机几乎没动时不计算尺度比；只有一张海报时，即使看到多个 ID，也不单凭整体偏移断定地图过期。
3. **退化要落到逐帧。** 逐帧约束记录（5.2）标明每一帧由哪些来源约束。只靠 IMU 衔接的片段、只有单个远处标签的片段，在结果里可以被识别和剔除，而不是只给整段一个结论。
4. **保留现有的硬性拒绝。** 建图的可观测性检查、定位覆盖率和最长无视觉时长的门槛都不放宽。标签的加入只增加证据，不降低已有门槛。

一个可选的增强：融合后计算各节点位姿的后验协方差（GTSAM 的边缘化），作为逐帧不确定度写入结果。它能统一地反映上述所有退化（哪一帧、哪个方向定得不好），而不需要为每种情形单独写检查。代价是计算量，可只对抽样节点计算。是否实施留到阶段 3 之后根据需要决定。

### 阶段 5（可选）：没有地图的任务

只有标签和 IMU 时也能输出，并标记标签消失的片段为不可靠。没有地图定位先验时，固定海报上的一个参考点和水平朝向，竖直方向取重力；所有板内 ID 仍使用同一海报变量和固定布局，不另建自由位姿。IMU 单独衔接的能力有限，具体缺口容限需要实测，因此对海报可见性要求高。

2026-11-11 进度：独立轨迹和单手回退的原生图已加入海报约束，保留惯性尺度初始化及原有世界规范。下述“由标签完全负责初始化、参考点定原点”等方案仍未实现，不能视为整个阶段已完成。

两个用途：一是现场无法慢扫时的常规路径；二是共享地图对某个任务不可用（地图过期，见 5.11）时的回退路径，此时用该任务自己的画面建临时地图，再由标签确定尺度和摆放。第二个用途即使现场总能慢扫也有价值。

## 7. 决策

7.2、7.3、7.7 已定，其余待定。2026-11-11 补充明确主目标：采集前建图，任务抽取时将环境标签加入地图定位与 IMU 的融合（第 1 节）；实际载体为已知布局的 ArUco 海报，不以无地图模式为主线。

### 7.1 两套融合图何时合并

- A. 阶段 0–3 只扩展场景融合，阶段 4 合并。**（倾向）**
- B. 阶段 0 就合并。

理由：逐段引擎承担标定 C 段验证并有逐字节一致的回归基线，过早改动风险大；阶段 4 本来就要把它的因子搬过来，届时合并是顺带的结果。

### 7.2 环境标签用哪种码

**已定：使用现有海报的 ArUco `DICT_4X4_100`（2026-11-11）。** ID 12–88，共 77 个；不是夹爪检测当前使用的 `DICT_4X4_50`，也不是 specialist 的 AprilTag。

原先倾向 AprilTag 36h11 的方案由实际海报规格替代。specialist 的标签角点因子思路继续参考，检测器与板内布局按实际海报适配。用户 PDF 已核对：黑边 1 格、ID 按行递增、朝向一致，见布局资产。

### 7.3 标签位姿从哪来

**已定：B（2026-11-10）。**

2026-11-11 根据实际采集方式再次确认 B：建图和任务中都经常看到标签，但标签在建图后或任务之间可能移动。建图观测用于该次地图的尺度估计，任务观测用于该任务的轨迹融合；不复用跨录像的标签位置。

同日进一步明确：标签在一张有已知排版的海报上。因此 B 的求解单位改为“每段录像一个海报位姿”，各标签位姿由固定布局导出；复用板内几何，不为每个 ID 单独解自由位姿。

- A. 建图时解一次并冻结。
- B. 每个任务自己解。**（采用）**

A 要求建图录像足够确定海报位姿，并要求海报在地图使用期内不动；B 只要求海报在每段录像内静止、板内布局保持一致，每个任务要有足够观测确定海报位姿，且无法发现任务相对地图的固定偏移。完整对比见 5.5。原先单标签独立求解的描述已按整板已知布局调整。

将来若需要 A 的能力（用更少的任务内观测获得约束，或发现固定偏移），可以在 B 的基础上给标签位姿加一个来自建图的先验，不必推翻现有结构。

### 7.4 来源互相矛盾时

- A. 判失败，报告是哪一方的问题。**（倾向）**
- B. 告警，自动降低可疑一方的权重后继续。

A 会多丢一些任务，但不会把有问题的数据放进训练集。

### 7.5 是否做阶段 5

取决于两点：采集现场是否总能慢扫；地图过期导致的任务失败有多常见（5.11）。前者决定是否需要它作为常规路径，后者决定是否需要它作为回退路径。阶段 2 的校验上线后可以统计后者的发生率，再做决定。

### 7.6 可信等级是否影响训练导出

`training_ready` 是否要求达到某个等级，或只把等级写入导出包由训练侧筛选。

### 7.7 建图录像里的标签怎么用

**已定：B（2026-11-10）。**

- A. 只核对地图尺度，不修正。
- B. 标签估计有效时，用标签修正地图尺度。**（采用；合并方式为按不确定度加权平均，同日确定）**
- C. 先 A，积累数据后在阶段 4 改为 B。

采用 B 的理由：地图尺度为所有任务共用，建图时修正一次，任务中看不到标签的也受益；尺度是标签最能改善、对训练数据影响最直接的一项（4.3）。做法和保护措施见 5.5：不充足时退回 IMU 尺度；两个来源矛盾时不默默选用；修正后用惯性残差复核。标签不改变地图的形状。

由此带来的变化：阶段 2 不再是"完全不改变现有轨迹"，贴了标签且建图时拍到的场地，地图尺度和其下的轨迹会变；建图录像从"不用拍标签"变为"建议拍，但不强制"。为降低风险，阶段 2 内部先记录后生效（见阶段 2）。

## 8. 风险与未验证的假设

| 项 | 现状 | 影响 |
|---|---|---|
| 环境镜头标定 | 截至 2026-11-10，registry 中两台相机的当前目录里只有工作镜头的标定 | 阶段 2 的前置 |
| 标签可见比例 | 未实测 | 决定阶段 3 的收益；阶段 1 回答 |
| 任务内海报观测是否够解出位姿 | 未实测。按整板的时间覆盖、角点分布和几何条件评估，不要求每个 ID 都有充分观测 | 阶段 1、2 给出满足 5.5 条件的任务比例，而不只统计 ID 总数 |
| 任务相对地图的固定偏移 | 每任务求解标签位姿后无法由标签发现 | 不影响相对动作形式的训练数据；若将来需要绝对坐标，要回到给标签位姿加建图先验的做法（7.3） |
| 环境镜头有效视场 | 标定只覆盖中心 1440 裁切，环境镜头实际有效区域待自身标定核对 | 大海报可能只部分落入有效区域，应按可见角点统计而非要求整板入镜 |
| 远处标签的像素大小 | 按约 550 px 等效焦距粗算，现有 100 mm 标签在 2.5 m 处约 22 px，实际还受鱼眼投影、角度和模糊影响 | 海报整体很大不保证每个小标签都能可靠解码；阶段 1 实测 |
| 海报布局与实际打印不一致 | PDF 的 ID 行列、朝向、黑边和设计尺寸已核对，打印后实际尺寸未测；海报可能弯曲、起皱或打印非等比缩放 | 已生成明确的 ID → 米制角点布局，仍需实测打印成品横纵尺寸；布局共同误差不能靠 77 个 ID 平均消除 |
| 两个镜头的时间偏移差 | 未量 | 决定标签观测时刻的处理方式（5.3） |
| 卷帘快门 | 现有融合未建模；标签角点在快速运动时会受影响 | 可能需要按角速度筛选或降权 |
| Python 自定义因子的速度 | 每帧新增若干因子；逐段引擎已是每个观测一个自定义因子，量级相近 | 需实测 |
| 地图定位误差的相关性 | 阶段 3 仍把每帧定位当独立先验，地图的整体偏差会压过标签；阶段 4 才解决 | 阶段 3 的改善可能有限，属预期 |
| 工作镜头与出厂参数的对应 | 当前 X3 安装已按 specialist 的解析与夹爪检测路径统一：工作 lens1、环境 lens0，见[镜头术语](../设备与坐标.md#镜头术语) | 保留原始编号；镜头身份明确不能代替模型和图像观测验收 |
| 标签被移动或尺寸填错 | 属系统性错误，鲁棒核处理不了 | 依赖 5.6 的来源间校验 |
| 边长填错会直接写进地图尺度 | 建图时用标签修正尺度（决策 7.7）后，边长错 1% 地图尺度就错 1%，且影响该地图下所有任务 | 保护：与 IMU 尺度偏差超过失败界限时判为矛盾；修正后用惯性残差复核。小于界限的边长误差发现不了，所以边长必须用尺子实测并记录 |
| 远处小标签给出的尺度不够准 | 尺度来自相机相对标签的位移，标签远、位移小时不确定度大 | 加权合并下它自动少占比重；另有有效性门槛把关，数值待实测 |
| 不确定度估不准，加权就失真 | IMU 的 `relative_scale_std` 和标签的最小二乘协方差都只反映数据内部的离散，不含系统误差，很可能偏小 | 两边各加地板项；用归一化差值的实测分布检验后再让合并生效（5.5）。在此之前这是加权平均方案的主要不确定因素 |

本计划中的 specialist 行为来自阅读其源码，未运行；环境标签重构已部分实施，未完成项仍属于计划。后续内参来源开关与真实工作镜头验证已另行完成，证据和环境镜头待验证范围见[标定架构与验证](标定架构与验证.md#14-实测出厂内参来源开关2026-11-10)，不代表海报融合已通过真实任务验证。
