# 场景配置与排障

本页说明场景参数、批次选项、视频配对、地图复用和故障处理。首次采集按[安装与日常使用](安装与日常使用.md)完成；设备字段见[套件说明](../kits/README.md)，数据布局见[设备与坐标](设备与坐标.md)。

## 配置分别写在哪里

| 文件或目录 | 管理内容 | 填写方式 |
|---|---|---|
| `kits/<套件>/kit.yaml` | 左右相机、明确的相机标定版本及夹爪文件路径 | 手动填写；可跨场景复用 |
| `scenes/<场景>/scene.yaml` | 处理模式、参考手和非默认参数 | 可省略；需要覆盖默认值时填写 |
| `<批次>/batch.yaml` | 本轮套件、使用手和可选复用地图 | 手动填写 |
| `<批次>/mapping/` | 本轮建图 INSV | 放置原片 |
| `<任务>/.umi/episode.yaml` | 程序生成的原片引用，人工指令和同步 | run 后补充说明与同步；保留原片引用 |

套件名来自目录且在项目内唯一；批次名在场景内唯一；任务名在批次内唯一。推荐使用 `20261105_001`、`take_001`。任务名不能使用 `cache`、`runs`、`results` 等内部目录名。

## 场景参数

默认 `shared_front` 使用一张共享前地图，支持左手、右手和双手任务。每个批次的 `mapping/` 放恰好一段建图录像，实际来源相机按 INSV 序列号识别；建图只用一只手也能处理后续双手任务。

需要调参时，复制[场景模板](../scenes/example_scene/scene.example.yaml)为 `scenes/shelf/scene.yaml`，只保留需要覆盖的字段：

```yaml
mode: shared_front
trajectory:
  video:
    frame_step: 2
```

`trajectory` 覆盖 `config/trajectory.yaml`，`parameters` 覆盖 `config/scene_parameters.yaml`，均直接填写映射。视频裁切、尺寸、编码、音轨和参数单位见[参数说明](../config/README.md)。

### 前后双镜头模式

`mode: dual` 使用左右前地图和共享后地图，需要左右设备各自的实测后镜头标定。在 `kit.yaml` 的每手设备中填入已登记的 `rear_calibration` 版本，在 `scene.yaml` 选择：

```yaml
mode: dual
reference_arm: left
```

建图原片按手放置：

```text
<批次>/mapping/
├── left/左手建图原片.insv
└── right/右手建图原片.insv
```

之后仍执行 `run <批次>`。建图阶段验收并固定前后地图的放置、尺度和重力，设备与手的对应关系必须匹配所选地图。模式的算法差异见[算法原理](算法原理.md)。

## 批次选项

[批次模板](../scenes/example_scene/20261104_001/batch.example.yaml)列出全部用户字段：

| 字段 | 默认与要求 |
|---|---|
| `kit` | 必填；引用已有套件目录名 |
| `arms` | 默认使用套件全部手；可写非空子集，如 `[right]` |
| `map_version` | 默认使用本批次 `mapping/` 重新建图；填写时明确复用已发布地图，并移走本轮建图原片 |

套件只有右手时不用重复写 `arms`。双手批次缺少一手视频会保持不完整，不根据缺片改变预期使用手。

每次 `run` 都读取当前 `batch.yaml`、`kit.yaml` 和建图原片，核对测量资产并更新内部解析记录。修改相机标定、夹爪几何或建图原片后，直接重跑当前批次；运行开始时复制测量文件，历史成功结果保存当时的配置、资产副本与输入。`registry/` 中的固定测量资产应保留。

## 原片配对与补片

已确定任务归属时，把对应视频放在同一 take 的 `left/`、`right/` 中，每侧一段。程序读取内部序列号核对身份，记录 SHA256 并按内容去重，保留 take 名称和分组。缺片时补到同一任务对应侧，然后重跑。

未分组原片可放在批次 `pending/`。run 按序列号、文件名开始时间和视频时长寻找唯一配对，成功后才归入任务。默认开始时间容差 2 秒、时长差容差 1 秒，读取 `config/scene_parameters.yaml`。这些数值不修正双手时间轴，也不使用文件修改时间代替录制时间。

歧义原片继续留待确认；人工把对应视频整理到同一 take 后重跑。同一原片不能属于多个任务。其他套件设备会报告不匹配，需移出本批次或修正配置。

### 同一批次中的单手任务

如果本批次所有任务都只采右手，在 `batch.yaml` 写 `arms: [right]`。若双手批次中只有某一次操作确实仅录右手，首次 run 生成任务清单后，在该任务 `.umi/episode.yaml` 写：

```yaml
expected_arms: [right]
```

保留自动生成的 `schema_version` 和 `recordings`，确认实际原片只包含声明的手，再重跑。任务使用手必须是批次预期使用手的非空子集。指令与同步的填写方式见[训练数据指南](训练数据.md)。

## 地图复用与重建

地图发布到 `scenes/<场景>/.umi/maps/versions/<版本>/`。版本号例如 `20261105_153000-65d192ef`，使用本机开始时间和随机标识；完整输入身份保存在地图 `manifest.json`。

程序核对建图录像、设备资产、参数和算法指纹，相同输入复用已有地图。相机标定或建图原片变化会重新构建；宽度标定变化继续复用地图。夹爪几何内容计入当前建图身份，更换 TCP 几何可能触发重建。

新批次不会自动采用场景最近地图。明确复用时，在 `batch.yaml` 写 `map_version` 并移走 `mapping/` 中的建图原片。不同地图版本的坐标不保证一致。

只检查建图时可执行：

```bash
./umi-scene build scenes/shelf/20261105_001
./umi-scene build scenes/shelf/20261105_001 --force
```

`build` 只执行建图；`--force` 强制生成新版本，`--keep-work` 保留成功运行的中间数据。正常 `run` 已包含建图。高级 `run --map-version <版本>` 只覆盖该次任务处理的地图选择，下次仍读取配置；当前批次准备仍校验声明与建图输入。

地图清单、尺度诊断和约束依据见[算法原理](算法原理.md#共享地图的尺度与发布条件)，结果中的地图引用见[结果说明](结果查看与验收.md#场景任务结果)。

## 批量处理与检查

```bash
./umi-scene run scenes --jobs 2
./umi-scene run scenes/shelf/20261105_001 --dry-run
./umi-scene status scenes/shelf --json
./umi-scene preflight scenes/shelf/20261105_001/take_001 --json
```

`--jobs` 按 CPU 与内存设置。预览与实际运行共用原片规划，预览不创建清单、锁、地图、缓存或结果。它只能检查当前输入和计划，不能保证视觉建图成功。

原片检查包含录制模式、IMU 有效性、时间覆盖、时长、开头静止和曝光。规则来自 `config/scene_parameters.yaml`：

| 状态 | 含义与处理 |
|---|---|
| PASS | 满足当前检查规则 |
| WARN | 给出提醒并继续，如开头静止不足 |
| FAIL | 阻止处理，需修正输入 |
| UNKNOWN | 缺少判断依据，如原片没有曝光信息 |

`--skip-preflight` 供排障使用。检查通过不等于物理轨迹精度达到要求；查看、验收与导出按[结果指南](结果查看与验收.md#人工验收与导出)执行。

## 故障排查

| 问题 | 检查或操作 |
|---|---|
| 缺手、同一侧多段或配对歧义 | 核对 take 分组及内部序列号，每侧保留正确的一段原片；补片后重跑 |
| 套件或测量版本不可用 | 核对 kit.yaml 与 registry 中的实际版本；安装后手动更新套件 |
| 新批次没有建图输入 | 放入 mapping 原片，或明确填写 map_version；两者不能并用 |
| 建图失败或尺度不可靠 | 查看地图版本 work 下的对齐诊断；改善平移、旋转与环境覆盖后重录 |
| 预检失败 | 查看报告中的具体检查项，按录制要求修正原片 |
| 输入变化后验收失效 | 重跑、查看新结果并重新验收 |
| 失败后仍能看到旧 results | results 保留上次成功结果；以最新处理状态判断是否有效 |

任务失败摘要和调用栈位于 `<任务>/.umi/runs/<失败运行>/error.json`，原片检查报告在失败现场保留。成功结果按输入和算法指纹复用，阶段缓存支持重试；相同输入、相同原因的失败去重。内部文件位置见[目录参考](设备与坐标.md#目录)。
