# 场景处理

本文说明批次建图、任务定位、共享地图验收、失败诊断和高级场景配置。日常只需准备 `batch.yaml`、`mapping/` 和任务视频，然后执行 `./umi-scene run <批次>`；本文件中的分步命令用于高级配置和排障。

日常先填写 `batch.yaml`、放好视频，再用 `./umi-scene run <批次>` 自动登记、建图和抽取，见[日常使用](安装与日常使用.md)。下面的分步命令用于高级配置与排障，日常无需逐条执行。

[文档导航](README.md) · [设备与目录](设备与坐标.md) · [录制建议](安装与日常使用.md)

按 **套件、场景 → 采集批次 → 任务** 组织。套件定义左右手设备及测量版本，场景管理工作环境和共享地图；批次清单明确记录本次场景使用的套件，任务对应一次录制。相机测量仍保存在全局设备资产库。

任务清单可配置人工核验的双手固定时间偏移，采用 `t_episode = t_video + offset`；未配置时保留未经确认的零偏移假设。指令、同步配置与`umi-scene export --format training`见 [训练数据指南](训练数据.md)。当前不自动估计同步或时钟漂移。

## 登记套件与场景

设备先完成标定并手动 `umi-calib install`。以下命令从项目根目录执行，序列号按实际替换。

```bash
./umi-scene kit kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL
./umi-scene kits
./umi-scene init scenes/shelf
```

仅左手用 `--left`，仅右手用 `--right`。套件只有一个顶层 `kits/<套件>/kit.yaml`，保存当前左右手设备、标定和夹爪配置。上述命令读取设备当前默认测量并写入此文件，重新登记同名套件会更新它。套件可以被多个场景复用。场景已有 `scene.yaml` 时直接复用。日常按批次登记建图录像，每轮重新建图使用新批次。

## 建立采集批次

```bash
./umi-scene session scenes/shelf --name 20261025_001 --kit kit_001 --mapping /media/sd/VID_mapping.insv
# 相同套件可以直接用于另一个场景
./umi-scene init scenes/counter
./umi-scene session scenes/counter --name 20261025_001 --kit kit_001 --mapping /media/sd/VID_counter_mapping.insv
```

套件名在项目内唯一，批次名在场景内唯一；不同场景可以使用同一个套件。创建批次时指定场景、批次名和套件。程序校验 `kit.yaml` 中的实测资产，把设备配置自动保存到批次的 `.umi/manifest.yaml`；每次 run 读取当前套件，修改套件后再次 run 会采用当前配置，历史运行仍保留当时使用的设备版本。

```yaml
# kits/kit_001/kit.yaml：可跨场景复用的套件配置
arms:
  left:
    serial: LEFT_SERIAL
    calibration: '001'
    gripper: handheld_v1
    gripper_version: '003'
```

批次默认使用套件全部手；双手套件只采右手时加 `session ... --arms right`。批次不要求地图已经存在，也不要求采完当天就离线处理。

任务原片与清单、结果放在同一个 take 内，原片直接位于 `take_001/left/`、`take_001/right/`。已按 take 整理的每侧一段原片保留分组，无需再次按时间猜测归属。自动发现只扫描这些原片目录及批次 `pending/`，跳过任务的 `results/` 和 `.umi/`。

旧的 `take_001/videos/left/`、`right/` 仍兼容，原片继续原地引用，不自动迁移或复制；新导入和补齐的原片写入任务下的 `left/`、`right/`。同一个 take 每侧应只有一段原片，旧、新目录中同时存在多段不同原片仍会报待确认。

每次任务直接放在批次目录中，例如 `scenes/shelf/20261025_001/take_001/`；批次快照位于批次 `.umi/manifest.yaml`。任务名不能使用 imports、cache、runs 等内部目录名称。

场景和套件名称直接来自目录；批次和任务的上级清单按固定层级确定，不再重复写路径。默认使用 `shared_front`，单段建图自动确定参考来源。空描述、未指定的参数覆盖、未绑定的地图均不写空字段；`expected_arms` 默认继承，只有明确使用部分手时才写覆盖。单手录制不写同步配置。


## 导入原片与任务配对

```bash
./umi-scene ingest /media/sd/this_session \
  --session scenes/shelf/20261025_001 --dry-run
./umi-scene ingest /media/sd/this_session \
  --session scenes/shelf/20261025_001
```

导入目录只放本批次的原片。导入读取 INSV 内部序列号，按套件确定左右手，保留原名并记录 SHA256。按内容去重，重复执行不重复创建已登记任务。其它套件设备会被列为忽略，不参与配对。

单手批次每段录像生成一个任务。双手批次按文件名中的开始时间和实际视频时长筛选，只有双方候选都唯一才自动配对。默认开始时间容差 2 秒、时长差容差 1 秒，见 `config/scene_parameters.yaml`。这些数值只用于配对，不用于修正时间轴。

无法配对或有歧义的未分组原片留在批次 `pending/`，导入报告列出待确认项。下一次导入会重新考虑未分配原片。不从文件修改时间猜录制时间，不把缺手双手任务降为单手。

需要人工指定配对或操作描述时，使用 `--instruction`：

```bash
./umi-scene episode scenes/shelf/20261025_001 --name take_001 \
  --left /media/sd/LEFT.insv --right /media/sd/RIGHT.insv --instruction '取出商品并放入篮子'
```

可以先只登记其中一手，再用同一任务名补齐另一手。手动补片和自动配对共用写入规则，保留已有任务描述；重复登记同一内容不会改写清单或清除验收。双手批次中确实只录右手的一次任务，必须明确声明：

```bash
./umi-scene episode scenes/shelf/20261025_001 --name take_right \
  --arms right --right /media/sd/RIGHT.insv
```

批量导入单手任务同样使用 `ingest ... --arms right`。预期使用手只能是批次已声明手的非空子集，不能用缺失原片隐式改变预期。

## 离线建图与抽取

```bash
./umi-scene build scenes/shelf/20261025_001
./umi-scene run scenes/shelf/20261025_001 --dry-run
./umi-scene run scenes/shelf/20261025_001
./umi-scene status scenes/shelf
./umi-view scenes/shelf
```

地图保存到 `scenes/<场景>/.umi/maps/versions/<版本号>/`，`.umi/maps/current.json` 指向当前版本。
新版本号如 `20261025_153000-65d192ef`：依次为本机建图开始时间、8 位随机标识。输入身份完整保存在 `manifest.json` 的 `inputs` 中，用于复用判断与追溯，不再重复放进目录名。
时间使用运行机器的本地时区；输入未变化时复用原版本，`build --force` 才强制重新构建。已有不带时间或包含输入指纹的地图版本仍可使用，无需改名。

每个地图版本包含 `manifest.json`、`maps/`、`devices/`、展示数据 `map.json` 和摘要 `report.txt`。
建图配置统一保存在清单的 `inputs.definition`，成功导出不保留空日志；有内容的日志和失败现场保留。
成功建图默认清理 `work/`，可用 `--keep-work` 保留。已发布版本不改写，避免改变批次固定的清单哈希。

地图米制化复用轨迹后端的运动段筛选：先按跟踪中断、视觉与陀螺仪旋转不一致切段，长段失败时进一步细分；仅用通过验收的可靠段共同估计一个尺度、重力方向和加速度计零偏。各段速度独立，但同一张地图不会分配多个尺度或放置。可靠段尺度或重力方向冲突、运动退化或残差过大时，仍拒绝发布。

可靠段通过后，还会把这一个固定尺度、重力和零偏用于复核其余可检查段的惯性位置方程；不再为这些段另拟合尺度。任一段的 RMS 超过 `maximum_alignment_rms_m` 就拒绝整张地图。这样不会把“后半段可定标”误当成“整张地图可共用尺度”。诊断中的 `fixed_map_validation` 记录逐段结果；地图不能通过此检查时，独立轨迹后端仍可能以分段尺度和惯性衔接输出录像轨迹，两者不等价。

分段与求解参数读取 `config/trajectory.yaml` 的 `fusion`；共享地图的尺度不确定度、重力、可观测性与残差门槛读取 `config/scene_parameters.yaml`。默认门槛保持尺度相对不确定度不超过 20%、自由重力与 9.81 的差不超过 0.5 m/s²。可靠段与共同尺度的相对偏差也不得超过尺度门槛，重力向量差不得超过重力门槛。

失败的每个候选子地图在 `.umi/maps/versions/<版本>/work/try_<次数>/<地图角色>/localize/m<索引>/metric_alignment.json` 中保留各运动段尺度、不确定度、重力和共同拟合结果。成功版本在 `manifest.json` 的 `maps.<地图角色>.placement.evidence.alignment` 中保存相同诊断；这些是内部一致性指标，实际位置精度仍需独立验证。

同一场景的任务在 `episode.json` 的 `map` 中记录展示地图相对运行目录的路径和 SHA256，左右手共用该引用，直接读取该版本的 `map.json`。单独打开原位置的任务或结果目录也可查看共享地图；移动数据时应携带场景地图并保留相对目录结构。各手指标和配置统一位于 `arm_results`，人工阅读只需打开根 `report.txt`。

`shared_front`：一张共享前地图，任务相机在已有地图中定位。建图可以只使用一只手。日常建图使用 `--mapping <原片>`，该原片不限制后续任务的左右手身份。

`dual`：左右前地图加共享后地图；建图需要两只手的参考录像和对应实测后镜头标定。前后地图放置、尺度和重力在建图阶段验收并冻结；双镜头设备与手的对应关系必须匹配固定地图。

```bash
./umi-scene build scenes/shelf --mode dual \
  --mapping-left /media/LEFT_mapping.insv --mapping-right /media/RIGHT_mapping.insv \
  --rear-left /measurements/LEFT_rear.json --rear-right /measurements/RIGHT_rear.json
```

`run <批次>` 每次读取当前 batch.yaml、kit.yaml 和 mapping/。单段建图不写左右手标签，实际相机按 INSV 序列号匹配套件。修改相机标定或替换原片后重跑，地图输入身份变化会自动重建；输入相同则复用。width_calibration 变化继续复用地图。

明确复用历史地图时，在 batch.yaml 中设置 map_version，并移走 mapping/ 中的本轮建图输入。修改该配置后重跑即可生效；高级 `run --map-version <版本>` 仅覆盖本次命令。不同地图版本不保证坐标一致。历史结果保存当时的 kit、地图版本和输入指纹，当前解析记录不控制配置。

任务只定位已有地图，再融合各自 IMU，输出固定场景系的 TCP 轨迹。场景算法与内部逐段轨迹引擎 的区别见 [原理](算法原理.md)。

```bash
# 批量处理所有场景；默认逐任务执行
./umi-scene run scenes --jobs 2
./umi-scene status scenes --json
```

并行数按 CPU、内存设置。成功结果按输入和算法指纹复用；准备数据和定位结果分阶段缓存，融合失败重试可复用定位。失败记录在独立运行目录，已有 `results` 成功入口保留。`--dry-run` 只读，不创建运行、锁、缓存或报告。

## 录制检查与验收

```bash
./umi-scene preflight scenes/shelf/20261025_001/take_001 --json
```

处理前检查原片模式、IMU 有效性与时间覆盖、时长、开头静止和曝光。检查规则及完整参数先写入 `preflight_report.json`；成功后收入 `episode.json` 的 `preflight` 并移除独立文件，失败时保留原始检查报告。根 `report.txt` 展示检查结论及 WARN/UNKNOWN 提醒。检查没有固定的耗时保证。

| 状态 | 含义 |
|---|---|
| PASS | 本项满足已实现规则 |
| WARN | 建议改善，例如开头不够静止；继续处理 |
| FAIL | 明确不满足规则；阻止本次处理 |
| UNKNOWN | 所需信息缺失，例如原片没有可用曝光信息 |

静止窗口用于改善惯性初始化，不要求任务录像必须有大幅运动；独立的地图尺度恢复仍要求足够可观测运动。检查通过不代表轨迹已达到某个绝对精度。`--skip-preflight` 仅用于排障，不替代人工验收。

处理完成后查看 `results/report.txt`，结合视频、地图与轨迹做人工验收（支持对整个批次一键验收，或单独验收单个任务）：

```bash
# 批次一键验收
./umi-scene review scenes/shelf/20261025_001 \
  --accept --reviewer reviewer_001

# 单个任务验收
./umi-scene review scenes/shelf/20261025_001/take_001 \
  --accept --reviewer reviewer_001
./umi-scene export scenes/shelf/20261025_001/take_001 \
  --out exports/dataset_001
```

拒绝用 `--reject --reason '原因'`。验收绑定具体成功结果；换输入、重算出新结果或新尝试失败后，需要重新确认。导出要求所有选择任务都是当前有效且人工接受的结果，已有导出目录拒绝覆盖。默认导出 TCP、报告、元数据和双手表，可加 `--with-video`。导出清单保留各任务地图坐标 ID，不把不同地图版本当成同一坐标。

## 已有验证与边界

模拟商超样例使用历史实验室单相机录像；新组织流程已实际处理 1041 帧、约 34.7 秒。套件更新与批次快照、跨场景、单手/双手、漏片补齐、失败重试和验收导出由自动化测试覆盖。尚无真实双机新采数据完成物理回归，也没有独立真值支撑的绝对精度结论。
