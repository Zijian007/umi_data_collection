# 结果、查看与验收

本文说明 `umi-view`、结果目录、轨迹字段、视频帧号、人工验收和导出前检查。

## 查看器

同时查看 UMI 的三维轨迹、环境稀疏地图、姿态、前镜头视频和速度曲线。读取 UMI 自己的结果格式，无需 Node 构建或加载外网资源。

`./umi-view scenes/<场景名>` 也可查看 `umi-scene` 已发布的任务：同一三维画面显示左右手，配两路同步视频，只回放共同有效时间。场景操作见 [场景与双手任务](场景处理.md)。

[文档导航](README.md) · [结果格式](结果查看与验收.md) · [查看器代码](../software/viewer/README.md)

从项目根目录启动：

```bash
./umi-view
```

浏览器打开 **http://127.0.0.1:9091**。默认扫描项目的 `scenes/`，自动打开最新一段成功轨迹。新录像抽取完成后，点击录像库旁的刷新按钮即可。

也可以指定场景、采集批次或单个结果目录：

```bash
./umi-view scenes/shelf
./umi-view scenes/shelf/20261104_001
./umi-view --port 9092
```

`umi-view` 的 HTTP 服务使用 Python 标准库，采集清单读取依赖 ruamel.yaml，无需在服务进程加载 SLAM 或惯性融合环境。旧地图转换自动调用项目 `.deps/env/bin/python` 与已安装的 ORB 地图导出器；自定义依赖目录时设置 `UMI_DEPS`，或将 `UMI_PY` 指向对应环境的 Python。`UMI_VIEW_PYTHON` 仍可指定服务器使用的 Python。

默认监听本机；如果查看器运行在实验室服务器、浏览器在另一台电脑，可用 SSH 转发：

```bash
ssh -L 9091:127.0.0.1:9091 zijianwang@lab1
```

然后在电脑上打开 http://127.0.0.1:9091。也可以显式使用 `--host 0.0.0.0`，通过服务器 IP 访问。

## 操作

- 左侧选择录像，或搜索文件名、路径、序列号。
- 左键拖动旋转，右键或 Shift 拖动平移，滚轮缩放；双击或 `R` 复位。
- 顶部切换 TCP／相机／IMU；打开“对照轨迹”查看其他轨迹的虚线轮廓。
- “环境地图”控制稀疏点云显示，下拉框切换前镜头子地图；“关键帧”显示代表性相机位置与朝向。
- “地图坐标轴”显示所选子地图的 `O_map` 原点及红 X、绿 Y、蓝 Z 轴，标签注明轴长（原始地图单位）。已对齐地图的轴与点云使用同一变换，其原点和方向可以不同于轨迹世界坐标；右下角方向提示会单独注明世界／地图方向。
- “世界坐标轴”显示轨迹世界系的 `O_world` 原点及 XYZ 轴，Z 朝上，长度单位为米。两套轴默认同时显示、分别开关：世界轴用虚线，地图轴用实线，并以 `_world`／`_map` 标签区分。未对齐子地图使用原始地图坐标时，世界轴自动隐藏且开关禁用；切回已对齐地图或隐藏原始地图后恢复。
- 开关坐标轴保持当前旋转、缩放和平移；需要按当前显示内容重新取景时，按 `R`、双击画布或点击“透视”。
- 当前位置的红、绿、蓝姿态轴分别是局部 X、Y、Z，经四元数转换到该录像的世界坐标。
- 空格播放／暂停，左右箭头逐帧；拖时间轴或点击速度图、三维轨迹可定位时间。
- 视频、三维位置、姿态和速度使用同一时间轴；支持倍速和循环。
- “查看本次记录”显示当前标定、目录、运动范围和诊断摘要。

## 环境地图

地图异步加载，轨迹和视频先显示。新的抽取结果自动保留 `details/map.json`；旧结果如果保留了选中轮次的 `map.osa`，首次查看会自动转换，不需要重建地图，也不会修改旧结果。若地图已清理且没有轻量地图产物，界面会提示，仍可独立查看轨迹。

旧地图的转换结果会持久缓存，重启查看器后直接复用；地图、轨迹或转换实现变化时自动重新准备。

可靠对齐的地图叠加在米制轨迹上，并显示用于展示的拟合残差。它表示地图与融合轨迹的一致性，不是独立真值误差。静止、近直线运动、对应点不足或拟合残差过大时，子地图按原始地图单位单独显示，隐藏轨迹叠加；时间轴、视频和下方轨迹位姿读数仍可使用。

每张子地图独立选择，不混合不同坐标系的点。每图最多展示 50000 个点，较大的地图抽样绘制；完整地图仍在原始 `.osa` 中。当前展示前镜头地图，不提供稠密表面重建或后镜头地图显示。更新前已经启动的服务需要重启，再刷新页面。

## 视频加载与兼容播放

查看器优先使用单独缓存的浏览器预览视频，原始建图视频保持不变。预览最大 720 像素宽、码率约 1.5 Mbps，保留鱼眼视野、帧率和视频时间轴。首次查看新录像时在后台生成，期间仍能看原视频或兼容画面；准备好后自动切换并保持当前时间和播放状态，之后再次打开可直接播放。

首帧同样持久缓存，不必每次启动 FFmpeg。查看器缓存默认在 `~/.cache/umi-view/`（设置 `XDG_CACHE_HOME` 时跟随该目录），不增加录像结果目录中的文件；可用 `UMI_VIEW_CACHE` 更换位置。清理缓存后会重新生成。

部分浏览器无法原生播放结果中的视频编码或像素格式，例如可配置的 HEVC / yuv444p。查看器会自动切换“兼容模式”，也可以点击视频下方的“兼容播放”。服务器用项目已有的 FFmpeg 解码 JPEG 画面；视频画面和三维位姿按同一个轨迹点更新。

兼容模式的画面帧率由服务器解码速度决定，会低于原生视频；播放时跳过来不及显示的中间画面，暂停、逐帧和拖动后会显示所选轨迹点对应的画面。最近读取过的画面会在内存复用，不生成整段抽帧目录，不改变轨迹数据。手动点击“兼容播放”后会保持该模式，重新选择录像可恢复自动选择。

如服务在更新前已经启动，需要在原终端按 Ctrl+C，然后重新运行 `./umi-view`，并刷新浏览器页面。如果提示找不到 FFmpeg，先安装项目的轨迹组件，或把系统 `ffmpeg` 加入 PATH。缺少视频文件本身时仍只能独立查看三维轨迹。

## 数据约定

支持新的 `details/` 布局、旧 `diagnostics/` 布局和历史平铺布局；不修改轨迹、设备档案或原始录像。

- 必须有 `traj_tcp.txt`，每行 `t x y z qx qy qz qw`；跳过注释，检查有限数值、递增时间和四元数。
- 相机／IMU 轨迹可选，时间戳必须与 TCP 对齐。
- `frames.csv` 提供约束类型、处理后视频帧号、原片帧号和跟踪状态；字段含义见[结果说明](结果查看与验收.md#detailsframescsv)。缺失或无效的帧显示“未知”。
- 视频优先读取结果根目录的 `front.mp4`。该文件独立于 `debug/`，成功后清理中间数据也能播放；它是前镜头裁切视频，默认 720×720、约 29.97 fps，保留鱼眼畸变；裁切、尺寸、取帧及编码由[视频参数](../config/README.md#视频处理参数)配置。兼容旧 `diagnostics/work/kiwi*/front/front.mp4` 和 `work/` 路径，按摘要里的选中轮次读取。没有保留视频时仍能独立回放轨迹。
- 环境地图来自 ORB 的稀疏三维特征点，不是完整物体模型。TCP 是 CAD 名义几何，地图约束比例不是实际误差。
- 场景任务在同一地图版本内共享坐标；不同地图版本不保证坐标一致。内部逐段结果的原点和水平朝向每段独立。

## 场景任务结果

```text
results/
├── report.txt                 任务总览、预检提醒与左右手轨迹指标
├── episode.json               输入、配置、各手指标、预检、地图引用和资产哈希
├── bimanual.csv               双手共同时间轴（双手任务时）
├── left/
│   ├── traj_tcp.txt           左手 TCP 位姿
│   ├── front.mp4              左手相机的前镜头视频
│   └── details/
│       ├── traj_camera.txt
│       ├── traj_imu.txt
│       └── frames.csv
└── right/                     右手同样布局；单手任务只保留实际使用的一侧
```

`front.mp4` 来自该手相机的原始 INSV。默认输出 720×720、约 29.97 fps；裁切、取帧、尺寸、缩放、编码和音轨由 `config/trajectory.yaml` 的 `video:` 控制，参数和场景覆盖方式见[视频处理参数](../config/README.md#视频处理参数)。画面保留设备标定的鱼眼模型。

先查看唯一的任务 `report.txt`，其中包含左右手指标和预检提醒，再对照各手视频与 `traj_tcp.txt`。场景任务的环境地图在所属场景的 `.umi/maps/versions/<版本>/` 中，任务 `episode.json` 的 `map` 保存相对运行目录的路径与 SHA256。移动数据时保留场景地图与任务之间的目录关系。

新场景结果采用 schema 3，成功后不再生成各手 `report.txt`、`details/summary.json`、`details/run_settings.json` 或独立的 `preflight_report.json`。默认双手结果共 13 个文件（不含夹爪宽度）。历史布局继续支持查看、验收和导出，读取时不改写旧结果。失败现场仍保留独立的 `preflight_report.json`，便于在没有成功清单时排查。

## 轨迹文件格式

TUM 格式，`#` 开头为说明，之后每行一个位姿：

```text
t  x  y  z  qx  qy  qz  qw
```

- **t**：场景结果采用任务时间 `t_episode = t_video + offset`，不强制把各手首行置零；内部逐段结果采用视频时间。常规录制的行频率由 `video.frame_step` 决定，默认约 29.97 行/秒；实际时间以文件为准。
- **x y z**：位置，单位米。
- **qx qy qz qw**：朝向四元数，w 在最后；位姿将该物体坐标系中的点变换到参考系。
- **参考系**：同一场景地图版本内共享米制坐标，Z 轴朝上。不同地图版本不保证原点与水平朝向一致；内部逐段引擎则每段独立建立世界系。
- **TCP**：按本次实际夹爪资产定义；当前 CAD 名义几何未经过独立实物精度核验。自身轴向见 [TCP 坐标系](设备与坐标.md)。
- **相机系**：x 向右、y 向下、z 向前。

## details/frames.csv

设 `k` 为处理后视频的帧序号，`N = video.frame_step`。新结果中的帧号含义如下：

| 字段 | 含义 |
|---|---|
| `row` | 轨迹行号，从 0 开始 |
| `video_frame` | 生成的 `front.mp4` 中的帧号，等于 k |
| `source_video_frame` | 原始 INSV 的帧号，为 N × k；默认 N=2 |
| `t_video_s` | 原片捕获时间，秒 |
| `t_scene_s` | 场景任务时间，等于 `t_video_s + offset`；内部逐段结果不写此列 |
| `front_lens_tracked` | 前镜头定位是否成功，1 或 0 |
| `constraint` | 融合约束来源：场景结果为 `full` / `imu`；内部逐段结果还可出现 `rot` |

`video_frame` 用于从处理后 MP4 取图，`source_video_frame` 用于追溯原始 INSV。历史结果不含后一列时，`video_frame` 可能采用原片帧号，需按该结果的格式版本解释。

## 参数记录与训练图像

场景任务统一使用 `episode.json` 保存运行记录：`inputs.trajectory_parameters.video` 保存视频选项，`arm_results.<手>.frame_geometry` 保存实际裁切、尺寸与派生帧率；`arm_results.<手>` 还保存各手运动指标、融合证据、相机测量及 TCP 外参。共同的场景、同步、TCP 定义和地图引用仅在任务层保存。`preflight` 保存完整录制检查，跳过检查时为 `null`。内部逐段结果的完整配置仍保存在 `details/run_settings.json` 的 `parameters` 中。

训练导出会复制各手 `front.mp4` 到包内 `videos/left.mp4`、`right.mp4`，并在 `samples.npz` 中保存时间对齐的帧索引。训练包可独立读取，无需原始 INSV。导出 `--fps` 调整训练样本时间轴，视频本身维持 `video.frame_step` 对应的帧率。详见[训练数据](训练数据.md)。

## 内部逐段引擎结果

标定 C 验证和开发测试使用内部逐段引擎，其单段输出布局如下：

```text
umi_traj_out/VID_20261003_182246_00_067/
├── traj_tcp.txt           主要结果：夹爪尖轨迹
├── front.mp4              前镜头视频，viewer 直接读取
├── trajectory.png         轨迹预览（绘图成功时生成）
├── report.txt             状态、设备、标定、运动统计和提醒
├── details/
│   ├── traj_camera.txt    相机轨迹，供标定验证和排查
│   ├── traj_imu.txt       IMU 轨迹
│   ├── frames.csv         逐帧对应关系和约束来源
│   ├── run_settings.json  完整配置及资产哈希
│   ├── summary.json       完整结果指标和复用判断信息
│   └── map.json           前镜头轻量地图展示数据（导出成功时）
└── debug/
    ├── logs/              建图、定位和融合日志，默认保留
    ├── dataset/           提取的时间戳与 IMU（按需保留）
    ├── lens_videos/       本段录像共用的镜头视频（按需保留）
    └── reconstruction/    各轮重建中间数据（按需保留）
```

内部逐段结果先看 `report.txt`、`trajectory.png`，使用 `traj_tcp.txt`，配合 `front.mp4` 回看画面。视频是前镜头裁切，默认 720×720、约 29.97 fps，保留鱼眼畸变；实际裁切、尺寸、取帧和编码参数见本次运行记录。`details/` 提供完整结果与配置，`debug/` 用于排查。

新运行成功后默认清理数据集与重建中间文件，根视频、轨迹、辅助结果和日志继续保留。`--keep-work` 保留完整中间数据；失败或中断时也保留。无独立真值的任务录像只报告跟踪和运动统计，不把地图约束比例当作真实误差。

`details/map.json` 保存选中轮次的前镜头稀疏点云、关键帧和展示对齐信息。它独立于被清理的 `.osa`，可直接由 `umi-view` 查看；每图最多展示 50000 点。对齐只用于展示，不改动轨迹或地图，拟合残差不代表真实精度。导出失败只增加提醒，不改变轨迹抽取的成功状态，详细原因见 `debug/logs/map_export_error.log`。

旧 `diagnostics/` 与平铺结果仍能读取；输入匹配而跳过计算时会自动整理为上述目录。整理旧结果只搬迁文件、发布根视频并修复引用，不重新建图、不改变轨迹数值，也不删除已有独有中间数据。

### details/summary.json

**总览**

| 字段 | 意思 |
|---|---|
| `status` | `ok` 或 `failed`；失败时 `reason` 写原因 |
| `tcp_path_length_m`、`tcp_extent_m` | TCP 走过的路程、活动范围（米），用来和你记得的动作大致对一下 |
| `notes` | 自动检查发现的问题（经验规则，不是精度测试） |
| `run_settings` | 相对结果根目录的 `details/run_settings.json` |

**建图**

| 字段 | 意思 |
|---|---|
| `tracking.front_map_build_tracked` | 建图那一趟跟上了多少帧 / 总帧数（`debug/logs/run.txt` 里的 `map: rc=… TRACKED a / b`）。偏低：开头没初始化、中途跟丢另起图 |
| `tries`、`chosen_try` | 重建失败或质量可疑时会重试完整的建图、定位和融合（默认最多 3 次）。`placements` 是融合里地图被摆了几块，大于 1 多半建图时跟丢、atlas 里不止一张图 |

**定位**

| 字段 | 意思 |
|---|---|
| `tracking.relocalization` | 每一张图单独查一遍。只有 `loc_m0` 表示全程一张图；出现 `loc_m1` 就是建图时另起过图，定位对每张图各播一遍 |
| `tracking.front_lens_tracked_fraction` | 定位成功的帧比例（和 `details/frames.csv` 的 `front_lens_tracked` 一致） |

**融合（最终轨迹）**

| 字段 | 意思 |
|---|---|
| `constraint_fraction.full` | 有多少比例的帧最终用地图位置（越高越好；验证过的录像在 0.85–1.0）。定位成功但和 IMU 对不上会变成 `rot`，不是建图数字 |
| `camera_map_chains` | 融合里连续「有地图位置」的段数。1 最好 |
| `longest_stretch_without_map_position_s` | 最长一段没有地图位置、靠 IMU 衔接的时长（秒） |

### debug/logs/：运行日志

默认保留镜头视频准备日志、选中轮次的运行/建图/定位/融合记录，以及各次重试摘要；整段失败时保留完整阶段数据。摘要的失败阶段会区分视频准备、建图、定位、合并定位和 IMU 融合。

| 文件 | 内容 |
|---|---|
| `run.txt` | 建图/定位摘要、工具哈希 |
| `front_map_log.txt` | 建图过程、初始化和新地图事件 |
| `front_loc_frames.csv` | 合并后的逐帧定位状态、位姿和地图来源 |
| `fuse_info.json` | 融合全文，包括 chains、尺度与参数 |
| `fuse.log` | 融合过程日志（源日志存在时保留） |
| `runner_tryN.log` | 各轮阶段摘要、失败阶段与原始日志位置 |

### debug/ 中间数据

新运行仅在 `--keep-work`、失败或中断时保留；迁移旧结果时保留原有独有数据。

| 路径 | 内容 |
|---|---|
| `debug/dataset/mav0/` | 每帧时间与 IMU |
| `debug/lens_videos/front.mp4` | 从原片生成一次的前镜头视频；dual 模式另有 rear.mp4 |
| `debug/reconstruction/try_N/front/front.mp4` | 该轮引用的共享前镜头视频，各轮不会重新裁切原片 |
| `debug/reconstruction/try_N/front/map/map.osa` | 保存的地图 |
| `debug/reconstruction/try_N/front/map/frames.csv` | 建图逐帧状态 |
| `debug/reconstruction/try_N/front/loc_m*/frames.csv` | 对各地图逐帧重定位的结果 |
| `debug/reconstruction/try_N/fuse/state.csv` | 融合内部状态，包括速度与 bias |

根目录 `front.mp4` 独立保留，不依赖这些中间目录。双镜头模式的后镜头视频属于中间数据，可用 `--keep-work` 保留。

### 参数与复用记录

`details/run_settings.json` 的 `parameters` 保存完整有效配置、覆盖来源、代码和引擎身份；TXT 显示配置 ID 和覆盖项。重建参数与提醒规则分别计算指纹，详见 [参数管理](../config/README.md)。新运行的融合脚本来自项目，标定包仅提供测量；双镜头模式的后镜头仍为样例几何。

## 相机标定结果

相机标定看 `calibration_result/report.txt`，机器可读证据在 `run/record.json`（schema 3）。执行 complete 不等于验收通过：PASS/带提醒可安装，FAIL 表示完整证据不达标，INCOMPLETE 表示执行未完成或缺少有效证据。C 只衡量本次共同时间范围内的相机位置误差和尺度，不代表姿态或 TCP 精度；D 残差超限为静止诊断提醒。仅修改门限用 `umi-calib recheck`，不会重算或启用标定；操作见 [标定指南](标定.md)。
