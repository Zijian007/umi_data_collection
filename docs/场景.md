# 场景采集与离线处理

[文档导航](README.md) · [设备与目录](设备与目录.md) · [录制建议](轨迹/录制.md)

按 **场景 → 套件 → 采集批次 → 任务** 组织。场景管理工作环境和共享地图，场景下的套件确定左右手设备及测量版本，批次记录一次采集活动，任务对应一次录制。相机测量仍保存在全局设备资产库。

任务清单可配置人工核验的双手固定时间偏移，采用 `t_episode = t_video + offset`；未配置时保留未经确认的零偏移假设。指令、同步配置与独立 `umi-dataset` 入口见 [训练数据指南](训练数据.md)。当前不自动估计同步或时钟漂移。

## 登记场景与套件

设备先完成标定并手动 `umi-calib install`。以下命令从项目根目录执行，序列号按实际替换。

```bash
./umi-scene init scenes/shelf
./umi-scene kit scenes/shelf kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL
./umi-scene kits scenes/shelf
```

仅左手用 `--left`，仅右手用 `--right`。套件只有一个 `kits/<套件>/kit.yaml`，保存当前左右手设备、标定和夹爪配置。上述命令读取设备当前默认测量并写入此文件，重新登记同名套件会更新它。也可以直接编辑这个 YAML。

## 建立采集批次

```bash
./umi-scene session scenes/shelf --name 20261025_001 --kit kit_001
# 相同硬件用于另一个场景，在该场景登记套件，再建立批次
./umi-scene init scenes/counter
./umi-scene kit scenes/counter kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL
./umi-scene session scenes/counter --name 20261025_001 --kit kit_001
```

套件名在场景内唯一，批次名在套件内唯一；不同套件可以使用相同批次名。相同硬件可以登记到多个场景，引用同一份全局测量，无需重复标定。创建批次只需指定场景、批次名和该场景的套件。程序校验 `kit.yaml` 中的实测资产，把设备配置自动保存到批次的 `session.yaml`；已有批次只读取自己的快照，之后修改套件不影响它。

```yaml
# kits/kit_001/kit.yaml：当前套件配置，命令会自动生成这些测量版本
id: kit_001
description: 左手采集套件
arms:
  left:
    serial: LEFT_SERIAL
    calibration: CALIB_VERSION
    gripper: handheld_v1
    gripper_version: GEOMETRY_VERSION
```

批次默认使用套件全部手；双手套件只采右手时加 `session ... --arms right`。批次不要求地图已经存在，也不要求采完当天就离线处理。

每次任务直接放在批次目录中，例如 `sessions/20261025_001/take_001/`，与 `session.yaml` 同级。任务名不能使用 imports、cache、runs 等内部目录名称。

## 导入原片与任务配对

```bash
./umi-scene ingest /media/sd/this_session \
  --session scenes/shelf/kits/kit_001/sessions/20261025_001 --dry-run
./umi-scene ingest /media/sd/this_session \
  --session scenes/shelf/kits/kit_001/sessions/20261025_001
```

导入目录只放本批次的原片。导入读取 INSV 内部序列号，按套件确定左右手，保留原名并记录 SHA256。按内容去重，重复执行不重复创建已登记任务。其它套件设备会被列为忽略，不参与配对。

单手批次每段录像生成一个任务。双手批次按文件名中的开始时间和实际视频时长筛选，只有双方候选都唯一才自动配对。默认开始时间容差 2 秒、时长差容差 1 秒，见 `config/scene_parameters.yaml`。这些数值只用于配对，不用于修正时间轴。

无法配对或有歧义的原片留在批次原片目录，导入报告列出待确认项。下一次导入会重新考虑未分配原片。不从文件修改时间猜录制时间，不把缺手双手任务降为单手。

需要人工指定配对或操作描述时，使用 `--instruction`：

```bash
./umi-scene episode scenes/shelf/kits/kit_001/sessions/20261025_001 --name take_001 \
  --left /media/sd/LEFT.insv --right /media/sd/RIGHT.insv --instruction '取出商品并放入篮子'
```

可以先只登记其中一手，再用同一任务名补齐另一手。手动补片和自动配对共用写入规则，保留已有任务描述；重复登记同一内容不会改写清单或清除验收。双手批次中确实只录右手的一次任务，必须明确声明：

```bash
./umi-scene episode scenes/shelf/kits/kit_001/sessions/20261025_001 --name take_right \
  --arms right --right /media/sd/RIGHT.insv
```

批量导入单手任务同样使用 `ingest ... --arms right`。预期使用手只能是批次已声明手的非空子集，不能用缺失原片隐式改变预期。

## 离线建图与抽取

```bash
./umi-scene build scenes/shelf --mapping /media/sd/VID_mapping.insv
./umi-scene run scenes/shelf/kits/kit_001/sessions/20261025_001 --dry-run
./umi-scene run scenes/shelf/kits/kit_001/sessions/20261025_001
./umi-scene status scenes/shelf
./umi-view scenes/shelf
```

地图保存到 `scenes/<场景>/maps/versions/<版本号>/`，`maps/current.json` 指向当前版本。
新版本号如 `20261025_153000-65d192ef`：依次为本机建图开始时间、8 位随机标识。输入身份完整保存在 `manifest.json` 的 `inputs` 中，用于复用判断与追溯，不再重复放进目录名。
时间使用运行机器的本地时区；输入未变化时复用原版本，`build --force` 才强制重新构建。已有不带时间或包含输入指纹的地图版本仍可使用，无需改名。

每个地图版本包含 `manifest.json`、`maps/`、`devices/`、展示数据 `map.json` 和摘要 `report.txt`。
建图配置统一保存在清单的 `inputs.definition`，成功导出不保留空日志；有内容的日志和失败现场保留。
成功建图默认清理 `work/`，可用 `--keep-work` 保留。已发布版本不改写，避免改变批次固定的清单哈希。

同一场景的任务与左右手只在 `details/summary.json` 中记录展示地图的相对路径和 SHA256，直接读取该版本的 `map.json`，不再各存地图副本。单独打开原位置的任务或结果目录也可查看共享地图；移动数据时应携带场景地图并保留相对目录结构。

`shared_front`：一张共享前地图，任务相机在已有地图中定位。建图可以只使用一只手。日常建图使用 `--mapping <原片>`，该原片不限制后续任务的左右手身份。旧 `--mapping-left` 或 `--mapping-right` 单独使用仍可兼容；两段同时提供、混用新旧接口或提供不用的后镜头配置会报错。

`dual`：左右前地图加共享后地图；建图需要两只手的参考录像和对应实测后镜头标定。前后地图放置、尺度和重力在建图阶段验收并冻结；双镜头设备与手的对应关系必须匹配固定地图。

```bash
./umi-scene build scenes/shelf --mode dual \
  --mapping-left /media/LEFT_mapping.insv --mapping-right /media/RIGHT_mapping.insv \
  --rear-left /measurements/LEFT_rear.json --rear-right /measurements/RIGHT_rear.json
```

`run` 首次实际处理将当前地图版本与清单哈希固定到批次，之后发布新地图不改变该批次。需要切换时显式传 `--map-version <已发布版本>`，重新处理与验收；不同地图版本不保证坐标一致。

任务只定位已有地图，再融合各自 IMU，输出固定场景系的 TCP 轨迹。场景算法与独立 `umi-traj` 的区别见 [原理](轨迹/原理.md)。

```bash
# 批量处理所有场景；默认逐任务执行
./umi-scene run scenes --jobs 2
./umi-scene status scenes --json
```

并行数按 CPU、内存设置。成功结果按输入和算法指纹复用；准备数据和定位结果分阶段缓存，融合失败重试可复用定位。失败记录在独立运行目录，已有 `results` 成功入口保留。`--dry-run` 只读，不创建运行、锁、缓存或报告。

## 录制检查与验收

```bash
./umi-scene preflight scenes/shelf/kits/kit_001/sessions/20261025_001/take_001 --json
```

处理前检查原片模式、IMU 有效性与时间覆盖、时长、开头静止和曝光。检查规则及完整参数写入 `preflight_report.json`，没有固定的耗时保证。

| 状态 | 含义 |
|---|---|
| PASS | 本项满足已实现规则 |
| WARN | 建议改善，例如开头不够静止；继续处理 |
| FAIL | 明确不满足规则；阻止本次处理 |
| UNKNOWN | 所需信息缺失，例如原片没有可用曝光信息 |

静止窗口用于改善惯性初始化，不要求任务录像必须有大幅运动；独立的地图尺度恢复仍要求足够可观测运动。检查通过不代表轨迹已达到某个绝对精度。`--skip-preflight` 仅用于排障，不替代人工验收。

处理完成后查看 `results/report.txt`，结合视频、地图与轨迹做人工验收：

```bash
./umi-scene review scenes/shelf/kits/kit_001/sessions/20261025_001/take_001 \
  --accept --reviewer reviewer_001
./umi-scene export scenes/shelf/kits/kit_001/sessions/20261025_001/take_001 \
  --out exports/dataset_001
```

拒绝用 `--reject --reason '原因'`。验收绑定具体成功结果；换输入、重算出新结果或新尝试失败后，需要重新确认。导出要求所有选择任务都是当前有效且人工接受的结果，已有导出目录拒绝覆盖。默认导出 TCP、报告、元数据和双手表，可加 `--with-video`。导出清单保留各任务地图坐标 ID，不把不同地图版本当成同一坐标。

## 已有验证与边界

模拟商超样例使用历史实验室单相机录像；新组织流程已实际处理 1041 帧、约 34.7 秒。套件更新与批次快照、跨场景、单手/双手、漏片补齐、失败重试和验收导出由自动化测试覆盖。尚无真实双机新采数据完成物理回归，也没有独立真值支撑的绝对精度结论。
