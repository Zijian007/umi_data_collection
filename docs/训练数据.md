# 训练数据准备与导出

已有场景轨迹后，按本页补充任务指令、核验双手同步，再重新处理、验收并导出训练中间包。安装沿用[日常指南](安装与日常使用.md)，无需安装 wholebody 或 LeRobot。

输出包含视频、由相机轨迹和所选夹爪几何换算的 TCP 位姿、指令、质量信息及已配置的视觉夹爪宽度。当前 kit_001 的 TCP 几何仍为 CAD 名义值，不能据此声称已核验实物 TCP 精度；中间包也不伪造关节角、头部图像或机器人控制指令。

| 目标 | 必需条件 |
|---|---|
| 导出可检查的训练中间包 | 当前有效且已验收的结果、非空指令、双手同步确认、可识别的 TCP 定义 |
| 通过基础通道 training_ready 检查 | 上述条件，以及所需手已配置宽度标定、导出宽度样本全部有效 |

无宽度标定仍可导出中间包，`training_ready` 为 false。需要宽度通道时，在第 3 步重跑前完成[宽度标定接入](#夹爪宽度标定与接入)。

## 1. 填写任务指令

按 take 放好原片，在 `<任务>/task.yaml` 中填写指令；首次运行前或运行后均可：

```yaml
instruction: 双手拿起盒子，放到托盘上
```

`task.yaml` 仅填写 `instruction`、可选的 `expected_arms` 和 `synchronization`。原片路径、序列号和哈希由程序写入批次 `.umi/tasks/<任务>/episode.yaml`，无需手动编辑。

指令原文保存在 `task.yaml`，处理后进入结果 `episode.json`，成果打包和训练导出都会携带。普通轨迹处理允许为空；训练导出拒绝空白指令。

更新指令会使旧结果和验收失效。按下文重新处理、验收；已有地图无需重建。

## 2. 核验双手同步

双手默认零偏移是未经确认的假设，需要人工核验；单手任务无需跨相机同步确认。旧清单内的人工选项在迁移时自动提取到 `task.yaml`。

双手任务编辑 `<任务>/task.yaml`，保留已有的 `expected_arms` 覆盖，配置如下：

```yaml
instruction: 双手拿起盒子，放到托盘上
synchronization:
  offsets_s:
    left: 0.0
    right: -0.120
  confirmed: true
  note: "同一事件：左视频2.000s，右视频2.120s；录像末尾已再次核对"
```

时间规则为 **`t_episode = t_video + offset`**，单位秒。双手以左视频为参考，左偏移必须是 0。示例中 `2.120 - 0.120 = 2.000`，同一事件落到同一任务时间。仅右手任务则以右视频为参考，偏移为 0。

`confirmed` 表示人工确认，`note` 记录核验依据；程序不会将填入一个偏移自动当作同步通过。应在录像前后分别核对共同事件。若偏差随时间变化，固定偏移不足以修正，保持 `confirmed: false`，不要导出用于训练。当前不估计时钟漂移，也不自动从音频或视觉求同步。

跨相机偏移只用于任务公共时间轴，不改变单相机的 IMU 求解时钟，不叠加到相机–IMU 标定时差。

## 3. 重新处理、查看和验收

```bash
./umi-scene run scenes/shelf/20261105_001/take_001
./umi-view scenes/shelf
./umi-scene review scenes/shelf/20261105_001/take_001 \
  --accept --reviewer operator
```

核对报告中的指令、偏移与确认依据，查看左右视频与轨迹。同步配置改变后，旧验收不能沿用。没有共同时间区间时处理拒绝。

## 4. 导出中间包

```bash
./umi-scene export --format training scenes/shelf/20261105_001 \
  --fps 30 --out datasets/umi_shelf_v1
```

也可以指定一个任务、批次或场景目录，或多个路径。顶层套件目录只保存配置，不包含任务。所有选中任务都必须满足条件：当前成功结果有效、已人工接受、指令非空、双手同步已确认、TCP 定义可识别。任一任务不满足则整次导出失败，不悄悄跳过。输出目录必须不存在，且不能放入源场景内部；失败不会发布部分结果。

`--fps` 是样本时间轴频率；视频保持已有编码与帧率，通过索引关联样本。默认 `--max-gap-s 0.25`：不跨越更大的轨迹时间缺口插值，缺口两侧分配不同 `segment_id`。没有足够样本、视频无法解码、帧索引越界或图像时间误差过大时拒绝导出。

```text
datasets/umi_shelf_v1/
├── manifest.json
├── export_report.json
└── episodes/<场景>/<批次>/<任务>/
    ├── episode.json
    ├── samples.npz
    └── videos/
        ├── left.mp4
        └── right.mp4
```

单手任务只包含实际使用的手。视频和样本都在包内，无需原始 INSV、场景目录或设备注册表。包内源输入身份仅用于追溯，不作为读取时依赖。

## 夹爪宽度标定与接入

如果只需要两枚标签中心的三维实际距离，可在 kit 的 `gripper` 中设置 `tag_distance: tag_distance.json`，并在该 JSON 填写 `{"tag_sizes_mm":{"0":6.0,"1":6.0}}`（分别替换为两枚黑色外框实测边长，单位 mm）。此模式不需要下述像素—毫米 anchors；详细几何和质量检查见[标签中心三维间距](../software/gripper_width/README.md#标签中心三维间距)。

结果写入 `trajectory.csv` 的 `tag_distance_mm`、`tag_distance_valid`、`tag_distance_source`，查看器随视频显示。它表示中心间距，闭合时也可以大于零；不生成 `width_mm`、`close_01` 或 `closed`。轨迹交付包保留这些字段；训练包当前的夹爪开合通道仍使用下面的实测开口关系。

原片需要能看到指尖的 `DICT_4X4_50` ArUco ID 0、1。程序从原始 INSV 的工作镜头半幅检测标记中心距离，再通过对应安装的像素—毫米锚点换算。像素距离使用原片分辨率，不能从缩小后的 front.mp4 测量。相机、夹爪、标记或安装变化后需要重新核验；几何开口不代表抓住物体或接触力。

### 从录像读取像素距离

固定相机、夹爪和标签安装，将夹爪依次保持在闭合及几个已知开口，用卡尺或量块确定两指接触面的间距，并记下每一档对应的录像时间。

```bash
./umi-calib preview-width /path/to/width.insv
# 自定义输出位置
./umi-calib preview-width /path/to/width.insv --out /path/to/width_preview.mp4
# 固定范围：先裁剪再检测，仍输出完整工作镜头预览
./umi-calib preview-width /path/to/width.insv --roi 600 980 1350 1250
```

默认在原片旁生成 `<原片名>_width_preview.mp4`，已有输出会提示选择新路径。它只需要原始 3840×1920 INSV，无需相机登记、宽度 JSON 或 Basalt。

视频逐帧显示标签定位框与 ID、两个中心的连线、原片时间和中心像素距离。只有 ID 0、1 各唯一出现时才显示数值；标签缺失或重复时显示 N/A。预览为 960×960 H.264，距离按原始 1920×1920 工作镜头半幅计算；读取画面上的数值，不在缩小视频上另量像素。

程序会自动确定标签活动区域，在区域内逐帧解码，每 30 帧全图重定位；标签移出区域时，可能短暂显示 N/A，最多等待 29 帧重新定位。缺失目标会做同帧锐化及候选区域 2～3 倍放大补检；无需指定 ROI，距离始终换回原始像素。小尺寸、欠曝、模糊或遮挡的标签仍可能漏检。录制时给夹爪标签补充均匀照明，保证黑白格清晰；可适当增大标签或调整安装角度，安装变化后重新核验锚点。活动区域参考前序有效观测，但预览不使用前帧位置或插值距离代替本帧测量，N/A 表示该帧无法得到唯一的双标签测量。

暂停各个稳定开口时间段，记录稳定的像素距离，与实测毫米数配成 anchors。闭合时 mm 为 0，但标签中心像素距离通常仍大于 0。预览用于观察测量，不会自动推断实际毫米开口或写入套件。

无窗口检测时，指定固定范围，默认按视频时间以 30 Hz 采样，同时输出 CSV 和叠加 MP4：

```bash
./umi-calib detect-width /path/to/width.insv --roi 600 980 1350 1250
# 保存结果，摘要和进度仍输出到终端
./umi-calib detect-width /path/to/width.insv --roi 600 980 1350 1250 --hz 30 --out width.csv
# 自定义视频路径（CSV 的 --out 含义不变）
./umi-calib detect-width /path/to/width.insv --roi 600 980 1350 1250 --video-out width_detect.mp4
# 不按原速等待，测量包含视频编码的处理频率
./umi-calib detect-width /path/to/width.insv --roi 600 980 1350 1250 --benchmark --out benchmark.csv
# 只需 CSV 时关闭视频编码
./umi-calib detect-width /path/to/width.insv --roi 600 980 1350 1250 --no-video
```

默认在原片旁保存 `<原片名>_width_detect.mp4`，不覆盖已有文件；可用 `--video-out` 指定新路径，或用 `--no-video` 关闭保存。视频显示完整工作镜头半幅、绿色标签框与 ID、黄色中心连线及原始像素距离、蓝色 ROI 框；缺失或重复 ID 时显示 N/A。视频帧与 CSV 采样一一对应，保留原片时间间隔，落后丢样时不加速播放。

此入口先裁剪原始 YUV，再转换 ROI 灰度并检测；显示视频单独缩小至 960×960。快速路径只做原图与同帧锐化，使用针对小标签的阈值和解码采样设置，无需额外参数；补检以较低阈值常量保留暗格子边缘，同时省去最小窗口以控制噪声开销。跳过耗时的候选放大补检，并用最小像素周长限制排除微小噪声。识别覆盖和角点估计可能与完整模式的 `preview-width` 不同，正式测量锚点需对照相同处理方式核验。

暗光可以尝试 `--contrast 2`：在检测前将 ROI 灰度对比度提高到 2 倍，输出 MP4 的相同区域也会提亮，画面标注增益。默认值 1 不增强；原始 INSV 不修改。先从 2 倍开始，过大的增益会放大噪声并使亮部饱和，增强不能恢复欠曝或模糊已经丢失的格子信息。

```bash
./umi-calib detect-width /path/to/width.insv --roi 500 980 1550 1250 --hz 30 --contrast 2 --video-out width_contrast2.mp4
```

`preview-width` 同样支持 `--contrast 2`。增强模式的检测结果可能与未增强时不同，应对照定位框和实际标签检查。它不向采集套件或场景流程写入参数。

CSV 含原片时间、两个标签的原始半幅中心坐标、像素距离及裁剪/转换/检测耗时；缺失或重复 ID 的测量留空。默认按原速输出，处理落后时跳过过期采样，不积压旧结果；`--benchmark` 不等待且不丢弃计划采样。摘要输出实际采样频率、覆盖数量及耗时，30 Hz 是目标频率，能否持续达到需以当前原片和机器实测为准。CSV 不覆盖已有文件，不替代场景宽度结果。

两个入口的 ROI 均为 `LEFT TOP RIGHT BOTTOM`，表示原始 1920×1920 工作镜头半幅内的左上、右下坐标，右下角不是宽高。原点位于工作镜头半幅左上角，不加 INSV 拼接画面的 1920 像素偏移；若参考 960×960 预览取坐标，需乘 2。指定 ROI 后始终只检测此区域，不自动扩展或全图重定位；区域内需完整包含两个标签及周围空白。`detect-width` 必须提供 ROI，MP4 预览未指定 ROI 时仍自动确定活动区域。

### 保存并引用实测关系

宽度测量直接和套件放在一起：

```text
kits/kit_001/
├── kit.yaml
├── tcp_camera.json
├── left_width.json
└── right_width.json
```

每个 JSON 保存该手当前安装的实测对应关系。以下数值只说明格式，不可直接用于实物：

```json
{
  "anchors": [{"x": 200.0, "mm": 0.0}, {"x": 400.0, "mm": 100.0}]
}
```

x 是两标记中心距离（像素），mm 是实际开口（毫米）。至少两个锚点，两列严格递增，首个开口为 0。最大锚点定义归一化开口范围。锚点需来自当前安装的实测关系，配置文件只保存锚点。已有 mapping.anchors 格式也可直接读取。

在 kit.yaml 对应手中引用相对文件路径，保留其他设备字段：

```yaml
arms:
  left:
    serial: LEFT_SERIAL
    calibration: '002'
    gripper:
      tcp: tcp_camera.json
      width: left_width.json
  right:
    serial: RIGHT_SERIAL
    calibration: '002'
    gripper:
      tcp: tcp_camera.json
      width: right_width.json
```

文件路径相对 kit.yaml，需指向套件目录内的 JSON。只配置一侧也可以，另一侧只处理轨迹；未配置时不会自动寻找宽度文件。直接运行 run，无需安装或登记宽度版本。

处理策略位于 config/scene_parameters.yaml，也可在 scene.yaml 的 parameters 中覆盖：

```yaml
parameters:
  gripper_width_max_gap_s: 0.2
  gripper_width_closed_threshold_mm: 3.0
  gripper_width_diagnostics: false
```

max_gap_s 指宽度缺口两端的最大间隔，0 表示不填补；闭合阈值单位为毫米，需小于标定最大开口。它们分别通过上述带 gripper_width_ 前缀的配置项控制。原测量文件含 max_gap_s / closed_threshold_mm 时，将其移到这里并删除 JSON 中的旧字段。

修改锚点、闭合阈值、插值策略或任务同步后，重跑只需复用缓存的原始像素检测，再进行换算和对齐；更换原片或检测器才重新检测。已有地图继续复用。任务 episode.json 的 gripper_width.<手> 是宽度报告的唯一记录，保存规范化测量、源文件哈希和覆盖率；历史运行保留原快照，更新后重新查看和验收。

随后照常 `run`、查看、验收和导出，默认结果为：

```text
results/
├── episode.json                 gripper_width 中保存各手测量与报告
└── <手>/trajectory.csv           同一行保存时间、TCP 位姿、宽度和开合量
```

排障时设 gripper_width_diagnostics: true，额外生成 `<手>/details/gripper_width_frames.csv`，记录原片时间、标记像素距离、换算宽度和超范围标记；普通成果导出会一并携带已生成的诊断 CSV。

仅在 kit 配置了 `gripper.width` 时，`trajectory.csv` 才生成宽度测量列；只测标签中心距时不生成这些列，训练导出仍如实标记缺少开口通道。宽度相关列为 `t_video_s`、`t_episode_s`、`width_mm`、`close_01`、`closed`、`valid` 和 `source`。`close_01 = 1 - width_mm / open_width_mm`，0 为全开、1 为闭合。漏检与长缺口的宽度、开合量和闭合状态都留空，不能当作 0 mm。超出最大锚点不作为有效样本；短缺口插值单独标为 interpolated。表中同时保存 TCP 的 `x,y,z,qx,qy,qz,qw`；位置单位为米，宽度单位为毫米。宽度时间沿用 `t_episode = t_video + offset`，与 TCP 使用相同任务时间。原片短缺口填补与训练导出的 --max-gap-s 分属两个阶段，后者限制训练采样时的时间插值。

## 导出字段与时间约定

格式标识为 `umi_training_dataset`，新导出 `schema_version: 2`，读取器兼容不含宽度的版本 1。`manifest.json` 登记任务和文件哈希，任务 `episode.json` 保存指令、同步、参考坐标、TCP 定义、资产身份、人工验收与各数组的形状/类型。

| `samples.npz` 字段 | 含义 |
|---|---|
| `t_episode_s` | 共同任务时间轴，秒；不强制把第一样本置零 |
| `segment_id` | 连续片段编号；未来训练切片不得跨片段 |
| `<arm>_T_scene_tcp` | `[N,4,4]`，TCP → 固定场景的齐次变换，位置为米 |
| `<arm>_video_frame_index` | 对应包内 MP4 的解码帧序号，从 0 开始 |
| `<arm>_video_pts_s` | 被选中视频帧的实际 PTS，秒，便于定位/读取 |
| `<arm>_image_time_s` | 被选帧的捕获时间，经偏移映射到任务时间轴 |
| `<arm>_image_time_error_s` | `image_time_s - t_episode_s`，保留正负号 |
| `<arm>_full_constraint` | 插值两端均具有完整视觉约束；不是物理误差认证 |
| `<arm>_front_tracked` | 插值两端工作镜头均被跟踪 |
| `<arm>_gripper_width_m` | 已配置手的夹爪实际开口，米；缺失为 NaN |
| `<arm>_gripper_close_01` | 归一化开合量，0 开、1 闭；缺失为 NaN |
| `<arm>_gripper_valid` | 宽度样本有效性；禁止忽略该 mask 使用缺失数值 |
| `<arm>_gripper_source` | 0 缺失、1 双标记、2 短缺口插值、3 超标定范围 |

没有配置宽度的手不伪造这些数组。两手都配置不代表自动就绪：导出样本的宽度必须全部有效；否则保留缺失/来源并在 `not_ready_reasons` 中说明。宽度连续插值仅在两端均有效且时间跨度符合约束时进行，不跨无效测量段。

位置线性插值，朝向球面插值，禁止外推；图像使用最近捕获帧。MP4 按 `video.frame_step` 生成定帧率视频，裁切、尺寸与编码由 `config/trajectory.yaml` 的 `video:` 控制，其 PTS 与原始捕获时间分别保留，不将两者混作一个时钟。`frames.csv` 的 `video_frame` 指生成视频中的帧号，`source_video_frame` 指原片帧号。

TCP 按每集实际资产约定保留，不因默认版本变化而静默换轴；训练前需统一各集约定。坐标定义见 [TCP 坐标系](设备与坐标.md)。不同地图坐标不直接拼成同一个绝对参考系；相对动作留给训练切片时计算。

## 独立读取与完整性检查

在安装了本项目 Python 包依赖的环境中：

```python
import json
from pathlib import Path
from software.dataset.export import load_episode

root = Path("datasets/umi_shelf_v1")
manifest = json.loads((root / "manifest.json").read_text())
metadata, arrays = load_episode(root, manifest["episodes"][0]["path"])
print(metadata["instruction"], arrays["t_episode_s"].shape)
```

读取器核对任务登记、路径、文件哈希和数组布局，默认允许检查中间包；宽度 NaN 必须与无效 mask 对应。训练调用应设置 `require_training_ready=True`，不满足条件会明确报告缺失或无效测量。独立数据包可移动到其他目录再读取。
