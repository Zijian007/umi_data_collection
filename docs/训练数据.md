# UMI 训练数据中间包

`umi-scene` 负责原片、地图、任务处理与验收；`umi-dataset` 只读取当前有效且已验收的结果，准备训练数据。安装沿用 [安装指南](安装.md)，无需安装 wholebody 或 LeRobot。

导出包含视频、实测 TCP、任务指令、质量信息，以及已配置的视觉夹爪宽度。无宽度标定时仍可导出中间包，但标记 `training_ready: false`；宽度已经过实物核验且所有导出样本有效时，基础数据通道才标记为就绪。不生成虚假的夹爪值、关节角、头部图像或控制指令。

## 夹爪宽度标定与接入

原片需要能看到指尖的 `DICT_4X4_50` ArUco ID 0、1。主流程使用 main 引入的双标记算法，从原生前镜头半幅测量标记中心距离，再通过对应安装的像素—毫米锚点换算。相机、夹爪、标记或安装变化后需要重新核验。闭合宽度表示几何开口，不证明抓住物体或接触力。

支持历史 `plateaus.json` 的 `mapping.anchors`，也支持 `apply_width.py` 标定输出的顶层 `anchors`。下面只是字段示例，数值不可直接用于实物：

```json
{
  "mapping": {
    "status": "measured",
    "anchors": [{"x": 200.0, "mm": 0.0}, {"x": 400.0, "mm": 100.0}]
  },
  "verified": false,
  "closed_threshold_mm": 3.0,
  "max_gap_s": 0.2
}
```

锚点必须至少两个，像素和毫米严格递增，首个毫米宽度为 0；最大锚点定义归一化开口范围。`closed_threshold_mm` 默认为历史脚本的 3 mm，应按实物核验；`max_gap_s` 控制可填补缺口两端的最大时间跨度。历史文件没有 `verified` 时默认为 false；只有完成当前安装的实物核验后才将其设为 true，不从历史 status 字符串自动推断通过。

在登记套件时分别提供对应标定，再创建新批次：

```bash
./umi-scene kit scenes/shelf kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL \
  --width-left /data/calibration/left_width.json \
  --width-right /data/calibration/right_width.json
./umi-scene session scenes/shelf --name 20261026_002 --kit kit_001
```

文件复制为不可变资产 `registry/cameras/<serial>/gripper_width/<版本>/width_calibration.json`，绑定该相机和夹爪几何版本；`kit.yaml` 保存 `width_calibration` 版本，批次自动快照。只配置一侧也可以，另一侧不会借用标定。更新套件需再次给出希望保留的宽度标定；旧批次和旧资产不变。标定变化不要求重建地图。

随后照常 `run`、查看、验收和导出。新增各手结果：

```text
results/<手>/
├── gripper_width.csv                  与该手 TCP 行/时间对齐的宽度和开合量
└── details/
    ├── gripper_width.json             标定、输入哈希、检测版本和覆盖率
    └── gripper_width_frames.csv        原片逐帧时间、宽度与超范围标记
```

`gripper_width.csv` 保留 `t_video_s`、`t_episode_s`、`width_mm`、`close_01`、`closed`、`valid` 和 `source`。`close_01 = 1 - width_mm / open_width_mm`，0 为全开、1 为闭合。漏检与长缺口的宽度、开合量和闭合状态都留空，不能当作 0 mm。超出最大锚点不作为有效样本；短缺口插值单独标为 interpolated。宽度时间沿用 `t_episode = t_video + offset`，与 TCP 使用相同任务时间。

## 1. 补充任务指令

新任务可通过 `umi-scene episode --instruction` 登记。已有任务可只更新指令，不必重新传原片：

```bash
./umi-scene episode scenes/shelf/kits/kit_001/sessions/20261025_001 \
  --name take_001 --instruction "双手拿起盒子，放到托盘上"
```

指令原文保存在 `episode.yaml`，处理后进入结果 `episode.json`，成果打包和训练导出都会携带。普通轨迹处理允许为空；训练导出拒绝空白指令。

更新指令会使旧结果和验收失效。按下文重新处理、验收；已有地图无需重建。

## 2. 核验双手同步

新建任务使用 schema 5；旧 schema 4 仍可处理，但双手零偏移只是一项未经确认的假设。单手任务无需跨相机同步确认。

双手任务直接编辑 `<任务>/episode.yaml`，保留原 `session`、`recordings` 和 `expected_arms`，配置如下：

```yaml
schema_version: 5
instruction: 双手拿起盒子，放到托盘上
# session、recordings、expected_arms 沿用已有内容
synchronization:
  offsets_s:
    left: 0.0
    right: -0.120
  confirmed: true
  note: "同一事件：左视频2.000s，右视频2.120s；录像末尾已再次核对"
```

时间规则为 **`t_episode = t_video + offset`**，单位秒。双手以左视频为参考，左偏移必须是 0。示例中 `2.120 - 0.120 = 2.000`，同一事件落到同一任务时间。仅右手任务则以右视频为参考，偏移为 0。

`confirmed` 表示人工确认，`note` 记录核验依据；程序不会将填入一个偏移自动当作同步通过。应在录像前后分别核对共同事件。若偏差随时间变化，固定偏移不足以修正，保持 `confirmed: false`，不要导出用于训练。当前不估计时钟漂移，也不自动从音频或视觉求同步。

跨相机偏移只用于任务公共时间轴，不改变单相机的 IMU 求解时钟，不叠加到相机–IMU 标定时差。

## 3. 重新处理、查看和验收

```bash
./umi-scene run scenes/shelf/kits/kit_001/sessions/20261025_001/take_001
./umi-view scenes/shelf
./umi-scene review scenes/shelf/kits/kit_001/sessions/20261025_001/take_001 \
  --accept --reviewer operator
```

核对报告中的指令、偏移与确认依据，查看左右视频与轨迹。同步配置改变后，旧验收不能沿用。没有共同时间区间时处理拒绝。

## 4. 导出中间包

```bash
./umi-dataset build scenes/shelf/kits/kit_001/sessions/20261025_001 \
  --fps 30 --out datasets/umi_shelf_v1
```

也可以指定一个任务、套件或场景目录，或多个路径。所有选中任务都必须满足条件：当前成功结果有效、已人工接受、指令非空、双手同步已确认、TCP 定义可识别。任一任务不满足则整次导出失败，不悄悄跳过。输出目录必须不存在，且不能放入源场景内部；失败不会发布部分结果。

`--fps` 是样本时间轴频率；视频保持已有编码与帧率，通过索引关联样本。默认 `--max-gap-s 0.25`：不跨越更大的轨迹时间缺口插值，缺口两侧分配不同 `segment_id`。没有足够样本、视频无法解码、帧索引越界或图像时间误差过大时拒绝导出。

```text
datasets/umi_shelf_v1/
├── manifest.json
├── export_report.json
└── episodes/<场景>/<套件>/<批次>/<任务>/
    ├── episode.json
    ├── samples.npz
    └── videos/
        ├── left.mp4
        └── right.mp4
```

单手任务只包含实际使用的手。视频和样本都在包内，无需原始 INSV、场景目录或设备注册表。包内源输入身份仅用于追溯，不作为读取时依赖。

## 5. 字段和时间

格式标识为 `umi_training_dataset`，新导出 `schema_version: 2`，读取器兼容不含宽度的版本 1。`manifest.json` 登记任务和文件哈希，任务 `episode.json` 保存指令、同步、参考坐标、TCP 定义、资产身份、人工验收与各数组的形状/类型。

| `samples.npz` 字段 | 含义 |
|---|---|
| `t_episode_s` | 共同任务时间轴，秒；不强制把第一样本置零 |
| `segment_id` | 连续片段编号；未来训练切片不得跨片段 |
| `<arm>_T_scene_tcp` | `[N,4,4]`，TCP → 固定场景的齐次变换，位置为米 |
| `<arm>_video_frame_index` | 对应包内 MP4 的解码帧序号，从 0 开始 |
| `<arm>_video_pts_s` | 被选中视频帧的实际 PTS，秒，便于定位/读取 |
| `<arm>_image_time_s` | 被选帧的捕获时间，经偏移映射到任务时间轴 |
| `<arm>_image_time_error_s` | `image_time_s - t_episode_s`，保留正负号 |
| `<arm>_full_constraint` | 插值两端均具有完整视觉约束；不是物理误差认证 |
| `<arm>_front_tracked` | 插值两端前镜头均被跟踪 |
| `<arm>_gripper_width_m` | 已配置手的夹爪实际开口，米；缺失为 NaN |
| `<arm>_gripper_close_01` | 归一化开合量，0 开、1 闭；缺失为 NaN |
| `<arm>_gripper_valid` | 宽度样本有效性；禁止忽略该 mask 使用缺失数值 |
| `<arm>_gripper_source` | 0 缺失、1 双标记、2 短缺口插值、3 超标定范围 |

没有配置宽度的手不伪造这些数组。两手都配置不代表自动就绪：标定必须 verified，导出样本的宽度必须全部有效；否则保留缺失/来源并在 `not_ready_reasons` 中说明。宽度连续插值仅在两端均有效且时间跨度符合约束时进行，不跨无效测量段。

位置线性插值，朝向球面插值，禁止外推；图像使用最近捕获帧。MP4 是定帧率生成的视频，其 PTS 与原始捕获时间分别保留，不将两者混作一个时钟。`frames.csv` 的 `video_frame` 指生成视频中的帧号，`source_video_frame` 指原片帧号。

TCP 按每集实际资产约定保留，不因默认版本变化而静默换轴；训练前需统一各集约定。坐标定义见 [TCP 坐标系](TCP坐标系.md)。不同地图坐标不直接拼成同一个绝对参考系；相对动作留给训练切片时计算。

## 6. 独立读取和完整性检查

在安装了本项目 Python 包依赖的环境中：

```python
import json
from pathlib import Path
from software.dataset.export import load_episode

root = Path("datasets/umi_shelf_v1")
manifest = json.loads((root / "manifest.json").read_text())
metadata, arrays = load_episode(root, manifest["episodes"][0]["path"])
print(metadata["instruction"], arrays["t_episode_s"].shape)
```

读取器核对任务登记、路径、文件哈希和数组布局，默认允许检查中间包；宽度 NaN 必须与无效 mask 对应。训练调用应设置 `require_training_ready=True`，不满足条件会明确报告缺失、标定未核验或无效测量。独立数据包可移动到其他目录再读取。

`training_ready` 只表示当前导出基础数据通道齐全，宽度已核验且采样有效，不代表已经完成物理 TCP 精度验证、LeRobot 适配或机器人部署。相机缺失视角 mask、相对动作编码和机器人执行解码仍属于训练/部署适配，不由此导出器伪造。
