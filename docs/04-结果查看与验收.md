# 结果查看与验收

本页用于查看结果、记录人工验收和查阅场景任务的输出字段。首次运行步骤见[日常指南](01-安装与日常使用.md)，失败处理见[场景排障](03-场景处理.md#故障排查)。

查看器只接受命令行的结果目录、`--host`、`--port` 和 `--show-config`，不读取算法 YAML。`./umi-view --show-config` 只显示启动配置，不扫描结果、不启动服务器。默认值和范围见[umi-view 参数参考](命令行参数.md#umi-view)，各入口的参数归属见[配置指南](../config/README.md)。

## 打开查看器

同时查看 UMI 的三维轨迹、环境稀疏地图、姿态、工作镜头视频和速度曲线。读取 UMI 自己的结果格式，无需 Node 构建或加载外网资源。

双手任务在同一三维画面显示左右手，配两路同步视频，只回放共同有效时间。

从项目根目录启动：

```bash
./umi-view
```

浏览器打开 **http://127.0.0.1:9092**。默认扫描项目的 `scenes/`，自动打开最新一段成功轨迹。新录像抽取完成后，点击录像库旁的刷新按钮即可。

也可以指定场景、采集批次或单个结果目录：

```bash
./umi-view scenes/shelf
./umi-view scenes/shelf/20261104_001
./umi-view --port 9092
```

`--port` 接受 0–65535，0 表示自动选择空闲端口，以启动后打印的地址为准。各入口都支持从其他工作目录通过软链接启动；传入的相对数据路径仍相对于当前工作目录。

### 界面操作

- 左侧选择录像，或搜索文件名、路径、序列号。
- 左键拖动旋转，右键或 Shift 拖动平移，滚轮缩放；双击或 `R` 复位。
- 顶部切换 TCP、工作镜头光心和 IMU 原点。勾选“叠加其他参考点”可用虚线显示同一设备上其余参考点的轨迹。双手模式下开关显示为“叠加左手其他参考点”，左右手的图例会分别标出当前所选参考点。
- “环境地图”控制稀疏点云显示，下拉框切换工作镜头子地图；“关键帧”显示代表性相机位置与朝向。
- “地图坐标轴”显示所选子地图的 `O_map` 原点及红 X、绿 Y、蓝 Z 轴，标签注明轴长（原始地图单位）。已对齐地图的轴与点云使用同一变换，其原点和方向可以不同于轨迹世界坐标；右下角方向提示会单独注明世界／地图方向。
- “世界坐标轴”显示轨迹世界系的 `O_world` 原点及 XYZ 轴，长度单位为米。海报系的 Z 指入纸面，重力对齐的地图系 Z 朝上。两套轴默认同时显示、分别开关：世界轴用虚线，地图轴用实线，并以 `_world`／`_map` 标签区分。未对齐子地图使用原始地图坐标时，世界轴自动隐藏且开关禁用；切回已对齐地图或隐藏原始地图后恢复。
- 开关坐标轴保持当前旋转、缩放和平移；需要按当前显示内容重新取景时，按 `R`、双击画布或点击“透视”。
- 当前位置的红、绿、蓝姿态轴分别是局部 X、Y、Z，经四元数转换到该录像的世界坐标。
- 空格播放／暂停，左右箭头逐帧；拖时间轴或点击速度图、三维轨迹可定位时间。
- 视频、三维位置、姿态和速度使用同一时间轴；支持倍速和循环。
- 每路画面可选择工作镜头或环境镜头。有环境镜头成片时可直接播放。场景任务只有工作镜头成片时，查看器在首次选择环境镜头时按结果的帧号从原片生成预览并缓存。左右手可独立切换。
- “查看本次记录”显示当前标定、目录、运动范围和诊断摘要。

## 人工验收与导出

先查看每个任务的 `results/report.txt`，对照视频、TCP 轨迹和环境地图检查：实际动作是否一致，是否有跳变或长时间失去视觉约束，双手是否在同一时间范围和地图版本内。

计算成功后需要人工确认；查看器不会自动记录验收。可对批次统一验收，也可只指定一个任务：

```bash
./umi-scene review scenes/shelf/20261105_001 --accept --reviewer operator
./umi-scene review scenes/shelf/20261105_001/take_001 \
  --reject --reviewer operator --reason '轨迹与视频不一致'
```

验收绑定具体成功运行。原片、配置、任务指令或同步变化后，需要重新处理和验收；新尝试失败时不能继续把旧成功结果当作当前有效结果。

普通成果包包含 TCP 轨迹、报告、元数据及双手表，可附带视频。包的根目录用 `manifest.json` 登记任务和文件校验值。

```bash
./umi-scene export scenes/shelf/20261105_001 --with-video --out exports/shelf_20261105
```

导出要求所有选择任务都具有当前有效且人工接受的结果。程序按 `--out` 创建目标目录及缺少的父目录，已有目标目录会报错。训练中间包的指令、同步、宽度与就绪检查见[训练数据](05-训练数据准备与导出.md)。

## 场景任务结果

结果入口是 `<任务>/results/`，指向最近一次成功运行；失败不会替换该入口。最新状态仍需结合处理报告或 `umi-scene status` 判断。

```text
results/
├── report.txt                  人工验收摘要
└── data/
    ├── episode.json            输入、同步、坐标、质量摘要和文件校验值
    ├── bimanual.csv             双手共同时间轴（双手任务时）
    ├── left/
    │   ├── trajectory.csv       左手 TCP 位姿及已配置的夹爪测量
    │   └── front.mp4            左手工作镜头视频
    └── right/                   单手任务只发布实际使用的一侧
```

海报坐标结果使用 schema 6，查看器、人工验收和导出兼容已有 schema 4/5。先读 `report.txt`，再用查看器对照各手视频和轨迹。每手轨迹表按配置提供夹爪测量列，标签中心距使用 `tag_distance_*`，配置开口标定后才提供宽度列。[夹爪测量字段](05-训练数据准备与导出.md#夹爪宽度标定与接入)

工作镜头视频默认输出 720×720、约 29.97 fps，并保留鱼眼图像。裁切、取帧、尺寸、缩放、编码和音轨由 `config/algorithms/trajectory.yaml` 的 `video:` 控制。[视频处理参数](../config/README.md#视频处理参数)

地图位于所属批次的 `.pipeline/maps/versions/<版本>/`。清单 `data/episode.json` 的 `map` 保存相对内部运行目录的路径与 SHA256。移动现场数据时保留批次的目录关系。

直接打开任务目录的 `run.log` 查看最近一次进入重建或被任务预检拒绝的日志。实际重建开始时更新该入口。在批次目录执行 `tail -F take_001/run.log` 可以跟踪该任务的进度。失败原因会写入日志，复用结果时沿用已有日志。

完整的运行审计位于 `<批次>/.pipeline/tasks/<任务>/logs/<run-id>/`，其中的 `events.jsonl` 保存逐行结构化事件，`run_manifest.json` 记录状态、UTC 起止时间、耗时、输入指纹、结果指针和日志文件清单。`run_manifest.run_directory` 指向同一任务的 `runs/<run-id>/` 或 `runs/failed-<hash>/` 现场。完整融合证据和缓存审计位于内部运行目录的 `diagnostics.json`，逐帧证据位于 `<手>/details/frames.csv`，冻结设备资产位于 `devices/`。自动后端的尝试记录位于 `reconstruction_attempts/`，预检拒绝的现场包含 `preflight_report.json`。

## 离线轨迹质量评估

终端和 `umi-scene run --json` 使用同一份质量摘要。已发布结果的质量来源是 `data/episode.json` 中各手的 `arm_results`。摘要描述内部质量证据，精度结论需要独立真值。每只手包含：

- `rows`、`duration_s`、`path_length_m`：轨迹规模、时长和 TCP 路程；
- `visual_constraint_fraction`、`imu_constraint_fraction`：逐帧主要约束来源比例；
- `longest_visual_gap_s`：最长连续无视觉区间；
- `visual_consistency_rms_m`：视觉与融合结果的一致性内部指标；
- `environment_poster_status`：环境海报是否参与、未观测或被拒绝；
- `accuracy: not_measured`：系统没有把这些内部指标冒充真实误差。

运行期间，终端会在每个 take 的轨迹抽取前显示同步策略；`audio_auto` 会继续显示 `sync.json` 是复用还是重新估计、各手 `offsets_s` 和音频峰值比。进度写到标准错误，批量 `--json` 摘要写到标准输出，因此可以分别保存：

```bash
./umi-scene run scenes/<场景>/<批次> --json > run-summary.json 2> run-progress.log
```

`--json` 的每个 take 条目也包含 `synchronization`，可以直接检查最终应用的偏移；完整原始音频证据仍以任务 `sync.json` 为准。例如只查看每个 take 的状态、同步偏移和每只手的视觉约束比例：

```bash
./umi-scene run scenes/<场景>/<批次> --json > run-summary.json
jq '.[] | {name, status, offsets_s: (.synchronization.offsets_s // {}), quality: (.quality.arms // {})}' run-summary.json
```

人工验收可对照 `report.txt` 和查看器。批量统计使用 `--json` 输出的 `quality`，需要逐帧证据时读取内部运行目录的 `<手>/details/frames.csv`。

## 轨迹文件格式

每手的 `trajectory.csv` 保存时间、TCP 位姿及已配置的测量。只配置夹爪标签中心距时：

```csv
row,t_video_s,t_episode_s,x,y,z,qx,qy,qz,qw,tag_distance_mm,tag_distance_valid,tag_distance_source
```

- **row**：行号，从 0 开始，与该手生成视频的帧和 `details/frames.csv` 对应。
- **t_video_s / t_episode_s**：原片时间和任务时间，单位秒，`t_episode_s = t_video_s + offset`，不强制把各手首行置零。默认约 29.97 行/秒，由 `video.frame_step` 决定；实际时间以文件为准。
- **tag_distance_mm / tag_distance_valid / tag_distance_source**：两枚夹爪标签中心的三维距离（毫米）、有效性和来源；无效距离留空。
- **width_mm**：仅配置开口标定时生成，表示夹爪实际开口（毫米）；漏检长缺口或超标定范围时留空。
- **close_01 / closed**：仅配置开口标定时生成，表示归一化闭合量（0 全开、1 闭合）和按阈值判断的闭合状态。无有效宽度时留空。
- **valid / source**：仅配置开口标定时生成，仅描述宽度的有效性和来源；来源为 `two_tags`、`interpolated`、`missing` 或 `out_of_range`，不代表 TCP 跟踪质量。
- **x y z**：位置，单位米。
- **qx qy qz qw**：朝向四元数，w 在最后；位姿将该物体坐标系中的点变换到参考系。
- **参考系**：以 `scene.scope` 判断输出参考系。`task_poster` 使用海报布局轴；地图定位的海报结果还保存 `scene.T_board_scene`，查看器用它同步转换点云和关键帧。地图坐标结果在同一地图版本内共享米制坐标，Z 轴朝上。不同地图版本不保证原点与水平朝向一致；内部逐段引擎则每段独立建立世界系。
- **TCP**：按本次实际夹爪资产定义；当前 CAD 名义几何未经过独立实物精度核验。自身轴向见 [TCP 坐标系](principles/设备与坐标.md)。
- **相机系**：x 向右、y 向下、z 向前。

TCP 轴向和参考系保存在 `episode.json`。每手的 `trajectory.csv` 保存 TCP 位姿与已配置的夹爪宽度，查看器可用 TCP 和固定外参按需重建相机和 IMU 的显示轨迹。排障时在 `--expert-config` 文件的 `parameters.diagnostics` 下设置 `export_auxiliary_trajectories: true`，程序会在内部运行目录的 `<手>/details/` 写入 `traj_camera.txt` 和 `traj_imu.txt`。这两个文件与内部逐段引擎的轨迹都使用 TUM 格式 `t x y z qx qy qz qw`。

## details/frames.csv

设 `k` 为处理后视频的帧序号，`N = video.frame_step`。新结果中的帧号含义如下：

| 字段 | 含义 |
|---|---|
| `row` | 轨迹行号，从 0 开始 |
| `video_frame` | 生成的 `front.mp4` 中的帧号，等于 k |
| `source_video_frame` | 原始 INSV 的帧号，为 N × k；默认 N=2 |
| `t_video_s` | 原片捕获时间，秒 |
| `t_episode_s` | 场景任务时间，等于 `t_video_s + offset`，与 `trajectory.csv`、`bimanual.csv` 同名同义 |
| `front_lens_tracked` | 工作镜头定位是否成功，1 或 0 |
| `constraint` | 融合约束来源：场景结果为 `full` / `imu`；内部逐段结果还可出现 `rot` |

`video_frame` 用于从处理后 MP4 取图，`source_video_frame` 用于追溯原始 INSV。

## 参数记录与训练图像

场景任务统一使用 `episode.json` 保存运行记录。`inputs.trajectory_parameters.video` 保存视频选项，`arm_results.<手>.frame_geometry` 保存实际裁切、尺寸与派生帧率。`arm_results.<手>` 还保存各手运动指标、融合证据、相机测量及 TCP 外参。场景坐标记录在 `scene.frame_id`，批次名记录在 `session`。同步、TCP 定义和地图引用也在任务层保存。`code_revision` 用于追溯代码版本，地图与同步使用内容摘要参与复用。标签间距报告保存在 `tag_distance.<手>`。`preflight` 保存完整录制检查，跳过检查时为 `null`。内部逐段结果的完整配置位于 `details/run_settings.json` 的 `parameters` 中。

训练导出会复制各手 `front.mp4` 到包内 `videos/left.mp4`、`right.mp4`，并在 `samples.npz` 中保存时间对齐的帧索引。训练包可独立读取，无需原始 INSV。训练导出配置的 `fps` 调整样本时间轴，视频本身维持 `video.frame_step` 对应的帧率。详见[训练数据](05-训练数据准备与导出.md)。

## 环境地图

地图异步加载，轨迹和视频先显示。场景任务通过任务 episode.json 的 map 引用读取批次 `.pipeline/maps/versions/<版本>/map.json`，左右手共用；内部逐段引擎的结果才单独保存 `details/map.json`。逐段结果若仅保留选中轮次的 `map.osa`，查看器会按需转换。若地图已清理且没有轻量地图产物，界面会提示，仍可独立查看轨迹。

图集转换结果会持久缓存，重启查看器后直接复用；地图、轨迹或转换实现变化时自动重新准备。

可靠对齐的地图叠加在米制轨迹上，并显示用于展示的拟合残差。它表示地图与融合轨迹的一致性，不是独立真值误差。静止、近直线运动、对应点不足或拟合残差过大时，子地图按原始地图单位单独显示，隐藏轨迹叠加；时间轴、视频和下方轨迹位姿读数仍可使用。

每张子地图独立选择，不混合不同坐标系的点。每图最多展示 50000 个点，较大的地图抽样绘制；完整地图仍在原始 `.osa` 中。当前展示工作镜头地图，不提供稠密表面重建或环境镜头地图显示。更新前已经启动的服务需要重启，再刷新页面。

## 视频加载与兼容播放

查看器优先使用单独缓存的浏览器预览视频，原始建图视频保持不变。预览最大 720 像素宽、码率约 1.5 Mbps，保留鱼眼视野、帧率和视频时间轴。首次查看新录像时在后台生成，期间仍能看原视频或兼容画面；准备好后自动切换并保持当前时间和播放状态，之后再次打开可直接播放。

首帧同样持久缓存，不必每次启动 FFmpeg。查看器缓存默认在 `~/.cache/umi-view/`（设置 `XDG_CACHE_HOME` 时跟随该目录），不增加录像结果目录中的文件；可用 `UMI_VIEW_CACHE` 更换位置。清理缓存后会重新生成。

部分浏览器无法原生播放结果中的视频编码或像素格式，例如可配置的 HEVC / yuv444p。查看器会自动切换“兼容模式”，也可以点击视频下方的“兼容播放”。服务器用项目已有的 FFmpeg 解码 JPEG 画面；视频画面和三维位姿按同一个轨迹点更新。

兼容模式的画面帧率由服务器解码速度决定，会低于原生视频；播放时跳过来不及显示的中间画面，暂停、逐帧和拖动后会显示所选轨迹点对应的画面。最近读取过的画面会在内存复用，不生成整段抽帧目录，不改变轨迹数据。手动点击“兼容播放”后会保持该模式，重新选择录像可恢复自动选择。

如服务在更新前已经启动，需要在原终端按 Ctrl+C，然后重新运行 `./umi-view`，并刷新浏览器页面。如果提示找不到 FFmpeg，先安装项目的轨迹组件，或把系统 `ffmpeg` 加入 PATH。缺少视频文件本身时仍只能独立查看三维轨迹。

## 远程访问与运行环境

默认监听本机；如果查看器运行在实验室服务器、浏览器在另一台电脑，可用 SSH 转发：

```bash
ssh -L 9092:127.0.0.1:9092 zijianwang@lab1
```

然后在电脑上打开 http://127.0.0.1:9092。也可以显式使用 `--host 0.0.0.0`，通过服务器 IP 访问。

`umi-view` 的 HTTP 服务使用 Python 标准库，采集清单读取依赖 ruamel.yaml，无需在服务进程加载 SLAM 或惯性融合环境。图集转换自动调用项目 `.deps/env/bin/python` 与已安装的 ORB 地图导出器；自定义依赖目录时设置 `UMI_DEPS`，或将 `UMI_PY` 指向对应环境的 Python。`UMI_VIEW_PYTHON` 仍可指定服务器使用的 Python。

## 当前结果格式与其他流程

查看器读取当前发布布局：场景任务使用 `episode.json` 与每手的 `trajectory.csv`，独立轨迹使用 `details/summary.json`、`details/traj_camera.txt`、`details/traj_imu.txt` 和根目录 `traj_tcp.txt`。缺少视频或轻量地图时，对应视图不可用。

标定 C 验证和开发使用的内部逐段引擎输出、日志与中间数据见[轨迹模块输出参考](../umi/workflows/segment/README.md#输出)。相机标定的报告与验收结论见[标定结果说明](02-相机与夹爪标定.md#53-看结果)。
