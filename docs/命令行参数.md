## 使用约定

以下命令在项目根目录执行。`<路径>`、`<目录>` 等尖括号内容需要替换成实际值；包含空格的路径用引号括起。命令行相对路径从当前工作目录解析，查看器省略目录时固定使用本项目的 `scenes/`。

三个入口及其所有子命令都接受 `-h` / `--help`：显示帮助后退出。`umi-scene`、`umi-calib` 的选项放在对应子命令后面，顶层帮助只列子命令。表中无取值的开关默认关闭；标为“必填”的选项和位置参数没有默认值。

```bash
./umi-view --help
./umi-scene --help
./umi-scene run --help
./umi-calib --help
./umi-calib run --help
```

安装依赖后即可使用上述入口；`umi-scene` 和 `umi-calib` 的启动脚本需要 `.deps/env.sh`。查看器无子命令；另外两个入口必须选择子命令才能执行工作。

## umi-view

```text
./umi-view [数据目录] [--host 地址] [--port 端口] [--show-config]
```

| 参数 | 默认值 / 必填 | 含义与范围 |
|---|---|---|
| `数据目录` | 本项目 `scenes/` | 场景、批次、任务目录或单个结果目录；扫描其中可查看的数据 |
| `--host 地址` | `viewer.yaml` 的 `host`，初始 `127.0.0.1` | HTTP 监听地址；`0.0.0.0` 监听所有 IPv4 网卡，其他电脑使用服务器实际 IP 访问 |
| `--port 端口` | `viewer.yaml` 的 `port`，初始 `9092` | 整数 `0–65535`；`0` 自动选择空闲端口，以终端打印的地址为准 |
| `--show-config` | 关闭 | 输出启动配置 JSON 后退出，不扫描目录或监听端口 |

启动后按终端地址打开浏览器，`Ctrl+C` 停止服务。查看器不接受算法 `--config`；默认值读取 `config/viewer.yaml`，机器覆盖用 `config/viewer.local.yaml`，CLI 优先。运行/检测配置与缓存规则见 [配置说明](../config/README.md#运行与查看器默认值)。

```bash
./umi-view
./umi-view scenes/test_shelf --port 9092
./umi-view scenes/test_shelf --host 0.0.0.0 --port 9092
./umi-view --port 0 --show-config
```

## umi-scene

| 子命令 | 用途 |
|---|---|
| `check` | 检查轨迹处理环境；除帮助外没有参数 |
| `build` | 从一个批次的 `mapping/` 单独构建地图 |
| `run` | 登记原片、固定或构建批次地图、抽取任务轨迹 |
| `preflight` | 检查一段原片或一个任务的完整性 |
| `detect-tags` | 独立检测环境镜头海报并生成报告 |
| `status` | 查看处理与验收状态 |
| `review` | 人工接收或拒收当前结果 |
| `export` | 导出有效且已人工接收的结果 |
| `clean` | 删除已被取代的运行、地图版本和中断残留；可选清空缓存 |
| `inspect` | 查看批次当前绑定的地图信息 |

### build / run

```text
./umi-scene build <批次> [选项]
./umi-scene run <路径> [更多路径 ...] [选项]
```

| 位置参数 | 接受的输入 |
|---|---|
| `build` 的 `批次` | 一个批次目录、`batch.yaml` 或批次 `.pipeline/manifest.yaml`；需要该批次 `mapping/` 的建图原片 |
| `run` 的 `路径` | 一个或多个场景、批次、任务目录，或 `scene.yaml`、`batch.yaml`、`task.yaml`、批次 `.pipeline/manifest.yaml`、批次 `.pipeline/tasks/<任务>/episode.yaml`；上层目录可发现多个批次 |

两者共同接受：

| 选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--config 文件` | 无本次覆盖 | YAML 顶层只接受 `trajectory` / `parameters`；覆盖顺序为项目默认值 → `scene.yaml` → 此文件；设备与测量资产仍由 kit / batch 声明 |
| `--show-config` | 关闭 | 输出算法、运行/检测配置、逐项来源及实际 CPU/线程预算 JSON 后退出；读取配置，不检查原片或执行处理，优先于 `--dry-run` |
| `--intrinsics-source 来源` | 按 kit 的前后镜头选择；默认 front measured、rear factory | 临时把两镜头统一为 `measured` 或 `factory`，覆盖 batch 和 kit；正常使用在 kit 的 `intrinsics.front/rear` 分别选择 |
| `--cores CPU列表` | 不额外限制 | 限制算法子进程的 CPU 范围，例如 `0-7` 或 `0-3,8`；填写当前系统可用的 CPU 编号 |
| `--dry-run` | 关闭 | 检查输入并输出计划；不创建清单、锁、地图、缓存或结果 |
| `--force` | 关闭 | **build** 强制构建新地图版本并保留已有版本；**run** 忽略任务最终结果复用，生成新结果，中间准备/定位缓存仍可复用 |

仅 `build` 接受：

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--keep-work` | 关闭 | 成功后保留建图中间文件；默认成功清理，失败现场保留 |

仅 `run` 接受：

| 选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--jobs N` / `-j N` | `1` | 同时处理的任务数，正整数；仅 `jobs=1`、任务为双手且达到 `runtime.arm_min_cpus` 每手预算（默认共 8 核）时，在任务内拆分核心并行处理两手 |
| `--skip-preflight` | 关闭 | 排障时跳过任务原片预检；批次入库阶段的配对、设备与可读性检查仍执行 |
| `--map-version 版本` | 使用本批次地图 | 显式复用同一场景的指定版本，校验后冻结到当前批次；不会自动选择其他批次地图 |
| `--json` | 关闭 | 输出批量结果 JSON；默认输出终端汇总表；`--show-config` 本身总是输出 JSON |

批次存在无法读取、设备不匹配或待配对/待补齐原片时，该批次整批停止；其他批次仍可处理。`run --force` 不等于强制重新建图，需要新地图时使用 `build --force`。`build` 的结果直接输出 JSON，无须 `--json`。

```bash
./umi-scene run scenes/test_shelf/20261109_002 --show-config
./umi-scene run scenes/test_shelf/20261109_002 --dry-run
./umi-scene run scenes --jobs 2 --json
./umi-scene build scenes/test_shelf/20261109_002 --keep-work
```

### preflight

```text
./umi-scene preflight <目标> [--json]
```

`目标` 必填：原始 `.insv`、已登记任务目录或内部 `episode.yaml`。默认显示检查报告，`--json` 改为 JSON；不启动重建。检查未通过时退出码为 `1`。

### detect-tags

```text
./umi-scene detect-tags <video> --out <目录> [选项]
```

| 参数 | 默认值 / 必填 | 含义与范围 |
|---|---|---|
| `video` | 必填 | X3 原始 3840×1920、4K60 视频 |
| `--out 目录` | 必填 | 独立检测缓存和报告目录；默认复用匹配缓存 |
| `--layout 文件` | 项目内已核对 PDF 的 77 标签布局 | 海报布局 JSON，声明字典、ID、几何及黑边格数 |
| `--border-bits N` | 读取布局，默认海报为 `1` | 正整数，用于核对黑边格数，必须与布局一致 |
| `--frame-step N` | `2` | 每 N 个源帧检测一次，正整数 |
| `--minimum-side-px 像素` | `0` | 几何可用观测的最短投影边长，原片像素单位，有限非负数；`0` 不按尺寸过滤 |
| `--force` | 关闭 | 重新计算检测，不复用已有角点缓存 |

命令输出 JSON 报告，不改变任务轨迹；这些参数只作用于本次独立检测。

### status / review / export

这三个命令均接受一个或多个任务、批次、场景或套件目录。

```text
./umi-scene status <路径> [更多路径 ...] [--json]
./umi-scene review <路径> [更多路径 ...] (--accept | --reject) --reviewer <验收人> [--reason <说明>]
./umi-scene export <路径> [更多路径 ...] --out <目录> [选项]
```

`status` 默认逐条显示状态，`--json` 输出 JSON。尚未登记的原片可先用 `run --dry-run` 检查；`status` 按已有任务清单汇总。

`review` 的参数：

| 参数 | 默认值 / 必填 | 含义 |
|---|---|---|
| `--accept` / `--reject` | 必选一个，互斥 | 将当前结果标记为人工接收或拒收；接收要求当前成功结果仍有效 |
| `--reviewer 名称` | 必填 | 验收人姓名或标识，写入验收记录 |
| `--reason 说明` | 空字符串 | 验收说明或拒收原因 |

`review` 输出 JSON；批量结果应查看 `failed` 与 `details`，不能仅以退出码判断每项是否验收成功。

`export` 的参数：

| 参数 | 默认值 / 必填 | 含义与范围 |
|---|---|---|
| `--out 目录` | 必填 | 导出目录，已有目录拒绝覆盖 |
| `--format 格式` | `trajectory` | `trajectory` 为轨迹交付包；`training` 为训练中间包 |
| `--with-video` | 关闭 | 仅 `trajectory`：一并复制工作镜头视频；`training` 自动包含视频，与此开关同时使用会报错 |
| `--fps Hz` | `30` | 仅 `training`：目标采样帧率，有限数值且在 `(0, 120]` Hz；`trajectory` 忽略此项 |
| `--max-gap-s 秒` | `0.25` | 仅 `training`：最大插值间隔，有限正秒数；`trajectory` 忽略此项 |

导出结果输出 JSON。训练包的指令、同步和开合通道要求见[训练数据](训练数据.md)。

```bash
./umi-scene status scenes/test_shelf --json
./umi-scene review scenes/test_shelf/20261109_002 --accept --reviewer zijian
./umi-scene export scenes/test_shelf/20261109_002 --out exports/shelf --with-video
./umi-scene export scenes/test_shelf/20261109_002 --out datasets/shelf --format training --fps 30
```

### clean

```text
./umi-scene clean <路径> [更多路径 ...] [--cache] [--dry-run]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `路径` | 必填 | 批次、场景或上层目录；按其中的 `batch.yaml` 发现批次 |
| `--cache` | 关闭 | 同时清空任务与建图的全部可重建缓存；下次运行会重新解码、建图和定位 |
| `--dry-run` | 关闭 | 只列出将删除的内容和可释放空间，不做修改 |

保留规则与 `run`、`build` 成功后的自动清理相同：任务保留 `results`（或 `local_results`）指向的运行、最近一次尝试和验收记录的运行；地图保留 `manifest.yaml` 绑定、保留运行引用的版本和最新一次建图。正在运行的任务或建图会被跳过。输出 JSON 列出删除项和约释放空间（与结果共享硬链接的视频不计入）。

```bash
./umi-scene clean scenes/test_shelf --dry-run
./umi-scene clean scenes/test_shelf/20261109_008 --cache
```

### inspect

```text
./umi-scene inspect <批次目录、batch.yaml 或批次 .pipeline/manifest.yaml>
```

一个必填位置参数，无额外选项。输出批次 `manifest.yaml` 当前绑定地图的目录、名称、版本、坐标系与地图信息 JSON。

## umi-calib

| 子命令 | 用途 |
|---|---|
| `run` | 从 front / rear 的 A/B/C/D 录像求解并验收相机标定 |
| `verify` | 用 C 段录像复查已有工作镜头标定 |
| `recheck` | 用当前验收规则重新评估已有完整报告 |
| `install` | 自动识别并登记 front/rear 标定，更新该来源的当前选择 |
| `devices` | 只读查看各镜头的当前参数及套件来源选择 |
| `retire` | 停用一台相机 |
| `preview-width` | 生成标签检测与像素距离叠加 MP4 |
| `detect-width` | 按视频时间采样，输出像素距离 CSV 和可选 MP4 |
| `check` | 检查标定组件和板布局；除帮助外没有参数 |

### run / verify

```text
./umi-calib run <front或rear目录> [选项]
./umi-calib verify <C段录像> [选项]
```

`run` 的目录末级名称必须为 `front` 或 `rear`，据此选择工作镜头或环境镜头。目录中放 A/B/C/D 子目录各一段 INSV，或直接放四段按文件名排序对应 A/B/C/D 的 INSV；两种布局不能混用。rear 求解需要该设备已有工作镜头标定。`verify` 通过 C 录像的设备身份读取已有工作镜头标定，不生成或启用新参数。

共同参数：

| 选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--out 目录` | run：输入目录下 `calibration_result`；factory 为 `calibration_result_factory`。verify：录像旁 `<录像名>_calibration_verification` | 本次结果目录；“录像名”不含扩展名。已有非空目录的处理见 `--resume` / `--force` |
| `--tag-size-mm 毫米` | `24` | AprilGrid 单个标签黑色外框的实测边长，不含白边；有限正毫米数。不是夹爪标签尺寸；夹爪标签配置在 kit 的 `gripper.tag_distance` 引用文件 |
| `--config 文件` | `config/calibration.yaml` | 本次标定算法/验收 YAML 覆盖；C 验证自动使用本次板尺寸。覆盖格式见[配置指南](../config/README.md) |
| `--show-config` | 关闭 | 输出算法、运行/检测配置、逐项来源及实际 CPU/线程预算 JSON 后退出，不检查录像或准备求解环境；优先于 `--dry-run`，位置参数及执行选项仍须合法 |
| `--cores CPU列表` | 不额外限制 | 限制本进程及子进程的可用 CPU，例如 `0-7` 或 `0-3,8` |
| `--workers N` | 按 `runtime.yaml`：初始为可用 CPU 减 1，至少 `1`、最多 `24` | 图像准备与板检测线程预算，正整数；显式值受可用 CPU 数限制（包含 `--cores` 限制）；run 转 bag 的线程上限由 `runtime.calibration_bag_threads` 配置，默认 4 |
| `--resume` | 关闭 | 校验并复用有效阶段，从失败或中断处继续；与 `--force` 互斥 |
| `--keep-work` | 关闭 | 成功后保留中间文件；失败或中断默认保留，便于继续运行 |
| `--force` | 关闭 | 清空所选结果目录后重算，包括未显式提供 `--out` 时的默认结果目录；与 `--resume` 互斥 |
| `--dry-run` | 关闭 | 检查输入和生效参数，不创建结果或运行求解 |

仅 `run` 接受：

| 选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--intrinsics-source 来源` | `measured` | `measured`：A 求实测内参；`factory`：使用 B 原片对应镜头的工厂 MEI 拟合 KB4，A 只验证；两者都重新求 B 并验收 C/D |
| `--compare-sample` | 关闭 | 仅 front：额外用项目样例标定跑 C 段作对照；rear 使用此项会报错 |
| `--install` | 关闭 | 验收通过后自动按序列号登记相应镜头标定；默认只生成结果，随后手动执行 install |

```bash
./umi-calib run /path/to/front --tag-size-mm 24 --show-config
./umi-calib run /path/to/front --tag-size-mm 24 --dry-run
./umi-calib run /path/to/front --tag-size-mm 24 --resume --workers 8
./umi-calib run /path/to/rear --tag-size-mm 24 --intrinsics-source factory
./umi-calib verify /path/to/C.insv --tag-size-mm 24
```

### recheck / install

```text
./umi-calib recheck <完整结果目录> [--config 文件]
./umi-calib install <front/rear结果目录或rear_calibration.json> [--serial 序列号] [--force]
```

| 命令 / 参数 | 含义 |
|---|---|
| `recheck` 的位置参数 | 必填，已有完整标定结果目录；更新验收结论和报告，不重新求解 |
| `recheck --config 文件` | 可选验收规则覆盖；省略时按当前默认规则。计算参数发生变化会拒绝，需要重新运行 |
| `install` 的位置参数 | 必填，完整 front/rear 标定结果目录；rear 目录需包含 `rear_calibration.json`，也可直接传该文件；默认要求验收通过；安装成功更新对应镜头和来源的当前参数 |
| `install --serial 序列号` | 可选，核对测量所属设备身份，不能借此改写序列号 |
| `install --force` | 默认关闭；允许完整有效结果的质量拒绝，仍校验身份与证据，不能安装 `INCOMPLETE`。它不表示清空结果目录 |

### devices / retire

```text
./umi-calib devices [--kit 套件名] [--json] [--intrinsics-source 来源] [--require-rear]
./umi-calib retire <完整序列号>
```

`devices` 的参数：

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--kit 套件名` | 查看设备档案 | 检查指定套件的前后镜头来源及当前参数，例如 `kit_002` |
| `--json` | 关闭 | 输出机器可读的检查报告；默认终端报告 |
| `--intrinsics-source 来源` | 套件声明的来源 | 临时统一检查两镜头的 `measured` / `factory` 来源，必须同时指定 `--kit` |
| `--require-rear` | 关闭 | 必须同时指定 `--kit`；要求已独立验收的 rear，工厂推导不算 |

`devices` 默认只列每个镜头、每种来源的一份当前参数；历史身份仍可在结果记录中追溯。安装成功即更新对应的当前选择，无需手动激活版本。

`retire` 的完整序列号必填，无额外选项，用于停用设备。设备身份和当前来源可先用 `devices` 查询。

### preview-width / detect-width

```text
./umi-calib preview-width <video> [--out MP4] [--roi LEFT TOP RIGHT BOTTOM] [--contrast 倍数]
./umi-calib detect-width <video> [--out CSV] [--roi LEFT TOP RIGHT BOTTOM] [--contrast 倍数]
                         [--hz Hz] [--video-out MP4 | --no-video] [--benchmark]
```

两者的 `video` 都必填，为 X3 原始 3840×1920 INSV；显示/输出原始像素距离，不需要毫米标定。

| 共同选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--roi LEFT TOP RIGHT BOTTOM` | `600 980 1350 1250` | 四个整数，工作镜头原始 1920×1920 半幅坐标；左上原点，必须满足 `0 ≤ LEFT < RIGHT ≤ 1920`、`0 ≤ TOP < BOTTOM ≤ 1920`；先裁剪再检测 |
| `--contrast 倍数` | `1` | 检测区域灰度增益，有限数值且 ≥1；暗光可试 `2`，叠加预览同步增强 |

仅 `preview-width` 的输出选项：

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--out MP4` | 原片旁 `<原名>_width_preview.mp4` | 逐帧预览 MP4，已有文件拒绝覆盖；完成后向标准输出打印 JSON 摘要 |

`detect-width` 的其他选项：

| 选项 | 默认值 | 含义与范围 |
|---|---|---|
| `--hz Hz` | `30` | 视频时间上的采样频率，有限正数；按原片时间戳选帧，不补帧 |
| `--out CSV` | 标准输出 | 保存 `.csv`；已有文件拒绝覆盖 |
| `--video-out MP4` | 原片旁 `<原名>_width_detect.mp4` | 保存叠加 MP4；已有文件拒绝覆盖，与 `--no-video` 互斥 |
| `--no-video` | 关闭 | 只输出 CSV，关闭 MP4 编码 |
| `--benchmark` | 关闭 | 不按原速等待，测量包含解码的最大处理频率；仍按 `--hz` 采样 |

“原名”不含扩展名。`detect-width` 默认按原速运行，处理落后时会跳过采样帧；JSON 汇总写入标准错误，不混入标准输出 CSV。这些选项只影响本次独立诊断，正式任务测量参数在 kit / 场景配置中设置。

```bash
./umi-calib preview-width recording.insv --contrast 2
./umi-calib detect-width recording.insv --roi 600 980 1350 1250 --out samples.csv --no-video
./umi-calib detect-width recording.insv --hz 30 --no-video --benchmark > samples-benchmark.csv
```

## 同名参数的作用范围

| 参数 | 作用范围 |
|---|---|
| `--show-config` | 仅 view、scene run/build、calib run/verify；只展示配置，不代表输入已能运行 |
| `--dry-run` | scene run/build、calib run/verify 检查输入而不处理 |
| `--config` | scene run/build、calib run/verify/recheck；查看器和独立标签/宽度诊断不接受 |
| `--force` | scene build：新地图；scene run：新任务结果；scene detect-tags：重新检测；calib run/verify：清空结果重算；calib install：覆盖质量拒绝 |
| `--intrinsics-source` | scene run/build 选择已登记整包；calib run 选择求解内参来源；calib devices 只读检查指定套件来源 |
| `--json` | scene run/preflight/status、calib devices；其他子命令按上述各节的固定输出格式处理 |

## 启动环境变量

下列变量在命令前设置，不是 `--选项`。通常保持默认即可。

| 变量 | 入口 / 默认值 | 用途 |
|---|---|---|
| `UMI_DEPS` | 三个入口；项目 `.deps/` | 依赖根目录；scene/calib 从所选目录读取 `env.sh`，该文件也需与安装位置匹配 |
| `UMI_PY` | scene/calib；依赖目录 `env/bin/python` | 基础 Python 解释器；calib 正式求解会按需切换到标定环境 |
| `UMI_VIEW_PYTHON` | view；依赖目录 `env/bin/python`，不存在时用 `python3` | 查看器 Python 解释器 |
| `UMI_OPENCV_THREADS` | scene run/build/detect-tags；默认取 `runtime.yaml` 的 `opencv_threads`（初始 `4`） | OpenCV 线程数，正整数；覆盖本机 YAML |
| `UMI_VIEW_CACHE` | view；未设置 | 显式指定查看器缓存目录 |
| `XDG_CACHE_HOME` | view；`~/.cache` | 未设置 `UMI_VIEW_CACHE` 时，使用其下的 `umi-view/` |

```bash
UMI_OPENCV_THREADS=2 ./umi-scene run scenes/test_shelf/20261109_002
UMI_VIEW_CACHE=/tmp/umi-view-cache ./umi-view
```

参数解析定义分别位于 [viewer/server.py](../software/viewer/server.py)、[scene/cli.py](../software/scene/cli.py)、[calibration/cli.py](../software/calibration/cli.py)。维护参数时同步更新本页和对应 `--help`。
