# 命令行参数参考

从项目根目录运行。所有入口和子命令支持 `-h` / `--help`。日常步骤见[安装与日常使用](01-安装与日常使用.md)。

## umi-view

`./umi-view [数据目录] [--host 地址] [--port 端口] [--show-config]`

| 参数 | 用途 |
|---|---|
| `数据目录` | 场景、批次、任务或结果目录，默认项目的 `scenes/` |
| `--host 地址` | 监听地址，默认 `127.0.0.1`。可传 `0.0.0.0` 监听所有 IPv4 网卡 |
| `--port 端口` | 默认 `9092`，范围 0–65535，`0` 自动选端口 |
| `--show-config` | 打印生效配置后退出 |

本机查看器设置可写在 `config/operations/viewer.local.yaml`。启动后用浏览器打开终端显示的地址。

## umi-scene

| 命令 | 日常选项 |
|---|---|
| `run <路径> [更多路径…]` | `--dry-run` 查看计划，`--json` 输出批量结果，`--recompute` 重算任务 |
| `status <路径> [更多路径…]` | `--json` 输出 `batches` 和 `tasks`，包括地图和验收状态 |
| `review <路径> [更多路径…]` | 选 `--accept` 或 `--reject`，必填 `--reviewer 名称`，可填 `--reason 说明` |
| `export <路径> [更多路径…]` | 必填 `--out 目录`，见下文的导出格式 |

### build / run

给 `run` 传场景、批次或任务目录。内部清单文件也可作为现有自动化的输入。程序自动登记原片、选择地图计划、预检、同步和抽轨迹。已有地图和任务结果会按当前输入检查是否可复用。需要多地图时，优先读取已有计划并合并 Organizer 交接中的新增条目，也可根据原片起草计划。有歧义的批次会停止并报告具体原因。

`run --recompute` 跳过运行前的解码、定位和检测缓存并重算任务。本次新建缓存和有效的音频同步记录仍可复用，已构建地图继续使用。单独建图用 `./umi-scene build <批次>`，使用同一套地图规划规则。单地图批次的 `build --recompute` 会生成新地图版本。多地图批次构建待建的 epoch，已绑定的版本继续保留。可加 `--dry-run` 查看计划，或加 `--keep-work` 保留建图中间文件。

日常 CPU 和任务并发设置在 [config/user.yaml](../config/user.yaml)。单次排障时用 `./umi-scene run --help` 或 `./umi-scene build --help` 查看 `--cores`、`--jobs`、`--expert-config`、`--show-config` 和 `--skip-preflight` 的适用范围。`--show-config` 优先于 `--dry-run`。

### status / review / export

`status`、`review` 和 `export` 接受一个或多个任务、批次、场景或套件路径。批量验收的 JSON 报告包含 `failed` 与 `details`，可用来确认每项处理结果。

| 导出选项 | 用途 |
|---|---|
| `--format trajectory` | 默认，导出已接收的轨迹，可用 `--with-video` 同时复制工作镜头视频 |
| `--format training` | 导出训练中间包，包含对齐样本和视频 |
| `--profile 文件.yaml` | 仅训练包。可选字段为 `fps`、`max_gap_s`、`quality_policy`、`unknown_support`，默认值见[配置范例](../config/training_export.example.yaml)。生效值记录在包的 `manifest.json` |
| `--start-s 秒` / `--end-s 秒` | 仅训练包。须成对指定人工确认的任务窗口 |

导出目录必须不存在。训练专属参数要求 `--format training`，训练包已经包含视频。

```bash
./umi-scene export scenes/shelf --out exports/shelf --with-video
./umi-scene export scenes/shelf --format training --out datasets/shelf \
  --profile config/training_export.example.yaml
```

### 场景维护与诊断

| 命令 | 用途 |
|---|---|
| `check` | 检查轨迹依赖与设备档案 |
| `build <批次>` | 单独建图，自动识别多地图计划 |
| `detect-tags <INSV> --out <目录>` | 诊断海报角点。可用 `--layout JSON`、`--frame-step N`（默认 2）、`--full-frame-every N`（默认 15 个采样帧）、`--minimum-side-px N`（默认 0）、`--recompute`。黑边格数从布局读取 |
| `clean <路径>` | 清理过时运行和地图。用 `--dry-run` 预览，`--cache` 同时清理可重建缓存 |
| `evaluate-relative <任务或冻结结果>` | 用必填的 `--reference JSON` 和 `--out JSON` 评估双手相对位姿。报告须写到源运行目录外 |

#### clean

`./umi-scene clean <批次或场景> --dry-run` 会列出待删除的过期运行、过期地图和中断残留，以及预计可释放空间。当前、最近尝试和已验收结果受保留规则保护。去掉 `--dry-run` 执行清理。

## umi-calib

| 命令 | 日常选项 |
|---|---|
| `run <front或rear目录>` | `--tag-size-mm 毫米`、`--out 目录`、`--dry-run`、`--recompute` |
| `verify <C段录像>` | 与 `run` 同选项。使用当前登记的工作镜头标定复测 |
| `install <完整结果目录>` | 安装已通过验收的结果。rear 也接受结果目录里的 `rear_calibration.json` |
| `devices` | `--kit 套件名`、`--json`、`--require-rear`。要求独立 rear 标定时须同时给 `--kit` |

`run` 要求 A/B/C/D 子目录各一段 INSV，或直接放四段按文件名排序的 INSV。`--tag-size-mm` 是实测 AprilGrid 标签黑框边长，默认 24 mm。

`--out` 指定结果目录基名。首次求解默认写入 `calibration_result`，工厂内参用 `calibration_result_factory`。`verify` 默认写到原片旁的 `<录像名>_calibration_verification`。重复执行原命令时，程序检查最新版本的输入、配置和已有证据。可续跑时复用有效阶段，已完成且证据有效时直接返回。输入或配置变化、结果格式不兼容或指定 `--recompute` 时，使用同级的 `_v002`、`_v003` 等版本目录。以终端打印的结果目录读取报告并执行 `install`。

`--dry-run` 输出拟用目录和操作，`action` 为 `new`、`resume` 或 `reuse`，不创建结果。每次显式传入 `--recompute` 都会启动新版本。续跑刚中断的重算时，去掉 `--recompute`。单次线程和算法覆盖用 `./umi-calib run --help` 或 `./umi-calib verify --help` 查看。

### 标定维护与诊断

| 命令 | 用途 |
|---|---|
| `check` | 检查标定依赖和 AprilGrid 布局 |
| `recheck <完整结果目录>` | 使用已有测量重新验收，可用 `--expert-config YAML` 覆盖验收规则 |
| `retire <序列号>` | 停用相机 |
| `preview-width <INSV>` | 逐帧生成夹爪测量叠加 MP4。支持 `--out MP4`、`--roi LEFT TOP RIGHT BOTTOM`、`--contrast 倍数` |
| `detect-width <INSV>` | 快速采样夹爪像素宽度。另有 `--hz Hz`（默认 30）、`--out CSV`、`--video-out MP4` 或 `--no-video`、`--benchmark`，也支持相同的 ROI 和对比度选项 |

`./umi-calib install --allow-rejected` 仅允许覆盖证据完整的质量拒绝，仍核对身份和证据。`--serial 序列号` 可额外核对设备。夹爪宽度操作见[训练数据准备与导出](05-训练数据准备与导出.md#夹爪宽度标定与接入)。

## 兼容与启动环境

旧版 `--force` 对标定求解和复测是 `--recompute` 的别名，结果按新规则保留。安装时旧 `--force` 对应 `--allow-rejected`。标定 `--resume` 仍接受，自动续跑同样适用。训练导出的旧采样选项仍支持，但一次导出只用一种配置方式。旧建图命令的 `--epochs` 和海报检测的 `--border-bits` 仍可解析。

`UMI_DEPS` 可指定依赖目录，默认项目的 `.deps/`。场景和标定命令用 `UMI_PY` 覆盖解释器，查看器用 `UMI_VIEW_PYTHON`。查看器缓存可用 `UMI_VIEW_CACHE` 定位，默认在 `XDG_CACHE_HOME` 或 `~/.cache` 下的 `umi-view/`。场景执行的 OpenCV 线程可用 `UMI_OPENCV_THREADS` 临时覆盖。
