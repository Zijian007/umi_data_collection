# 设备、录像目录与标定选择

[文档导航](README.md) · [标定操作](标定/说明.md) · [轨迹抽取](轨迹/使用.md)

## 录像怎么放

推荐每台相机使用完整序列号作为一级目录，标定批次与任务分开：

```text
recordings/
└── IAQEB26097M4CP/
    ├── calib_20261022/
    │   ├── A/原始文件名.insv
    │   ├── B/原始文件名.insv
    │   ├── C/原始文件名.insv
    │   ├── D/原始文件名.insv
    │   └── umi_calib_out/        标定完成后生成
    └── tasks/
        └── 20261023/
            ├── 原始文件名.insv
            └── umi_traj_out/     轨迹抽取后生成
```

目录名用于整理数据；**设备身份来自 INSV 内部序列号**。已有 `recordings/M4CP/` 这样的简称目录可以继续使用。文件名也不用于判断设备，建议保留相机原始命名，便于追溯。

标定目录推荐 A/B/C/D 子目录各放一个 `.insv`；也兼容四个视频平铺后按文件名排序。不要混合两种布局。轨迹命令只处理输入目录直接包含的 `.insv`，不会递归进入日期子目录；请传入具体日期目录或单个视频。同一次批处理不能有同名录像。

## 标定结果存在哪里

标定运行结果保存在批次的 `umi_calib_out/`，默认不改变设备档案。检查报告后执行：

```bash
./umi-calib install recordings/IAQEB26097M4CP/calib_20261022/umi_calib_out
./umi-calib devices
```

`install` 使用报告中的序列号，将最终包复制到 `registry/cameras/<序列号>/bundle/`，更新 `registry/index.json` 中的标定、夹爪和哈希记录，并刷新报告中的启用状态。再次安装该相机的另一份标定，会替换该相机的默认包；原批次目录仍保留各次标定结果。

夹爪 TCP 几何与遮手图放在 `registry/grippers/<夹爪ID>/`。相机标定与夹爪配置分别管理，`umi-calib` 不求解 TCP 几何。

## 抽取时使用哪份标定

普通运行无需再指定标定路径：

```bash
./umi-traj recordings/IAQEB26097M4CP/tasks/20261023
```

工具读取录像内部序列号，查询设备档案并校验标定与夹爪资产。未登记、已停用或哈希不一致时拒绝处理；旧轨迹存在也不会跳过这项检查。

工程覆盖的优先级如下：

| 优先级 | 来源 | 用途 |
|---|---|---|
| 1 | `UMI_TRAJ_CALIB=<标定包目录>`，或 `factory` | 临时使用指定包或样例，供工程对照 |
| 2 | `--device <完整序列号>` | 显式使用另一条设备档案 |
| 3 | 录像内部序列号 | 日常默认选择 |

`--gripper <ID>` 可覆盖所选设备的夹爪。终端显示实际序列号、标定 ID、夹爪、来源和包目录；轨迹结果的 `details/summary.json` 中 `calibration_used` 保存同类信息，`details/run_settings.json` 记录完整资产和哈希。

停用设备使用 `./umi-calib retire <完整序列号>`。`./umi-calib devices` 显示当前状态；旧报告里的启用状态只代表报告生成时。

新相机标定包仅保存测量 JSON 和来源信息，算法配置独立管理；旧包读取时不会改写。参数文件、运行快照和复用规则见 [参数管理](../config/README.md)。
