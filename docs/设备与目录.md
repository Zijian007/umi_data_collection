# 场景、套件与设备资产

[文档导航](README.md) · [场景命令](场景.md) · [标定操作](标定/说明.md)

采集层次为 **场景 → 套件 → 批次 → 任务**。套件配置归各自场景管理，相机标定和夹爪测量按设备全局保存。相同硬件在不同场景登记时复用实测资产，不复制标定文件。

## 目录

```text
registry/                                   全局设备实测资产
├── index.json
├── cameras/<完整序列号>/
│   ├── calibrations/<版本>/
│   └── gripper_width/<版本>/width_calibration.json
└── grippers/<夹爪ID>/versions/<版本>/

recordings/
├── calibration/<序列号>/<标定批次>/front/
└── scenes/<场景>/
    ├── <套件>/<采集批次>/<序列号>/原始文件名.insv
    └── <建图批次>/mapping/<序列号>/原始文件名.insv

scenes/<场景>/
├── scene.yaml                              场景建图配置
├── maps/                                   本场景各套件共享的地图
│   ├── current.json
│   └── versions/<地图版本>/
└── kits/<套件>/
    ├── kit.yaml                            当前左右设备和测量配置
    └── sessions/<采集批次>/
        ├── session.yaml                    自动保存设备快照、使用手与地图
        ├── imports/                        入库报告
        └── <任务>/
            ├── episode.yaml                原片引用、预期使用手
            ├── state.json                  处理与人工验收状态
            ├── cache/                      可重建缓存
            ├── results -> runs/<运行版本>/  当前成功结果
            └── runs/<运行版本>/              成功产物或失败证据
```

原片以 INSV 内部完整序列号为准，保留原名、内容和 SD 卡源文件。已归档在同场景的录像可直接引用，避免建图和任务重复存储。任务原片按场景、套件、批次、序列号归档。

`state.json` 只保存处理尝试和人工验收记录，检查报告用相对路径引用，身份与使用手从清单读取。状态需与任务清单、成功结果一起保留；`cache/` 是可重建数据。`results` 只在新运行成功后更新，失败不会覆盖旧成功结果。成功运行目录包含 `episode.json`、`report.txt`、`preflight_report.json`、各手 `traj_tcp.txt` 与 `front.mp4`，双手任务另有 `bimanual.csv`。失败目录保存 `failure.json` 等诊断证据，通过原片检查后算法失败也保留本次检查报告。

套件可用 `--width-left` / `--width-right` 固定各手的宽度标定，已有批次不随之改变。配置后，各手新增 `gripper_width.csv` 和检测报告；无标定继续仅处理轨迹。详见 [宽度标定与接入](训练数据.md#夹爪宽度标定与接入)。

场景任务的展示地图只保存在 `maps/versions/<地图版本>/map.json`，每只手的 `details/summary.json` 保存相对路径与内容哈希。任务目录不再包含地图副本，移动场景数据时应保留地图和任务之间的相对结构。

## 身份和版本

| 对象 | 固定内容 | 何时新增 |
|---|---|---|
| 标定版本 | 相机测量、验收与资产哈希 | 重新标定并手动 install |
| 夹爪版本 | TCP、遮手图、测量来源 | 安装几何或夹爪改变 |
| 宽度标定版本 | 对应相机与夹爪安装的像素—毫米锚点、核验状态 | 重新测量或安装变化 |
| 套件配置 | 当前各手序列号、标定、夹爪版本及宽度标定 | 换设备、换手或采用新测量时更新 kit.yaml |
| 批次 | 场景、当时的套件设备快照、预期使用手 | 新采集活动或配置改变 |
| 地图版本 | 米制场景坐标、地图资产 | 显式重新建图 |
| 任务 | 一次操作的原片与预期使用手 | 重新录制一次操作 |

套件可以只有左手或右手。任务允许使用批次所声明手的非空子集，必须显式声明。双手任务缺片保持不完整，不会降为单手。

登记套件时读取当前默认标定和几何，写入唯一的 `kit.yaml`。创建批次时校验测量资产并自动保存设备快照；处理已有批次直接使用其 `session.yaml`，不再读取当前套件配置。更新或移除当前套件配置不改变已有批次，所固定的实际测量仍需保留并通过哈希校验。

批次可在地图不存在时建立，首次实际抽取固定地图版本与清单哈希。显式 `run --map-version` 才切换已有批次的地图。

```bash
./umi-calib install <umi_calib_out目录>
./umi-calib install-rear <rear_calibration.json>
./umi-calib install-gripper handheld_v1 <TCP与遮手图目录>
./umi-calib devices
./umi-calib retire <完整序列号>
```

停用设备不能用于新的套件或批次；历史批次仍可用已固定测量处理与查看。资产哈希始终校验，不退回当前默认值或样例后镜头。

## 命名与跨场景使用

清单由命令生成，实际设备和地图版本由程序固定。

套件 ID 在场景内唯一，批次名在套件内唯一，任务名在批次内唯一。批次推荐 `20261025_001`，任务推荐 `take_001`。相同硬件跨场景使用时，在各场景分别登记套件并分配原片；系统不猜拍摄场景。

[模拟商超样例](../scenes/supermarket_demo/README.md) 保留全部历史原片、标定和轨迹。视频为实验室单手数据。

独立 `umi-traj <录像.insv>` 不读取上述批次，按录像序列号选择当前默认测量，每段独立建图，不保证共享坐标。


## 旧标定包升级

旧 v1 包仍可只读使用，其中脚本不参与计算。需要整理为仅含测量与来源元数据的 v2 包时，先预览，再新增版本：

```bash
./umi-calib upgrade-device CAMERA_SERIAL --dry-run
./umi-calib upgrade-device CAMERA_SERIAL
# 按上一条命令返回的 version 显式启用；不需要切换时停在上一步
./umi-calib activate-calibration CAMERA_SERIAL CALIBRATION_VERSION
```

升级保留原标定版本，不自动修改设备默认值或历史套件/批次。显式启用只改变设备默认标定；新建或更新套件才采用新值。样例借用设备不能通过升级变为实测设备。`migrate-legacy` 仅备份迁出早期 `calibration_user/` 目录，旧命令名 `uninstall` 保留为别名，不会卸载软件。
