# 场景、采集批次与设备档案

[文档导航](README.md) · [场景操作](场景.md) · [标定操作](标定/说明.md)

组织关系是：**场景 → 采集批次 → 任务 → 实际设备与录像**。设备档案全局共享；同一台相机可以交错用于多个场景。

## 三个目录入口

```text
recordings/                              原片与标定运行产物
├── calibration/<完整序列号>/<标定批次>/
│   ├── front/
│   │   ├── A/原始文件名.insv
│   │   ├── B/原始文件名.insv
│   │   ├── C/原始文件名.insv
│   │   ├── D/原始文件名.insv
│   │   └── umi_calib_out/
│   └── rear/...
└── scenes/<场景>/<采集批次>/
    ├── mapping/<完整序列号>/原始文件名.insv
    └── episodes/<任务>/<完整序列号>/原始文件名.insv

registry/                                全局设备资产
├── index.json                           设备状态与新批次的默认标定、夹爪
├── cameras/<完整序列号>/calibrations/<版本>/
│   ├── manifest.json                    资产身份与 SHA256
│   └── bundle/                          前镜头测量；后镜头版本保存 rear_calibration.json
└── grippers/<夹爪ID>/
    ├── current.json                     新配置选择的默认几何版本
    └── versions/<版本>/
        ├── manifest.json
        ├── t_tcp_camera.json
        └── front_hand_mask.png

scenes/<场景>/                           清单、地图与处理结果
├── scene.yaml                           场景定义、建图输入与设备版本
├── maps/current.json                    最新成功地图指针
├── maps/versions/<地图版本>/...
└── sessions/<采集批次>/
    ├── session.yaml                     固定地图、标定与夹爪版本
    └── episodes/<任务>/
        ├── episode.yaml                 左右手、原片路径与哈希、时间同步
        ├── results -> runs/<运行版本>/   最新成功结果
        └── runs/<运行版本>/...
```

`recordings` 存储原片；`scenes` 存储引用原片的清单与处理结果。设备序列号以 INSV 内部数据为准，目录使用完整序列号。左右手由每个任务指定，相机可以在不同任务中换手；`dual` 模式还要满足固定前地图的设备对应关系。

## 什么时候建立新对象

| 对象 | 什么时候新建 |
|---|---|
| 场景 | 换工作环境，例如货架区、收银台；需要独立管理地图 |
| 地图版本 | 显式重新建图；每个版本有自己的坐标定义 |
| 采集批次 | 新一次采集活动，或更换地图、标定、安装配置、设备组合 |
| 任务 | 新录制一次操作；任务名只需在批次内唯一 |
| 标定版本 | 重新标定并手动安装；旧版本保留 |
| 夹爪几何版本 | 更改相机安装、TCP 或遮手图；重新测量并登记 |

采集批次推荐命名 `20261025_001`，任务推荐 `take_001`。同一个场景跨日采集可以继续复用原地图；工作区明显变化后应重新验证地图适用性。

## 标定安装与版本选择

```bash
./umi-calib run recordings/calibration/IAQEB26097M4CP/20261022/front --tag-size-mm 24.0
./umi-calib install recordings/calibration/IAQEB26097M4CP/20261022/front/umi_calib_out
./umi-calib devices
```

标定结果先保存在运行目录，`install` 才登记为设备默认版本。安装只新增版本或复用完全相同的已有资产，不覆盖历史测量。设备状态集中在 `registry/index.json`；运行中始终核对状态和资产哈希。

后镜头通过 `./umi-calib install-rear <rear_calibration.json>` 登记。也可在场景初始化时用 `--rear-left`、`--rear-right` 导入实测文件。

夹爪资产独立于相机标定：

```bash
./umi-calib install-gripper handheld_v1 <包含TCP文件和遮手图的目录>
```

新批次默认沿用场景中已固定的设备配置；显式 `session --device <序列号>` 则从该设备当前默认资产生成配置快照。`session.yaml` 固定实际版本，之后安装新标定或几何不会改变旧批次。需要使用其他已登记版本时，在新批次清单中明确指定，并运行只读预检。

设备停用使用 `./umi-calib retire <完整序列号>`。停用后拒绝新的算法处理，已经生成的结果仍可查看。

## 导入与追溯规则

`umi-scene init` 导入建图录像；`umi-scene episode` 导入任务录像。命令自动读取序列号、保留原始文件名，复制到对应场景、批次、设备目录，记录 SHA256；SD 卡源文件保留。

同名同内容可复用，同名不同内容拒绝覆盖。已经归档在本场景的原片可以直接引用，不会为了同时用于建图和任务再复制一份。处理前校验原片哈希，再核对实际序列号与清单。

场景使用 schema 2，任务使用 schema 2，设备索引使用 version 2；不提供旧目录和旧清单的自动兼容分支。

## 独立录像入口

`umi-traj <录像.insv>` 仍可用于独立实验，按 INSV 序列号查询当前默认标定；它不读取采集批次，也不保证跨录像共享坐标。`UMI_TRAJ_CALIB`、`--device` 和 `--gripper` 是此入口的工程覆盖选项。场景采集使用 `umi-scene` 的显式设备版本和批次清单。
