# 硬核算法实现约定

本文是代码阅读入口，说明建图、定位、尺度/重力融合和任务海报优化中共享的数学约定。参数默认值和验收门槛仍以 `config/algorithms/*.yaml` 为准；本文不复制数值配置。

## 位姿、时间和坐标

项目统一使用齐次变换 `T_a_b` 表示“把 b 坐标中的点变换到 a 坐标”。因此：

- `T_imu_camera`：相机坐标 → IMU 坐标，由相机标定资产读取。
- `T_camera_tcp`：TCP 坐标 → 相机坐标，由 kit 的 TCP 资产读取。
- `T_board_imu`：IMU 坐标 → 海报/地图坐标，是发布轨迹的主要位姿。
- `T_imu_base_tag`：夹爪 base tag 坐标 → 本手 IMU 坐标，是 `poster_vio` 的安装变量。

固定外参右乘到机身位姿：`T_world_tcp = T_world_imu · T_imu_camera · T_camera_tcp`。代码中的长度单位是米，角度在配置中按字段名使用 rad 或 deg；四元数使用 `xyzw`。公共实现和检查入口是 [`software/camera/geometry.py`](../software/camera/geometry.py)。

相机时间先转换到本机 IMU 时间，再做跨手同步。任何插值都禁止外推；跨手 `poster_vio` 会在两个本机惯性链中插入同一物理时刻的节点。地图版本、任务海报坐标和内部逐段世界坐标是不同坐标域，不能只凭标签 ID 互相比较。

## 共享场景：建图、定位和融合

入口链是：

```text
software/scene/spatial/slam.py
  → mapping.py
  → trajectory.algorithms.fusion.alignment.py
  → placement.py
  → graph.py / solver.py
  → recovery.py / quality.py
```

### 纯视觉建图

`slam.py` 是 ORB-SLAM3 外部引擎的适配层。建图阶段使用单目视觉，不把 IMU 传给 ORB-SLAM3；输出可能包含多个子地图、稀疏点、关键帧和地图编号。单目地图的尺度和轴向没有物理含义。

`mapping.py` 只负责地图角色、候选选择、尺度验收、放置和发布，不重新实现 ORB 优化。`shared_front` 选择参考手的 front 地图；`dual` 还需要各手 front 和共享 rear 的地图角色。地图发布前必须通过固定尺度复核、重力/可观测性和资产身份检查。

### 固定地图定位

`relocalization.py` 处理固定地图上的正向定位、反向补全和一致性合并。反向结果只能填补正向缺口，必须在原地图坐标内通过位置/旋转一致性检查，不重新对齐世界系，也不平均已有正向位姿。

### 尺度和重力对齐

`alignment.py` 负责切分视觉连续段、复核坏段、选择可用段；`alignment_solver.py` 组装线性位置方程并求解尺度、重力方向、速度和加速度 bias。核心约束是把视觉位姿经过尺度和放置后，与 IMU 预积分位置变化相匹配。它先求自由重力方向，再固定重力模长重新求解；`fixed_scale` 路径使用精确消元，不用大权重先验近似固定尺度。

可靠段的尺度、重力和残差先单段检查，再由 `placement.py` 放入共同地图坐标。未通过尺度检查的段可以保留旋转约束，但不能提供位置尺度。`graph.py` 才进入 GTSAM 非线性图，联合优化位姿、速度、bias、分段放置和视觉观测；`recovery.py` 为缺少直接视觉节点的输出时刻建立局部惯性恢复状态。`quality.py` 只验收和记录证据，不悄悄修正轨迹。

这套流程不是 ORB-SLAM3 的标准视觉惯性模式：视觉地图先独立建立，IMU 在之后的融合图中加入。共享地图的一致尺度与内部逐段引擎的分段尺度也不是同一个结果。

## poster_vio：任务级联合图

`poster_vio_inputs.py` 冻结海报角点、自然点、IMU、标定和时间偏移；`initialization.py` 只生成 PnP/惯性初值；`solver.py` 构建最终 GTSAM 图。

每手状态包含：

- 主节点 `X`：IMU 位姿；
- `V`：速度；
- `B`：陀螺和加速度 bias；
- 自然点 `P`：按“手 + 镜头 + 轨迹 ID”隔离；
- 启用跨手 base tag 时的 `T_imu_base_tag`：刚性安装 Pose3。

海报板坐标由任务布局固定，海报角点因子连接 `X` 与板坐标；自然点因子连接相机标定、`X` 和 `P`；IMU 因子连接相邻 `X/V/B`。相机内外参、TCP 和时间偏移保持固定。base tag 自身观测只约束安装变量，不约束世界轨迹；跨手观测同时连接观察者位姿、拥有者位姿和拥有者安装变量。

优化采用“短求解 → 按完整观测单元验收/剔除 → 热启动重解”的有限轮策略。留出观测在初始化和 BA 中都不使用，只用于内部一致性检查。非有限投影、非正深度、安装修正超限、时间覆盖不足或累计剔除预算超限会拒绝结果；不会通过继续删点隐藏几何冲突。

解析 Jacobian 位于 [`software/vision/poster/factors.py`](../software/vision/poster/factors.py)，右扰动约定与 GTSAM 因子变量顺序保持一致。`poster_vio` 的实际变量和因子入口见 [`software/trajectory/poster_vio/solver.py`](../software/trajectory/poster_vio/solver.py)。

## 代码阅读顺序和验证边界

建议按“数据契约 → 初值 → 因子图 → 优化/剔除 → 质量证据”的顺序阅读：

- 共享场景：`FusionInputs` → `alignment.py` → `placement.py` → `graph.py` → `solver.py` → `recovery.py`；
- poster_vio：`models.py/contract.py` → `initialization.py` → `frontend.py/keyframes.py` → `factors.py/base_tags.py` → `solver.py/refinement.py`。

解析 Jacobian 有中心差分回归，线性对齐有尺度/重力和固定尺度测试，poster_vio 有三变量 Jacobian、异步双手求解和异常观测测试。这些验证证明实现内部一致，不能替代真实录像、TCP 真值或独立轨迹误差评估。外部 ORB-SLAM3 的具体地图优化仍由引擎实现；本项目代码负责调用、坐标/时间转换、结果筛选和身份验收。
