# 相机与夹爪标定

本文说明每台 X3 的相机标定、验收、登记和夹爪 TCP 几何配置。

配置归属与覆盖规则见[配置指南](../config/README.md)。`./umi-calib run /path/to/front --show-config` 无需录像即可查看标定及 C 验证的生效参数；`--config` 指定实验覆盖，`--tag-size-mm` 提供本次实测板尺寸。准备好录像后用 `--dry-run` 检查输入。

> [文档导航](README.md) · [安装](安装与日常使用.md) · [设备与目录](设备与坐标.md)
> 工作镜头命令是 `./umi-calib run`：录 A/B/C/D → `run` → `install`。需要环境海报约束或双镜头定位时，还要为同一台相机完成环境镜头 `run <rear目录>` → `install-rear`，见[双镜头与海报接入](#双镜头标定与海报接入)。同一台之后抽轨迹，看仓库根目录的 [README.md](../README.md)。
> 任务采集见[日常指南](安装与日常使用.md)，算法说明见[算法原理](算法原理.md)。
> 阅读或修改标定代码见 [标定代码阅读指南](../software/calibration/README.md)，从 `cli.main()` → `workflow.run()` 开始。

## 1. 要不要重新标定

默认：**每台相机的每个参与几何求解的镜头分别完成标定与验收**。第 3–5 节以工作镜头为例，环境镜头见[双镜头与海报接入](#双镜头标定与海报接入)。仓库里那份样例标定属于当初实验室的那一台（2026-09-04），不是新相机的出厂值，也不当未知序列号的默认值。没有档案的序列号，内部轨迹引擎会拒绝处理。

| 情况 | 要不要重新标定 |
|---|---|
| 新买的 / 换了一台（即使同型号） | **要**。录 A/B/C/D，`./umi-calib run`，通过后 `./umi-calib install` |
| 同一台相机，装法没动 | 不用 |
| 同一台相机，从夹爪上拆下来又装回去 | **不用**。镜头和 IMU 都在机身里，拆装不改变它们之间的关系。拆装可能改变的是夹爪尖相对镜头的位置，见第 7 节 |
| 换了录制模式（不是「360 视频 4K60」） | 本工具不支持别的模式 |
| 轨迹明显不对（尺寸不对、漂得厉害），而录法没问题 | 重新标定一次，对比看看 |

全套 = 按第 4 节录 4 段，再运行一条命令。计算耗时取决于录像长度、CPU、磁盘和 C 轨迹重建的重试次数，以终端和报告的实测耗时为准。已有设备需要单独复查时可使用第 8 节的 `verify`。

默认从 A 求实测内参；也可[选择工厂来源](#选择实测或工厂内参)，从 B 原片的工厂 MEI 拟合固定 KB4。两种来源都需要完整 A/B/C/D，工作镜头和环境镜头分别验收。

## 2. 标定的是什么，四段为什么都不能省

### 2.1 算的是机身，不是工作区地图

这份标定描述的是**这一台机身**：工作镜头怎么把真实世界弯到画面上（内参）、镜头和机内 IMU 谁相对谁、图像比 IMU 晚多少毫秒。都在相机内部，跟相机怎么装在夹爪上无关。夹爪尖相对镜头是另一项，见第 7 节。

标定不会发布供任务采集使用的工作区地图。A/B 看的是标定板；C 段调用内部轨迹引擎生成验证用地图与轨迹，和板参考位置比较。这些中间数据在验收可用后默认清理；失败、中断或指定 `--keep-work` 时保留用于排查。场景采集需另外拍建图录像并放入批次 mapping/；`umi-scene run <批次>` 自动建立共享地图并处理任务，也可用 `umi-scene build <批次>` 只执行建图，见 [场景采集指南](场景处理.md)。内部轨迹引擎供标定验证与开发使用，日常任务从场景批次发起处理。

标定时相机装在夹爪上，只是为了镜头朝向和设置与采数据时一样。`umi-calib` 不算 TCP。

### 2.2 四段分工

默认 measured 模式中 A、B 进求解；factory 模式中 A 只验证固定工厂内参。两种模式的 B 都求解，C、D 都只检查、不改标定数字。

| 段 | 进求解？ | 干什么 | 为什么不能省 |
|---|---|---|---|
| **A** | measured 进；factory 不进 | 慢慢移动，让板扫过画面中间、四边、四角；实测模式算内参，工厂模式独立验证固定内参 | 实测需要边缘约束；工厂模式需要实拍证据，不能只看模型转换误差 |
| **B** | 进 | 对着板又平移又快转，把「画面里看到的运动」和 IMU 对上，算出镜头–IMU 位置和时间差 | 内参对了，外参和时间差仍未知 |
| **D** | 不进 | 六个朝向各放稳，查静止时加速度是不是 ≈ 9.81 m/s² | B 看的是视觉和 IMU 是否对得上。当前 B 固定 IMU 尺度，D 独立检查零偏与静止残差，不能证明全部动态参数正确 |
| **C** | 不进 | 一段没参与 A/B 的录像。用**新标定**完成轨迹重建，和板推算的米制位置参考比较 | A/B 的拟合质量不能代替整条轨迹链路的独立验证。C 检查「这份标定进了整条抽轨迹流水线之后准不准」。任务录像通常没有标定板，任务处理替代不了这次对照 |

任务轨迹处理不能替代 C 的板参考验证：任务录像一般没有板，没有独立真值；C 建的地图不供下一段任务复用。D 不能被任务开头那 3–5 秒静止替代：任务只需要一个朝向估重力；D 要多个朝向检查残差是否随姿态变化；本流程不在 D 重新估计零偏或尺度。

## 3. 准备

### 3.1 标定板

- 使用 **6×6 AprilGrid、tag36h11、2 格黑边**，确认 PDF 页脚为 `v2 border=2`；普通 1 格黑边板不兼容。
- 文件：[A4 板](../hardware/calibration_targets/prints/A4_24mm.pdf)（6×6 个标签，每个外黑框边长 24 mm）。
  能打 A3 的话用 [A3 板](../hardware/calibration_targets/prints/A3_36mm.pdf)（外黑框边长 36 mm），标签更大。
- **按 100% 实际尺寸打印**：关掉「适合页面」「缩放以适应」。用哑光纸，不要覆膜。
- **用尺子量**：任意一个黑色方块的边长（A4 板应为 24.0 mm，A3 板 36.0 mm），页面底部的标尺应为 100 mm。
  差 0.3 mm 以内算正常，把**量到的数**记下来，第 5 节运行时要填。差得多说明被缩放了，重打。
- 贴在平整的硬板上（亚克力、KT 板、硬纸板），不能弯。标签四周的白边不要裁掉。
- 把板**固定**在墙上或立在桌上，光照均匀，不要反光。整个过程板不动。

板布局只有 [`hardware/calibration_targets/aprilgrid.json`](../hardware/calibration_targets/aprilgrid.json) 一份，A4/A3 共用；本次实测边长通过 `--tag-size-mm` 输入，不需要修改板配置。文件职责、间距定义和打印要求见 [标定板说明](../hardware/calibration_targets/README.md)。

### 3.2 相机

- 模式：**360 视频、4K60**（和平时采数据完全一样）。原始 `.insv`，不要改名、剪辑、Studio 导出。别的模式（5.7K、单镜头、延时）会拒绝。
- 曝光锁定，快门 **1/240 秒或更快**，灯开亮。画面有拖影是标定失败最常见的原因。
- 相机装在夹爪上、和采数据时一样的状态下录。4 段之间不要改任何相机设置。
- 标定哪个镜头，就让哪个镜头对着 AprilGrid：工作镜头为夹爪指尖一侧；环境镜头为另一侧。原始 INSV 始终保存完整双镜头画面，不能先裁剪再交给标定入口。

### 3.3 相机离标定板多远（重要）

4K60 模式下每个镜头的分辨率不高，标定板离远了，上面的小方块就小到认不出来。A、B、C 三段都按下面的距离录：

| 标定板 | 相机到板的距离 |
|---|---|
| A4（方块 24 mm） | **0.3–0.5 米** |
| A3（方块 36 mm） | **0.4–0.7 米** |

宁近勿远。太近（小于 0.2 米）板会装不进画面，也不好。

## 4. 录 4 段

4 段各自单独开始、单独停止录制，必须来自同一台相机。推荐录完按用途放进 A/B/C/D 子目录，录制先后不影响识别；每个子目录只放本次采用的一个视频。仅在四段平铺时，程序才按文件名排序对应 A/B/C/D，此时应按 A、B、C、D 顺序录。
某一段录坏了就重录该段，再替换对应子目录中的本次输入，保持每段目录内恰好一个 INSV。

| 段 | 要标定板吗 | 时长 | 做什么 |
|---|---|---|---|
| **A** 内参 | 要 | 60–90 秒 | **慢慢**移动相机，让标定板依次出现在画面的中间、上下左右四条边、四个角——**一定要扫到画面边上**，只在中间拍难以可靠估计边缘畸变；距离保持在 3.3 节的范围内；正对着拍，也要倾斜 30–45° 拍 |
| **B** 相机–IMU | 要 | 90–120 秒 | 见下面的「B 段动作」 |
| **C** 独立检查 | 要 | 65–75 秒 | 对着标定板拿稳不动 15 秒（不必竖直放，拿稳即可）→ 慢慢环顾一下周围（带一点前后左右的移动，C 也要跑内部轨迹引擎，只转不挪尺度估不准）→ **在板前（3.3 节的距离内）慢慢地前后、左右、上下移动 15 秒以上，板完整地在画面里** → 像平时采数据那样动一动，可以离开板再回来 → 回到开始的位置，拿稳不动 10 秒。电脑靠能看清标定板的那些帧来核对轨迹，这样的帧太少就核对不了 |
| **D** 六个朝向 | 不要 | 约 2 分钟 | 把夹爪依次以 6 个不同的朝向**放稳**（可以想成上、下、左、右、前、后各朝上一次，用桌面、箱子、泡沫垫着都行），每个朝向**手离开、静置 12 秒以上**，换朝向时慢一点（3 秒以上）。镜头被挡住没关系 |

### B 段动作（最容易录得不够的一段）

1. 相机对着标定板，**拿稳不动 5 秒以上**。
2. **平移**，标定板大部分时间要在画面里，距离保持在 3.3 节的范围内：
   - 前后（靠近、远离标定板）来回 5 次以上；
   - 左右来回 5 次以上；
   - 上下来回 5 次以上。
   每次行程 20–30 厘米，**要快**——大约 1.5 秒一个来回，到头先减速再返回，不要撞、不要甩。动作太慢是这一段失败最常见的原因。
3. **转动**：绕前后、左右、上下三个方向各来回转 5 次以上，每次 ±30–45°，转的时候标定板不要出画面。
4. 再做两三组「边平移边转」的组合动作。
5. 回到开始的位置，**拿稳不动 5 秒以上**。

### 每段录完当场看一眼

- A / B / C：回放一下，画面清楚、没有拖影；标定板没有被手挡住。
- B：动作够快、够多；没有磕碰。
- D：每个朝向确实放稳了 12 秒，夹爪没有晃。

## 5. 运行

### 5.1 安装

先完成[安装与环境检查](安装与日常使用.md)。首次运行需要求解器的命令时，若缺少标定组件会自动补装，全套标定使用显式 `run` 子命令。

### 5.2 算标定

把相机里的原始 `.insv` 保留原名复制到标定目录，推荐放进 **A/B/C/D 四个子文件夹，每个恰好一个视频**（不要剪辑或用 Insta360 Studio 导出）：

```text
recordings/calibration/IAQEB26097M4CP/20261022/front/
├── A/原始文件名.insv
├── B/原始文件名.insv
├── C/原始文件名.insv
└── D/原始文件名.insv
```

以下序列号、日期按实际替换。传入标定目录即可自动识别四段：

```bash
./umi-calib run recordings/calibration/IAQEB26097M4CP/20261022/front --tag-size-mm 24.0
```

也支持四个视频直接放在目录中，按文件名排序对应 A/B/C/D。两种布局不要混用。结果默认写到传入目录的 `calibration_result/`。传入目录的末级名称必须为 `front`（工作镜头）或 `rear`（环境镜头）；程序按目录名选择镜头。先查看报告，再按下文手动启用。

`--tag-size-mm` 填你用尺子量到的黑色方块边长（A4 板大约 24，A3 板大约 36）。

这个尺寸同时用于 A/B 的板几何、C 的板参考和 ORB 标签辅助初始化；C 自动覆盖轨迹配置中的 `orb.initial_tag_size_m`，并记录有效配置，A4/A3 切换时无需再改第二处尺寸。独立 `verify` 和环境镜头标定也采用同一规则。

程序开始时显示本次镜头及 `A = ...`、`B = ...`、`C = ...`、`D = ...`。分段不对时停止处理，把录像整理到正确的 A/B/C/D 子目录后重新运行。

同一轮标定的目录按镜头对称组织：

```text
recordings/calibration/<序列号>/<日期>/
├── front/
│   ├── A/
│   ├── B/
│   ├── C/
│   └── D/
└── rear/
    ├── A/
    ├── B/
    ├── C/
    └── D/
```

两个目录均使用 `run`，无需镜头选项。只传日期目录、`rear_ABCD` 等其他名称会报错；`--show-config` 也需传入 front / rear 目录，但不要求录像已经存在。原独立环境镜头命令和 `--a/--b/--c/--d` 入口已移除。

已有环境镜头结果不会自动搬移。继续处理原 `umi_calib_rear_out/` 等结果时，用 `run <rear目录> --out <原结果目录> --resume` 显式指定；新运行默认使用 `rear/calibration_result/`。

主流程依次准备 4 段录像 → A 实测内参或固定工厂内参验证 → B 相机–IMU 标定 → D 重力诊断 → C 轨迹验证 → 汇总验收。资源允许时，C 板检测会提前与 A/B 重叠执行，但完整 C 验证仍在候选参数生成后进行。
终端为各步骤打印 `[开始]` 和带耗时的 `[结束]`；复用显示 `[复用]`，失败、中断或后台取消显示对应状态。`[结束]` 只表示该步骤执行结束，是否可用看最终验收结论。`report.txt` 分别列出阶段与子步骤耗时；父步骤包含子步骤，后台任务还可能重叠，不能把所有行相加当作总耗时。

默认只验证候选标定，front 加 `--compare-sample` 才额外验证样例；rear 不支持样例对照；每次验证内部的轨迹重建可能按配置重试。常用录像约需 10–20 GB 临时空间，长录像、重试和 `--keep-work` 会增加占用；验收可用后默认清理，失败或中断时保留。

每次工作镜头 `run` 还会自动提取 A/B/C/D 原片的 INSV 工厂 `offset_v3`，比较工厂 MEI 与本次所选的 KB4，无需额外参数或独立命令。这与 `--compare-sample` 的历史样例轨迹对照是两项不同的工作。

工厂对照在 B 参数生成后执行，复用 C 段板角点，均匀选择最多 24 个有足够标签的时刻。1440×1440 对应实测裁切；另解码这些时刻的 1920×1920 全镜头，外围 KB4 结果明确标记为外推。每帧按标签 ID 排序，留出每三个标签中的一个，仅用其他标签求板位姿；在所有模型共同成功的帧上比较留出角点像素误差。射线方向差、无效区域、有效帧数和外围板证据分别记录，不把模型差异当作真实物理误差。

工厂参数保留原始编号，固定 `lens1 = 工作镜头`、`lens0 = 环境镜头`（[对应依据](设备与坐标.md#镜头术语)）。每次 `run` 还会分别把两组工厂 MEI 拟合成 KB4，结果保存到 `factory/kb4_fit.json`。默认工作镜头实拍对照包含本次实测 KB4、工厂 MEI、工厂拟合 KB4；选用工厂模式时明确标记当前模型为工厂来源，环境镜头工厂模式对自身镜头做实拍验证。当前仅支持 X3 3840×1920 原片与双镜头 v3 参数。

拟合以工厂 MEI 反投影的射线为输入，优化八个 KB4 内参，使用 65×65 网格、两个初值的解析雅可比最小二乘，按训练 RMS 选解，不使用实拍角点拟合内参。范围明确为 **1440 裁切与名义半径 960 px 鱼眼圆的交集**；圆不是经过实测验收的有效区域遮罩。独立的错位 193×193 网格和额外边界探针不参与拟合或选解。报告包含 RMS/P95/P99/最大像素误差、中心/边缘/角落统计、射线角度差、无效点、圆外样本数和径向单调性。`*_kb4_fit_pixels.png` 使用统一 0–3 px 色标，灰色表示圆外或模型无效。1920 只评估同一拟合模型的外推，不重新求解。

**拟合误差衡量 KB4 接近工厂 MEI 的程度，不是实拍精度。** MEI 的切向畸变不能由纯 KB4 完整表达。拟合结果标记 `diagnostic_only: true`、`acceptance: not_evaluated`，这份光学诊断不能单独安装。显式选择 `--intrinsics-source factory` 后，另从 B 原片生成正式候选内参并重新求 B/C/D；最终整包仍须验收。自动对照方法版本为 4，旧对照在恢复运行时重算，成功后清除旧版错误镜头候选的射线图。

超广角实现限制也纳入诊断：拟合采用 `atan2` 投影与单位射线反投影，不通过针孔平面表示背向射线。OpenCV `fisheye` 仅用于对照兼容性，不参与拟合；其反投影会截断归一化半径，详见 [OpenCV 4.13.0 源码](https://github.com/opencv/opencv/blob/4.13.0/modules/calib3d/src/fisheye.cpp#L405)。未修复的 ORB-SLAM3 `KannalaBrandt8::unproject` 也截断半径并返回前向平面坐标，报告会列出旧实现受影响的样本数。项目构建现默认使用修复后的 ≤85° 前向视野，实测与工厂来源共用同一引擎。低拟合误差不等于可以直接启用整个视野。A/C 板参考现在使用球面 KB4 反投影，再明确筛掉非前向或无效射线后执行 PnP；不宣称完整 >180° 视野支持。

结果保存在 `factory/comparison.json`、射线差异 PNG 和留出角点叠加图中，摘要自动进入 `report.txt`。工厂步骤失败记录原因和 `run/logs/factory_error.log`；单个镜头拟合失败或视频解码失败单独进入诊断报告，已生成的数值拟合结果保留，不改变原有 A/B/C/D 验收与安装规则。有效结果和图像会在成功清理 work 后保留；`--resume` 校验来源、参数和图像哈希后复用，缺失或损坏会重新比较。对照失败会在下次恢复时重试。

失败或中断后，用原命令加 `--resume` 继续。需要设置线程、保留中间数据或强制重算时，见[高级运行参数](#高级运行参数)。

### 5.3 看结果

结果在 `<文件夹>/calibration_result/`。打开 `report.txt` 看验收结论，最终参数直接读取顶层 `calibration.json`；排查和恢复计算使用 `run/`。

```text
calibration_result/
├── report.txt                 # 验收结论、提醒、误差、耗时和安装命令
├── calibration.json           # 唯一最终参数：内参、畸变、外参、时间偏移
├── manifest.json              # 相机身份、镜头、板配置、输入来源和参数哈希
├── factory/                   # 工厂对照、两镜头 KB4 拟合 JSON、误差图与留出角点叠加
└── run/
    ├── record.json            # 完整阶段测量、验收证据、耗时和断点
    ├── logs/
    │   ├── camera_intrinsics.log
    │   ├── camera_imu.log
    │   ├── gravity_check.log
    │   └── trajectory_validation.log
    └── work/                  # 临时图像、bag 和轨迹；成功后默认清理
```

失败时最终参数或清单可能尚未生成，已完成阶段记录及 `run/work/` 会保留，后续用 `--resume` 继续。A 阶段原始参数、D 检查详情保存于 `record.json`，需要恢复 B 时再生成临时 A 参数文件；板配置和暗角图等附带文件留在工作目录。`--keep-work` 表示成功后也保留大体积工作数据。

阶段测量只保存一份：`record.json` 的 `measurements` 保存测量，`execution` 保存步骤检查点、耗时和错误，`computation` 保存计算配置及来源，`evaluation` 保存验收规则与结论。`report.txt` 是这些记录的人工摘要。B 阶段的参数从顶层 `calibration.json` 读取，清单保存身份与哈希。

启用状态是报告生成时的快照，后续设备切换以 `./umi-calib devices` 为准。普通 `run` 不更新设备配置，通过后仍需手动 `install`（或明确指定 `--install`）。`UMI_TRAJ_CALIB=<calibration_result目录>` 可显式选用本次参数；该目录只需携带 `calibration.json` 和 `manifest.json` 即可读取。安装和重新验收仍指定整个结果目录，需要 `run/record.json` 的验收证据。

运行结果使用上述 `calibration_result/` 布局（`run/record.json` schema 3）。不支持的记录格式需用原录像在新输出目录重新运行。已登记的 `registry/` 版本继续可用。

| 结论 | 意思 |
|---|---|
| **PASS** | 这份标定可以用 |
| **PASS（有提醒）** | 可以用，但报告里有标 `WARN` 的项，建议看一下（多半是某一段录得不够理想） |
| **INCOMPLETE** | 执行未完成或证据不足；查看失败阶段、补录或用 `--resume` 继续，不能安装 |
| **FAIL** | 不要用。报告里标 `FAIL` 的项说明了是哪里不对，对照第 6 节重录相应的那一段 |

TXT 报告单独列出“C 段轨迹误差”：位置 RMSE、95 分位、尺度比及其距离偏差、允许缩放后的诊断 RMSE、参考帧数和移动范围。允许缩放后的误差不代表实际输出精度；这些结果针对 C 段相机位置，不是夹爪尖精度保证。

报告里最重要的是 **C 段、新标定**那几行：电脑用新标定把 C 段的轨迹算了一遍，再和标定板推算的位置参考比较。

- 默认位置 ATE 的失败门限为 30 mm；具体门限见 `config/calibration.yaml`。已有样本达到几毫米，不代表其他录像都能达到该精度；
- C 比较只使用同一视频时间的共同样本，不按帧序号对齐；共同有效样本不足、轨迹退化或板参考运动范围小于默认 0.15 m，结论为 INCOMPLETE，不能安装。
- D 是静止物理诊断：残差超过默认 0.3 m/s²、朝向少或无静止窗口给 WARN；工具执行失败或证据来源不一致给 INCOMPLETE。
- 尺度比（将轨迹位置拟合到板参考位置所需的缩放倍数）在 1 ± 0.03 之内算正常；超出 1 ± 0.03 给提醒，超出 1 ± 0.10 判失败。
  板尺寸、平整度和图像质量会影响参考位置，不能把样例的尺度范围当作其他设备的容差；
- 显式加 `--compare-sample` 时，还会展示样例标定在同一段上的误差；该项仅供比较，不决定新标定验收。

报告包含工作镜头相对样例的健全性检查。与另一台设备有差异不等于测量误差；应结合独立 C 证据判断。

同一组录像重复运行可能有求解和轨迹波动。比较新实现时需固定原片、参数、引擎和资源，先测重复运行的波动，再分析差异；不能把历史样例的百分比当作统一容差。

### 5.4 写入设备档案

```bash
./umi-calib install recordings/calibration/IAQEB26097M4CP/20261022/front/calibration_result
```

`install` 使用报告里的序列号，把最终包复制到 `registry/cameras/<序列号>/calibrations/<版本>/bundle/`。版本按该相机递增为 `001`、`002`……；相同标定重复登记沿用原编号，完整资产哈希仍用于校验。旧版本保留，设备默认选择和报告中的启用状态随安装更新。安装不会自动改写已有套件；需要采用新版本时更新 `kit.yaml` 中的标定编号，批次重新运行时按当前套件处理，历史结果保留。场景任务通过套件快照读取标定，不需要另传相机参数。查看、停用、覆盖选择和完整目录规则见 [设备与目录](设备与坐标.md)。

算法用的是 Basalt（开源的相机–IMU 标定工具）加上一处我们自己的修改，和算样例标定时用的是同一个程序。来源见
[`../software/calibration/setup/basalt/PROVENANCE.md`](../software/calibration/setup/basalt/PROVENANCE.md)。

## 6. 结果不好怎么办

| 报告里的问题 | 多半是因为 | 怎么办 |
|---|---|---|
| A 段：每帧用上的角点数太少 | 标定板离得太远、画面糊、反光，或板经常不在画面里 | 重录 A：按 3.3 节的距离，动作更慢，灯更亮 |
| A 段：标定板没有扫到画面边上 | 标定板一直在画面中间 | 重录 A：让板出现在画面的上下左右四条边和四个角 |
| 内参：重投影误差偏大 | 画面有拖影，或标定板不平 | 检查板是否贴平；重录 A，动作更慢 |
| 内参：焦距 / 主点和样例标定差很多 | 相机模式不是 4K60，或 A 段只在画面中间拍 | 确认相机模式；重录 A |
| B 段：每帧用上的角点数太少 | 板离得太远，或动得太猛画面糊、板经常出画面 | 重录 B：按 3.3 节的距离，快但不要甩 |
| B 段：转动太慢 | 动作幅度太小、太慢 | 重录 B：按「B 段动作」做足 |
| 相机–IMU：和样例标定差很多 | B 段运动不够，或标定板经常出画面 | 重录 B |
| D 段：重力偏差超限，或朝向数不够 | 某个朝向没放稳、时间太短、只换了两三个朝向 | 重录 D：6 个朝向，每个手离开 12 秒以上 |
| C 段：轨迹算不出来 | C 段太短，或开头没有静止和环顾 | 重录 C：按第 4 节，开头静止、环顾，全长 65 秒以上 |
| C 段：能认出标定板的帧太少，或移动范围太小 | 离板太远，或在板前停留、移动得太少 | 重录 C：在板前（3.3 节的距离）慢慢移动 15 秒以上 |
| C 段：误差或尺度超限 | 前面某一段有问题（看其它 WARN / FAIL），或标定板尺寸填错了 | 核对 `--tag-size-mm`；按其它提示重录 |
| 提示「需要正好 4 个 .insv」 | 文件夹里有重录留下的多余文件 | 将本次输入整理为 A/B/C/D 子目录，每段保留一份有效原片 |

只重录了其中一段也要重新运行 `./umi-calib run`；新格式目录可加 `--resume`，程序重新计算受输入变化影响的阶段。需要全部重算时换一个 `--out`，或加 `--force`。

## 7. 夹爪尖相对镜头的位置（另一项标定）

内部轨迹引擎给出的是夹爪尖（两指合拢时的接触点）的轨迹，它是用镜头轨迹乘上夹爪尖相对镜头的位置得到的。
这份几何是尚未独立实测的 CAD 名义值，当前使用的文件为 `kits/kit_001/tcp_camera.json`，由 kit.yaml 每手的 `gripper.tcp` 明确引用。`umi-calib` 只管理相机标定，不求解或登记 TCP 几何；外部核验后直接更新套件内的文件，再运行场景处理。相机标定验收仅比较相机轨迹，不依赖夹爪配置。

当前默认 TCP 采用机器人机械轴向：+X 外侧指向内侧指（工作镜头画面左侧）、+Z 本体指向指尖、+Y 按右手规则确定。TCP 原点和新旧版本关系见 [TCP 坐标系](设备与坐标.md)。

夹爪尖合拢时相对镜头光心的位置变了（换了夹爪、换了相机的安装件、改了相机的安装位置或角度），TCP 轨迹会产生随姿态变化的位置误差，需要核验和更新夹爪几何后重新抽取。这种情况请联系维护者。

---

夹爪宽度可先用 `./umi-calib preview-width /path/to/width.insv` 生成标签框、ID 和像素距离预览，配合已知开口建立实测关系。宽度测量直接放在套件目录的 left_width.json / right_width.json，并在 kit.yaml 对应手通过 `gripper.width` 引用相对路径；run 自动读取，不需要安装或登记。格式和核验步骤见[宽度标定与接入](训练数据.md#夹爪宽度标定与接入)。

仅需两标签中心三维间距时，配置 `gripper.tag_distance` 引用的尺寸 JSON 即可：两枚标签黑色外框边长分别填写在 `tag_sizes_mm` 的 `"0"`、`"1"` 下，单位 mm；使用已选定的工作镜头 KB4 内参解算，不依赖像素宽度 anchors。输出名为 `tag_distance_mm`，与夹爪内侧开口区分；尺寸配置见[套件说明](../kits/README.md)。

## 8. 可选：独立复查已登记相机

全套 `run` 里的 C 已经用新标定对照过板。需要用另一段 C 录像复查已登记相机时，可执行：

```bash
./umi-calib verify recordings/calibration/IAQEB26097M4CP/20261022/front/C/原始文件名.insv --tag-size-mm 24.0
```

程序默认读取这台相机已登记的标定，计算轨迹并和标定板对照；未登记时需要先完成标定并安装。也可通过 `UMI_TRAJ_CALIB=<标定包目录>` 显式选择已有标定包，此时跳过设备登记选择。结果在录像旁边的 `<录像名>_calibration_verification/report.txt`。

| 结论 | 怎么办 |
|---|---|
| **PASS** | 本次 C 段验证通过，设备档案不变 |
| **PASS（有提醒）** | 板帧偏少 → 重录 C 再验证；误差或尺度偏大 → 做全套 |
| **FAIL** | 录像没问题的话，做全套（第 4、5 节） |
| **INCOMPLETE** | 先解决执行错误或补录足够移动范围/板可见时间的 C 段，不能据此认定标定好坏 |


## 高级运行参数

### 线程、后台任务与恢复

`--cores 0-7` 先限定可用 CPU，再计算数据处理线程预算。`--workers 8` 调整图像准备、独立板检测和转 bag 解码的线程预算；普通图像准备与板检测默认最多 24 个线程，转 bag 最多 4 个解码线程、预读队列最多为线程数两倍。后台 C 检测最多用可用核心的四分之一、上限 8 个线程，并受 `--workers` 限制。OpenCV 内部使用单线程。`--workers` 不设置 Basalt 或轨迹引擎自身的线程数；`--cores` 也会约束这些子进程。

至少有 16 个可用核心、线程预算至少为 4，且 A 需要重算时，会额外提前执行 A 板检测和 B 转 bag。两项任务共用一条后台队列，先检测 A，再转换 B；A 检测的线程上限与后台 C 相同。B 数据准备可能先于“B 相机–IMU 标定”出现，终端会标注后台并行。报告分别记录实际任务耗时与 A/B 等待后台结果的时间；提前完成的任务无需再次执行。

A 使用独立板覆盖检查，C 使用独立板参考；B 使用求解器的角点数、拟合质量与运动激励检查。历史覆盖配置含 `board.camera_imu_step` 时需删除该项，当前配置不接受此字段。

失败、中断或再次处理同一批输入时，用相同参数加 `--resume`：

```bash
./umi-calib run recordings/calibration/IAQEB26097M4CP/20261022/front --tag-size-mm 24.0 --resume
```

程序校验阶段输入身份、参数、代码/引擎和关键产物哈希后复用。C 轨迹失败时，已完成的 A/B/D 和 C 板检测可以保留；成功后即使已清理工作目录，再次 `--resume` 也能直接复用完成结果。只改 C 检测采样参数时复用 A/B，仅重建需要的 C 数据；保留的 A/C 角点缓存命中时不再准备图像；修改验收门限会重新判定，不直接沿用旧结论。`verify` 同样支持 `--resume` 和 `--workers`。

计划保留中间数据用于调参时，首次运行加 `--keep-work`，后续使用 `--resume`。代码或引擎改变会使受影响步骤重新计算，文件改名、文案所在源码的变化也可能改变代码指纹。

`--force` 表示清空输出后重新计算，不能与 `--resume` 同用。没有阶段记录或记录为旧格式的目录不能直接恢复，可换一个 `--out` 运行。求解器内部的单次迭代没有断点，恢复粒度是已经完成的阶段。

### 样例轨迹对照

`./umi-calib run` 默认只用新标定验证 C。需要与样例比较时，加 `--compare-sample`，才会额外用样例标定跑一次 C 段内部轨迹引擎：

```bash
./umi-calib run recordings/calibration/IAQEB26097M4CP/20261022/front --compare-sample
```

这会额外执行一次完整轨迹验证，耗时取决于录像和重建重试次数，结果仅供比较，不参与新标定的 PASS / FAIL；样例对照失败也不改变新标定的验收。报告会区分未运行、已运行和未成功。
焦距、镜头–IMU 位置等参数与样例的健全性检查仍照常执行，不受这个选项影响；它们不是把样例装到这台上。

全套 `run` 已包含候选参数的 C 验证；复查同一份参数、同一段录像通常无需再运行 `verify`。使用新录的 C 或复查另一份已登记参数时，可以单独验证。

### 配置与重新验收

默认值来自 `config/calibration.yaml`；`--config 文件.yaml` 显式覆盖。`run` 和 `verify` 支持 `--dry-run`，检查输入并显示有效配置，不运行算法或准备输出。完整参数与原始指标写入 `run/record.json`。只修改验收门限时，新格式的完整报告支持 `recheck`，不重算、不启用设备。配置分组、C 段轨迹配置及旧结果规则见 [参数管理](../config/README.md)。

新结果直接包含 `calibration.json`（实测结果）与 `manifest.json`（schema 3，身份、来源和校验信息）。登记时只复制这两个文件到设备版本的 `bundle/`，不复制 `run/`。已有 v1/v2 标定包继续只读使用。SLAM 配置按运行参数生成，融合使用共享脚本。

`install --serial` 仅用于核对测量所属相机，不能改写序列号。`install --force` 只覆盖完整结果的质量拒绝，不能跳过 INCOMPLETE、参数哈希不符或身份不符。环境镜头入口 `run <rear目录>` 共用相同流程和记录格式，通过后生成 `rear_calibration.json`，由 `install-rear` 校验并登记。

## 选择实测或工厂内参

```bash
# 工作镜头：实测来源为默认；工厂模式仍要求完整 A/B/C/D。
./umi-calib run /path/to/front --intrinsics-source factory

# 环境镜头：需要已有工作镜头档案；独立求环境镜头的 B/C/D。
./umi-calib run /path/to/rear --intrinsics-source factory
```

factory 模式从 B 原片读取该镜头的工厂 MEI（工作 lens1、环境 lens0），拟合 1440 裁切的 KB4，A 录像只作独立验证。B 固定该 KB4 重新求外参、时间偏移，输出后再次核对内参未被改变；不能把工厂内参与旧 B 拼接。两种镜头的工厂默认输出目录均为各自输入目录下的 `calibration_result_factory/`。与实测结果分开保存，不能靠 `--resume` 切换来源。

A 的工厂固定内参留出 RMS 默认超过 2 px 给提醒；少于 6 个有效验证帧或缺少有效误差则证据不足，不能安装。转换、录制一致性门槛位于 `factory` 配置，B/C/D 原有规则继续执行。这里只改变来源，不保证工厂内参优于实测。

通过后可在 run 中加 `--install` 按所选镜头自动登记，或手动用 `install <结果目录>` / `install-rear <环境镜头结果目录>/rear_calibration.json` 登记，保留两套独立版本。`umi-calib devices` 显示默认版本与来源；套件写明两套版本，随后 `umi-scene run <批次> --intrinsics-source factory` 选择工厂整包。命令不会在每段任务原片里重新拟合并覆盖已选参数，原片参数仅作一致性检查。具体套件写法见 [kits/README](../kits/README.md#同时保存实测与工厂来源)。

旧的 `UMI_TRAJ_CALIB=factory` 是实验室样例选择，不是本功能；需要工厂来源请使用新开关或显式指定已验收结果目录。


## 双镜头标定与海报接入

海报参与建图尺度或任务轨迹时，环境镜头需要自己的 KB4 内参、`T_imu_camera` 和 `cam_time_offset_ns`。优先使用套件或命令显式绑定的正式 rear 标定。未绑定时，共享场景和独立轨迹会读取当前 X3 原片的 `offset_v3`，拟合 rear KB4，并通过 `T_imu_rear = T_imu_front × T_front_rear` 组合本设备 front B 与工厂双镜头外参；front 的 B 仍不可省略。两半幅共用帧时间戳，因此兜底沿用 front 时差，未独立测量 rear 延迟。

兜底不需要 rear B，也不写入设备登记表。运行资产标记为 `umi_rear_factory_fallback` / `NOT_EVALUATED`，保存工厂原值、front 哈希、转换误差及时间假设，不能视为通过 rear A/B/C/D 或真实轨迹精度验收。仅支持已实现的 X3 v3、1440 裁切及 ≤85° 前向几何；转换不合格或原片缺参数时明确失败。显式 rear 绑定损坏、身份或来源错误时也失败，不静默兜底。需要独立 rear 验收时执行以下流程：

1. 先完成并登记本设备工作镜头标定。当前环境镜头验证后端仍要求已有工作镜头档案；这不表示环境镜头沿用工作镜头参数。
2. 用**环境镜头对着 AprilGrid**，按本文动作录制它自己的 A/B/C，并提供 D 多姿态静止录像。measured 模式由 A 求内参；factory 模式 A 验证对应镜头的工厂 KB4，B 仍重新求外参和时差，C/D 仍需验收。
3. 运行并检查完整报告，验收通过后登记：

   ```bash
   # 24 只是示例，应填写 AprilGrid 标签黑框实测毫米边长。
   ./umi-calib run /path/to/rear --tag-size-mm 24 --intrinsics-source measured
   ./umi-calib install-rear /path/to/rear/calibration_result/rear_calibration.json
   ```

   factory 模式改用 `--intrinsics-source factory`；其默认输出目录为 `calibration_result_factory/`。记录安装命令返回的 `rear_<hash>`，不要把工作镜头的 `002` 猜作 rear 版本。
4. 共享场景在套件中明确绑定 front/rear 版本，并在 `scene.yaml` 引用海报布局；独立模式用 `--tag-layout` 与 `--rear-calibration`。各入口默认只诊断，数值修正开关见[环境标签计划的实施说明](dev/环境标签与自适应融合重构计划.md)。
5. 量取实际海报的标签黑框及横纵跨标签距离，核对平整度、ID 和朝向。先在建图/任务录像上检查检测、像素残差与尺度一致性，再评估是否启用修正；目前默认阈值仅经合成测试。

**当前仍用 AprilGrid 标定相机，ArUco 海报用于轨迹约束。** AprilGrid 是 tag36h11、2 格黑边；你的海报是 DICT_4X4_100、1 格黑边。`--tag-size-mm` 填的是 AprilGrid 的实测边长，不是海报的 100 mm，也不是夹爪标签的 6 mm。现有 A/B/C 标定工具不支持把这张海报直接当成 AprilGrid 输入。

相机标定验收与海报融合验收分别记录：任务中的低重投影残差不能替代 A/B/C/D，也不能作为真实轨迹精度证明。C 段的板参考不能同时用于修正待评估轨迹，再被称为独立检查。C 显式关闭任务海报融合并使用单镜头验证；rear C 也关闭场景海报建图和融合开关，派生覆盖记录在配置身份中。修改任务海报开关不会让 C 要求海报或另一镜头标定资产。

独立双镜头定位可直接用 `--mode dual --rear-calibration rear_ACTUAL_HASH`，海报布局是额外选择。省略 `--rear-calibration` 时尝试上述工厂兜底；无需为了使用本设备 rear 而提供海报。dual 使用工厂几何时要求 ORB 引擎支持项目的前向 KB4；只做海报约束的 shared_front/handheld 不新增 rear SLAM 能力要求。

环境镜头安装只新增版本，不自动修改套件、地图或已有任务结果。登记后可以只读查询所有 front/rear 版本、内参来源、资产哈希与套件实际绑定：

```bash
./umi-calib devices
./umi-calib devices --kit kit_002 --require-rear
./umi-calib devices --kit kit_002 --require-rear --json
# 多来源套件：按实际准备使用的来源检查
./umi-calib devices --kit kit_002 --intrinsics-source factory --require-rear
```

`devices` 与 `status` 同义。front 显示全局默认，rear 只列已登记版本，不推断默认。指定 `--kit` 后检查套件固定的版本，不用设备默认替换；正式 front/rear 绑定的来源必须一致。未绑定 rear 时，普通套件查询保留 front 可用结论并显示缺项，`--require-rear` 检查正式标定仍返回失败：没有原片时无法判断工厂兜底是否可用。明确绑定但缺失、损坏、身份或来源错误的 rear 始终失败。已停用、样例或借用标定不能通过新采集的套件检查。

退出码：0 表示本次检查通过，1 表示发现缺项/无效资产（或空登记表），2 表示参数或登记表读取错误。无 `--kit` 时汇总所有登记设备及历史版本；有 `--kit` 时整体结论只取决于所选套件绑定，其他历史版本的问题仍列出。此命令不写入资产，也不检查原片匹配、夹爪安装资产或双镜头组合的实测误差；JSON 的 `combination_validation: not_checked` 明确保留该边界。
