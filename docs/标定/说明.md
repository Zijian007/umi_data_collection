# 标定：每台 X3 怎么录、怎么算、怎么写入档案

> 命令是 `./umi-calib`。新买的或换过来的每一台 X3 都走全套：录 A/B/C/D → `run` → `install`。同一台之后抽轨迹，看仓库根目录的 [README.md](../../README.md)。
> 轨迹怎么录见 [`../轨迹/录制.md`](../轨迹/录制.md)，怎么算见 [`../轨迹/使用.md`](../轨迹/使用.md)。

---

## 1. 要不要重新标定

默认：**每一台相机做一次全套标定**（第 3–5 节）。仓库里那份样例标定属于当初实验室的那一台（2026-09-04），不是新相机的出厂值，也不当未知序列号的默认值。没有档案的序列号，`umi-traj` 会拒绝处理。

| 情况 | 要不要重新标定 |
|---|---|
| 新买的 / 换了一台（即使同型号） | **要**。录 A/B/C/D，`./umi-calib run`，通过后 `./umi-calib install` |
| 同一台相机，装法没动 | 不用 |
| 同一台相机，从夹爪上拆下来又装回去 | **不用**。镜头和 IMU 都在机身里，拆装不改变它们之间的关系。拆装可能改变的是夹爪尖相对镜头的位置，见第 7 节 |
| 换了录制模式（不是「360 视频 4K60」） | 本工具不支持别的模式 |
| 轨迹明显不对（尺寸不对、漂得厉害），而录法没问题 | 重新标定一次，对比看看 |

全套 = 按第 4 节录 4 段（约 15 分钟），再运行一条命令（约 45 分钟，电脑自己算）。`verify` / `adopt-sample` 不是默认路径，见第 8 节。

## 2. 标定的是什么，四段为什么都不能省

### 2.1 算的是机身，不是工作区地图

这份标定描述的是**这一台机身**：前镜头怎么把真实世界弯到画面上（内参）、镜头和机内 IMU 谁相对谁、图像比 IMU 晚多少毫秒。都在相机内部，跟相机怎么装在夹爪上无关。夹爪尖相对镜头是另一项，见第 7 节。

标定**不建、也不保存**你干活那张桌子的环境地图。A/B 看的是标定板；C 段虽然会跑一遍 `umi-traj`，那张图只为核对这块板，算完就扔。后面每段任务录像仍要自己扫图，见 [`../轨迹/录制.md`](../轨迹/录制.md)。

标定时相机装在夹爪上，只是为了镜头朝向和设置与采数据时一样。`umi-calib` 不算 TCP。

### 2.2 四段分工

A、B 进求解；C、D 只检查、不改标定数字。看起来像重复，其实查的不是同一件事。

| 段 | 进求解？ | 干什么 | 为什么不能省 |
|---|---|---|---|
| **A** | 进 | 慢慢移动，让板扫过画面中间、四边、四角，算出内参 | 只在中间拍，畸变是错的 |
| **B** | 进 | 对着板又平移又快转，把「画面里看到的运动」和 IMU 对上，算出镜头–IMU 位置和时间差 | 内参对了，外参和时间差仍未知 |
| **D** | 不进 | 六个朝向各放稳，查静止时加速度是不是 ≈ 9.81 m/s² | B 看的是视觉和 IMU 是否对得上。Basalt 有时会把重力吃进加速度计尺度，B 过了 D 仍可能物理上不对 |
| **C** | 不进 | 一段没参与 A/B 的录像。用**新标定**跑完整 `umi-traj`，和板上的真实位置比 | A/B 只保证 Basalt 自己收敛。C 才检查「这份标定进了整条抽轨迹流水线之后准不准」。任务录像通常没有标定板，后面的 `umi-traj` 替代不了这次对照 |

C 不能被后来的任务 `umi-traj` 替代：任务录像一般没有板，没有独立真值；C 建的地图也不会留给下一段。D 不能被任务开头那 3–5 秒静止替代：任务只需要一个朝向估重力；D 要多个朝向才能拆开零偏和尺度。

### 2.3 计算时多出来的对照（不是第二套标定）

`./umi-calib run` 在 C 上会**再**用样例标定跑一次 `umi-traj`（大约多 8 分钟）。报告里标「仅供比较」，**不参与**新标定的 PASS / FAIL。焦距、镜头–IMU 位置和样例差多少，也是同型号健全性检查（差很多多半是某段没录好），不是把样例装到这台上。

不要在全套 `run` 之后再做 `verify`：C 已经做过同样的对照。

## 3. 准备

### 3.1 标定板

- 文件：[`../../hardware/calibration_targets/aprilgrid_6x6_24mm_A4.pdf`](../../hardware/calibration_targets/aprilgrid_6x6_24mm_A4.pdf)（A4 纸，6×6 个标签，每个黑色方块边长 24 mm）。
  能打 A3 的话用 [`aprilgrid_6x6_36mm_A3.pdf`](../../hardware/calibration_targets/aprilgrid_6x6_36mm_A3.pdf)（方块 36 mm）更好，标签大、看得更准。
- **按 100% 实际尺寸打印**：关掉「适合页面」「缩放以适应」。用哑光纸，不要覆膜。
- **用尺子量**：任意一个黑色方块的边长（A4 板应为 24.0 mm，A3 板 36.0 mm），页面底部的标尺应为 100 mm。
  差 0.3 mm 以内算正常，把**量到的数**记下来，第 5 节运行时要填。差得多说明被缩放了，重打。
- 贴在平整的硬板上（亚克力、KT 板、硬纸板），不能弯。标签四周的白边不要裁掉。
- 把板**固定**在墙上或立在桌上，光照均匀，不要反光。整个过程板不动。

### 3.2 相机

- 模式：**360 视频、4K60**（和平时采数据完全一样）。原始 `.insv`，不要改名、剪辑、Studio 导出。别的模式（5.7K、单镜头、延时）会拒绝。
- 曝光锁定，快门 **1/240 秒或更快**，灯开亮。画面有拖影是标定失败最常见的原因。
- 相机装在夹爪上、和采数据时一样的状态下录。4 段之间不要改任何相机设置。
- 用**对着工作区的那个镜头**（夹爪指尖那一侧的镜头）对着标定板。

### 3.3 相机离标定板多远（重要）

4K60 模式下每个镜头的分辨率不高，标定板离远了，上面的小方块就小到认不出来。A、B、C 三段都按下面的距离录：

| 标定板 | 相机到板的距离 |
|---|---|
| A4（方块 24 mm） | **0.3–0.5 米** |
| A3（方块 36 mm） | **0.4–0.7 米** |

宁近勿远。太近（小于 0.2 米）板会装不进画面，也不好。

## 4. 录 4 段

4 段各自单独开始、单独停止录制。按 A、B、C、D 的顺序录。程序按**文件名**排序认哪段是哪段，相机按时间起的文件名就会排成这个顺序。
某一段录坏了就**立刻重录那一段**，并把录坏的文件删掉（或者在第 5 节用 `--a --b --c --d` 指定文件）。四段必须是同一台相机。

| 段 | 要标定板吗 | 时长 | 做什么 |
|---|---|---|---|
| **A** 内参 | 要 | 60–90 秒 | **慢慢**移动相机，让标定板依次出现在画面的中间、上下左右四条边、四个角——**一定要扫到画面边上**，只在中间拍算出来的结果是错的；距离保持在 3.3 节的范围内；正对着拍，也要倾斜 30–45° 拍 |
| **B** 相机–IMU | 要 | 90–120 秒 | 见下面的「B 段动作」 |
| **C** 独立检查 | 要 | 65–75 秒 | 对着标定板拿稳不动 15 秒（不必竖直放，拿稳即可）→ 慢慢环顾一下周围（带一点前后左右的移动，C 也要跑 `umi-traj`，只转不挪尺度估不准）→ **在板前（3.3 节的距离内）慢慢地前后、左右、上下移动 15 秒以上，板完整地在画面里** → 像平时采数据那样动一动，可以离开板再回来 → 回到开始的位置，拿稳不动 10 秒。电脑靠能看清标定板的那些帧来核对轨迹，这样的帧太少就核对不了 |
| **D** 六个朝向 | 不要 | 约 2 分钟 | 把夹爪依次以 6 个不同的朝向**放稳**（可以想成上、下、左、右、前、后各朝上一次，用桌面、箱子、泡沫垫着都行），每个朝向**手离开、静置 12 秒以上**，换朝向时慢一点（3 秒以上）。镜头被挡住没关系 |

### B 段动作（最容易录得不够的一段）

1. 相机对着标定板，**拿稳不动 5 秒以上**。
2. **平移**，标定板大部分时间要在画面里，距离保持在 3.3 节的范围内：
   - 前后（靠近、远离标定板）来回 5 次以上；
   - 左右来回 5 次以上；
   - 上下来回 5 次以上。
   每次行程 20–30 厘米，**要快**——大约 1.5 秒一个来回，到头先减速再返回，不要撞、不要甩。动作太慢是这一段失败最常见的原因。
3. **转动**：绕前后、左右、上下三个方向各来回转 5 次以上，每次 ±30–45°，转的时候标定板不要出画面。
4. 再做两三组「边平移边转」的组合动作。
5. 回到开始的位置，**拿稳不动 5 秒以上**。

### 每段录完当场看一眼

- A / B / C：回放一下，画面清楚、没有拖影；标定板没有被手挡住。
- B：动作够快、够多；没有磕碰。
- D：每个朝向确实放稳了 12 秒，夹爪没有晃。

## 5. 运行

### 5.1 安装（只做一次）

先装好 `umi-traj`（见 [`../轨迹/使用.md`](../轨迹/使用.md)），然后第一次运行 `umi-calib` 时会自动装好标定需要的额外组件（1–3 分钟）。
也可以手动装：

```bash
bash software/calibration/install_calib.sh
```

不需要 sudo，也不需要编译任何东西：标定程序（Basalt）已经编译好放在仓库里了。

### 5.2 算标定

把相机里的 4 个 `.insv` 原始文件拷到电脑上一个**单独的文件夹**里（不要改内容、不要剪辑、不要用 Insta360 Studio 导出），然后：

```bash
./umi-calib run <放着 4 段录像的文件夹> --tag-size-mm 24.0
```

`--tag-size-mm` 填你用尺子量到的黑色方块边长（A4 板大约 24，A3 板大约 36）。

程序一开始会打出四行 `A = ...`、`B = ...`、`C = ...`、`D = ...`。对不上就停掉，改成按文件指定：

```bash
./umi-calib run --a <A段.insv> --b <B段.insv> --c <C段.insv> --d <D段.insv> --tag-size-mm 24.0
```

电脑会依次：读 4 段录像 → 用 A 段算镜头参数 → 用 B 段算镜头和 IMU 的关系 → 用 D 段检查 → 用 C 段验证。
8 核的电脑上整个过程大约 45 分钟（B 段录得越长越慢；C 上新标定和样例对照各约 8 分钟），中间会占用 10–20 GB 的临时空间，算完自动删掉。
电脑上还有别人在用时，加 `--cores 0-7` 这样的参数可以限制只用哪几个 CPU。

### 5.3 看结果

结果在 `<文件夹>/umi_calib_out/`。先看 `report.txt`，第一行是结论。`umi-traj` 要读的是同目录里的 `bundle/`。

| 结论 | 意思 |
|---|---|
| **PASS** | 这份标定可以用 |
| **PASS（有提醒）** | 可以用，但报告里有标 `WARN` 的项，建议看一下（多半是某一段录得不够理想） |
| **FAIL** | 不要用。报告里标 `FAIL` 的项说明了是哪里不对，对照第 6 节重录相应的那一段 |

报告里最重要的是 **C 段、新标定**那几行：电脑用新标定把 C 段的轨迹算了一遍，再和标定板给出的真实位置比较。

- 轨迹误差应不超过 30 mm（正常是几毫米）；
- 尺度（标定板量出的移动距离 ÷ 轨迹给出的移动距离）在 1 ± 0.03 之内算正常；超出 1 ± 0.03 给提醒，超出 1 ± 0.10 判失败。
  用标定板量尺度本身有 1–2% 的误差；我们自己的手持录像用样例标定读出来是 0.93–0.98；
- 旁边还有一行样例标定在同一段上的误差，**仅供比较**，不决定这份新标定过不过。

报告还把新标定的数值和样例标定并排列出。同型号的相机，两者应该很接近（镜头到 IMU 的位置相差几毫米以内）；差得很多通常说明某一段没录好。

**同一组录像算两遍，结果不会一模一样**，这是正常的（算法里有随机采样）。我们用样例标定的那 4 段原始录像重复算过：
焦距每次相差 0.2–0.8 像素（约 0.1%），镜头到 IMU 的位置相差 0.1–0.4 mm，时间差相差不到 0.01 毫秒，C 段轨迹误差都在 4–6 mm。
比这大一个量级的差别才值得注意。

### 5.4 写入设备档案

```bash
./umi-calib install <文件夹>/umi_calib_out
```

从标定录像读出序列号，把标定包拷进 `registry/cameras/<序列号>/`，并更新 `registry/index.json`。`umi-traj` 之后见到这台相机的 `.insv` 就会用这份。多台相机各 `install` 一次，互相不覆盖。

```bash
./umi-calib devices                    # 列出序列号、状态、标定哈希、夹爪
./umi-calib retire <序列号>            # 停用
```

夹爪几何在 `registry/grippers/handheld_v1/`，和相机标定分开。工程师临时指定某份 bundle（例如标定过程中的对照跑）仍可用 `UMI_TRAJ_CALIB=`，这不是默认路径。

算法用的是 Basalt（开源的相机–IMU 标定工具）加上一处我们自己的修改，和算样例标定时用的是同一个程序。来源见
[`../../software/calibration/basalt/PROVENANCE.md`](../../software/calibration/basalt/PROVENANCE.md)。

## 6. 结果不好怎么办

| 报告里的问题 | 多半是因为 | 怎么办 |
|---|---|---|
| A 段：每帧用上的角点数太少 | 标定板离得太远、画面糊、反光，或板经常不在画面里 | 重录 A：按 3.3 节的距离，动作更慢，灯更亮 |
| A 段：标定板没有扫到画面边上 | 标定板一直在画面中间 | 重录 A：让板出现在画面的上下左右四条边和四个角 |
| 内参：重投影误差偏大 | 画面有拖影，或标定板不平 | 检查板是否贴平；重录 A，动作更慢 |
| 内参：焦距 / 主点和样例标定差很多 | 相机模式不是 4K60，或 A 段只在画面中间拍 | 确认相机模式；重录 A |
| B 段：每帧用上的角点数太少 | 板离得太远，或动得太猛画面糊、板经常出画面 | 重录 B：按 3.3 节的距离，快但不要甩 |
| B 段：转动太慢 | 动作幅度太小、太慢 | 重录 B：按「B 段动作」做足 |
| 相机–IMU：和样例标定差很多 | B 段运动不够，或标定板经常出画面 | 重录 B |
| D 段：重力偏差超限，或朝向数不够 | 某个朝向没放稳、时间太短、只换了两三个朝向 | 重录 D：6 个朝向，每个手离开 12 秒以上 |
| C 段：轨迹算不出来 | C 段太短，或开头没有静止和环顾 | 重录 C：按第 4 节，开头静止、环顾，全长 65 秒以上 |
| C 段：能认出标定板的帧太少，或移动范围太小 | 离板太远，或在板前停留、移动得太少 | 重录 C：在板前（3.3 节的距离）慢慢移动 15 秒以上 |
| C 段：误差或尺度超限 | 前面某一段有问题（看其它 WARN / FAIL），或标定板尺寸填错了 | 核对 `--tag-size-mm`；按其它提示重录 |
| 提示「需要正好 4 个 .insv」 | 文件夹里有重录留下的多余文件 | 删掉录坏的，或用 `--a --b --c --d` 分别指定 |

只重录了其中一段也要重新运行 `./umi-calib run`（换一个 `--out`，或加 `--force`）。

## 7. 夹爪尖相对镜头的位置（另一项标定）

`umi-traj` 给出的是夹爪尖（两指合拢时的接触点）的轨迹，它是用镜头轨迹乘上夹爪尖相对镜头的位置得到的。
这份几何是 CAD 名义值，源文件在 `software/trajectory/calib/t_tcp_camera_nominal_cad.json`，采集时读的是 `registry/grippers/handheld_v1/`（TCP 和遮手指图）。还没有独立实测。`umi-calib` 不处理它，这里也不能重做。换夹爪就换一份 gripper 档案，不要写进相机序列号下面。

夹爪尖合拢时相对镜头光心的位置变了（换了夹爪、换了相机的安装件、改了相机的安装位置或角度），轨迹的形状仍可用，尖端位置会偏。这种情况请联系维护者。

---

## 8. 可选：不重标、沿用样例（不是默认）

默认不要走这一节。全套 `run` 里的 C 已经用新标定对照过板。只有明确决定「这台就用实验室那份样例相机–IMU、不做 A/B/D」时才用：只录第 4 节的 **C 段**，然后：

```bash
./umi-calib verify <C 段录像.insv> --tag-size-mm 24.0
```

电脑用样例标定（或档案里已有的那份）跑这段轨迹，再和标定板对照，约 15 分钟。结果在录像旁边的 `<录像名>_umi_calib_verify/report.txt`。

| 结论 | 怎么办 |
|---|---|
| **PASS** | 样例在这台上够准。若仍要沿用样例：`./umi-calib adopt-sample --from-video <这段C>`。默认流程仍是第 4、5 节全套标定 |
| **PASS（有提醒）** | 板帧数 / 移动范围不够 → 重录 C 再验证；误差或尺度偏大 → 做全套 |
| **FAIL** | 录像没问题的话，做全套（第 4、5 节） |

参考：实验室那台用样例标定，同类录像的轨迹误差是 3.3–7.7 mm。
