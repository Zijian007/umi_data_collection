# 标定说明：什么时候要重新标定，怎么录，怎么算

> 给使用 `umi-traj` 的人看的。不用懂算法，照着做就行。
> 录数据见 [`录制说明.md`](录制说明.md)，算轨迹见 [`使用说明.md`](使用说明.md)，原理和精度见 [`原理与精度.md`](原理与精度.md)。

---

## 1. 先判断：要不要重新标定

`umi-traj` 自带一份"出厂标定"。它描述的是**相机本身**：前镜头的成像参数、镜头和相机内部 IMU 之间的相对位置、图像和 IMU 之间的时间差。
这些都在相机机身内部，所以它只跟"是哪一台相机"有关，跟相机怎么装在夹爪上无关。

| 情况 | 要不要重新标定 |
|---|---|
| 同一台相机，装法没动 | 不用 |
| 同一台相机，从夹爪上拆下来又装回去 | **不用**。镜头和 IMU 都在相机机身里，拆装不改变它们之间的关系。拆装可能改变的是夹爪尖相对镜头的位置，那是另一项标定，见第 7 节 |
| 换了另一台相机（即使同型号） | **先验证，再决定**（见下面 1.1）。同型号相机之间差别不大，出厂标定多半能直接用，但每台有个体差异，要量一下才知道 |
| 换了录制模式（不是"360 视频 4K60"） | 本工具不支持别的模式 |
| 轨迹明显不对（尺寸不对、漂得厉害），而录法没问题 | 重新标定一次，对比看看 |

重新标定 = 按第 3 节录 4 段录像（约 15 分钟），再运行一条命令（约 45 分钟，电脑自己算）。

### 1.1 换了另一台同款相机：先花 15 分钟验证一下

不用上来就做全套标定。只录第 3 节里的 **C 段**（1 分钟多，对着标定板），然后：

```bash
./umi-calib verify <C 段录像.insv> --tag-size-mm 24.0
```

电脑用 `umi-traj` 现在的标定（没装过新标定的话就是出厂标定）算这段的轨迹，再和标定板对照，约 15 分钟。结果在录像旁边的 `<录像名>_umi_calib_verify/report.txt`：

| 结论 | 怎么办 |
|---|---|
| **PASS** | 这份标定在这台相机上够准，**不用重新标定**，直接采数据 |
| **PASS（有提醒）** | 看提醒的是什么：标定板帧数 / 移动范围不够 → 按第 3 节重录一段 C 再验证；误差或尺度偏大 → 建议做全套标定 |
| **FAIL** | 录像没问题的话，做全套标定（第 3、4 节） |

参考：我们自己那台相机用出厂标定，同类录像的轨迹误差是 3.3–7.7 mm。新相机的读数在这个范围附近就说明不用标。

## 2. 准备

### 2.1 标定板

- 文件：[`../hardware/calibration_targets/aprilgrid_6x6_24mm_A4.pdf`](../hardware/calibration_targets/aprilgrid_6x6_24mm_A4.pdf)（A4 纸，6×6 个标签，每个黑色方块边长 24 mm）。
  能打 A3 的话用 [`aprilgrid_6x6_36mm_A3.pdf`](../hardware/calibration_targets/aprilgrid_6x6_36mm_A3.pdf)（方块 36 mm）更好，标签大、看得更准。
- **按 100% 实际尺寸打印**：关掉"适合页面""缩放以适应"。用哑光纸，不要覆膜。
- **用尺子量**：任意一个黑色方块的边长（A4 板应为 24.0 mm，A3 板 36.0 mm），页面底部的标尺应为 100 mm。
  差 0.3 mm 以内算正常，把**量到的数**记下来，第 4 节运行时要填。差得多说明被缩放了，重打。
- 贴在平整的硬板上（亚克力、KT 板、硬纸板），不能弯。标签四周的白边不要裁掉。
- 把板**固定**在墙上或立在桌上，光照均匀，不要反光。整个过程板不动。

### 2.2 相机

- 模式：**360 视频、4K60**（和平时采数据完全一样）。
- 曝光锁定，快门 **1/240 秒或更快**，灯开亮。画面有拖影是标定失败最常见的原因。
- 相机装在夹爪上、和采数据时一样的状态下录。4 段之间不要改任何相机设置。
- 用**对着工作区的那个镜头**（夹爪指尖那一侧的镜头）对着标定板。

### 2.3 相机离标定板多远（重要）

4K60 模式下每个镜头的分辨率不高，标定板离远了，上面的小方块就小到认不出来。A、B、C 三段都按下面的距离录：

| 标定板 | 相机到板的距离 |
|---|---|
| A4（方块 24 mm） | **0.3–0.5 米** |
| A3（方块 36 mm） | **0.4–0.7 米** |

宁近勿远。太近（小于 0.2 米）板会装不进画面，也不好。

## 3. 录 4 段

4 段各自单独开始、单独停止录制。按 A、B、C、D 的顺序录——电脑按文件的先后顺序认哪段是哪段。
某一段录坏了就**立刻重录那一段**，并把录坏的文件删掉（或者在第 4 节用 `--a --b --c --d` 指定文件）。

| 段 | 要标定板吗 | 时长 | 做什么 |
|---|---|---|---|
| **A** 内参 | 要 | 60–90 秒 | **慢慢**移动相机，让标定板依次出现在画面的中间、上下左右四条边、四个角——**一定要扫到画面边上**，只在中间拍算出来的结果是错的；距离保持在 2.3 节的范围内；正对着拍，也要倾斜 30–45° 拍 |
| **B** 相机–IMU | 要 | 90–120 秒 | 见下面的"B 段动作" |
| **C** 验证 | 要 | 65–75 秒 | 对着标定板拿稳不动 15 秒 → 慢慢环顾一下周围（带一点前后左右的移动）→ **在板前（2.3 节的距离内）慢慢地前后、左右、上下移动 15 秒以上，板完整地在画面里** → 像平时采数据那样动一动，可以离开板再回来 → 回到开始的位置，拿稳不动 10 秒。电脑靠能看清标定板的那些帧来核对轨迹，这样的帧太少就核对不了 |
| **D** 六个朝向 | 不要 | 约 2 分钟 | 把夹爪依次以 6 个不同的朝向**放稳**（可以想成上、下、左、右、前、后各朝上一次，用桌面、箱子、泡沫垫着都行），每个朝向**手离开、静置 12 秒以上**，换朝向时慢一点（3 秒以上）。镜头被挡住没关系 |

### B 段动作（最容易录得不够的一段）

1. 相机对着标定板，**拿稳不动 5 秒以上**。
2. **平移**，标定板大部分时间要在画面里，距离保持在 2.3 节的范围内：
   - 前后（靠近、远离标定板）来回 5 次以上；
   - 左右来回 5 次以上；
   - 上下来回 5 次以上。
   每次行程 20–30 厘米，**要快**——大约 1.5 秒一个来回，到头先减速再返回，不要撞、不要甩。动作太慢是这一段失败最常见的原因。
3. **转动**：绕前后、左右、上下三个方向各来回转 5 次以上，每次 ±30–45°，转的时候标定板不要出画面。
4. 再做两三组"边平移边转"的组合动作。
5. 回到开始的位置，**拿稳不动 5 秒以上**。

### 每段录完当场看一眼

- A / B / C：回放一下，画面清楚、没有拖影；标定板没有被手挡住。
- B：动作够快、够多；没有磕碰。
- D：每个朝向确实放稳了 12 秒，夹爪没有晃。

## 4. 运行

### 4.1 安装（只做一次）

先装好 `umi-traj`（见 [`使用说明.md`](使用说明.md)），然后第一次运行 `umi-calib` 时会自动装好标定需要的额外组件（1–3 分钟）。
也可以手动装：

```bash
bash software/calibration/install_calib.sh
```

不需要 sudo，也不需要编译任何东西：标定程序（Basalt）已经编译好放在仓库里了。

### 4.2 算标定

把相机里的 4 个 `.insv` 原始文件拷到电脑上一个**单独的文件夹**里（不要改内容、不要剪辑、不要用 Insta360 Studio 导出），然后：

```bash
./umi-calib run <放着 4 段录像的文件夹> --tag-size-mm 24.0
```

`--tag-size-mm` 填你用尺子量到的黑色方块边长（A4 板大约 24，A3 板大约 36）。

电脑会依次：读 4 段录像 → 用 A 段算镜头参数 → 用 B 段算镜头和 IMU 的关系 → 用 D 段检查 → 用 C 段验证。
8 核的电脑上整个过程大约 45 分钟（B 段录得越长越慢），中间会占用 10–20 GB 的临时空间，算完自动删掉。
电脑上还有别人在用时，加 `--cores 0-7` 这样的参数可以限制只用哪几个 CPU。

### 4.3 看结果

结果在 `<文件夹>/umi_calib_out/`，先看 `report.txt`。第一行是结论：

| 结论 | 意思 |
|---|---|
| **PASS** | 这份标定可以用 |
| **PASS（有提醒）** | 可以用，但报告里有标 `WARN` 的项，建议看一下（多半是某一段录得不够理想） |
| **FAIL** | 不要用。报告里标 `FAIL` 的项说明了是哪里不对，对照第 6 节重录相应的那一段 |

报告里最重要的是 **C 段**这几行：电脑用新标定把 C 段的轨迹算了一遍，再和标定板给出的真实位置比较。

- 轨迹误差应不超过 30 mm（正常是几毫米）；
- 尺度（标定板量出的移动距离 ÷ 轨迹给出的移动距离）在 1 ± 0.03 之内算正常；超出 1 ± 0.03 给提醒，超出 1 ± 0.10 判失败。
  用标定板量尺度本身有 1–2% 的误差；我们自己的手持录像用出厂标定读出来是 0.93–0.98；
- 旁边还给出了用出厂标定算同一段的误差，可以直接比较新标定是不是更好。

报告还把新标定的数值和出厂标定并排列出。同型号的相机，两者应该很接近（镜头到 IMU 的位置相差几毫米以内）；差得很多通常说明某一段没录好。

**同一组录像算两遍，结果不会一模一样**，这是正常的（算法里有随机采样）。我们用出厂标定的那 4 段原始录像重复算过：
焦距每次相差 0.2–0.8 像素（约 0.1%），镜头到 IMU 的位置相差 0.1–0.4 mm，时间差相差不到 0.01 毫秒，C 段轨迹误差都在 4–6 mm。
比这大一个量级的差别才值得注意。

### 4.4 让 umi-traj 用新标定

```bash
./umi-calib install <文件夹>/umi_calib_out
```

之后 `umi-traj` 就用这份标定了。`./umi-traj check` 和每次结果里的 `summary.json` 都会写明用的是哪一份。

```bash
./umi-calib status       # 看现在用的是哪份标定
./umi-calib uninstall    # 回到出厂标定
```

新标定放在仓库目录下的 `calibration_user/` 里，只对这台电脑上的这份代码生效，`git pull` 不会动它。

**有好几台相机**：每台相机单独标定，各自的结果目录留着。处理某台相机的录像前，用环境变量指定用哪一份：

```bash
UMI_TRAJ_CALIB=<那台相机的结果目录>/bundle ./umi-traj <录像文件夹>
```

## 5. 标定的是什么（一分钟版）

- **A 段**：标定板的尺寸是已知的，电脑看它在画面各处的样子，算出镜头怎么把真实世界"弯"到画面上（内参）。
- **B 段**：相机一边看着标定板一边快速运动。电脑把"画面里看到的运动"和"IMU 感觉到的运动"对起来，算出镜头和 IMU 的相对位置，以及图像比 IMU 晚多少毫秒。
- **D 段**：相机静止时，IMU 应该只感觉到重力（9.81 m/s²）。六个朝向都测一下，检查 IMU 的零偏有没有算错。
- **C 段**：一段没有参与计算的录像。用新标定算它的轨迹，和标定板给出的位置比，这是对整份标定的独立检查。

算法用的是 Basalt（开源的相机–IMU 标定工具）加上一处我们自己的修改，和算出厂标定时用的是同一个程序。来源见
[`../software/calibration/basalt/PROVENANCE.md`](../software/calibration/basalt/PROVENANCE.md)。

## 6. 结果不好怎么办

| 报告里的问题 | 多半是因为 | 怎么办 |
|---|---|---|
| A 段：每帧用上的角点数太少 | 标定板离得太远、画面糊、反光，或板经常不在画面里 | 重录 A：按 2.3 节的距离，动作更慢，灯更亮 |
| A 段：标定板没有扫到画面边上 | 标定板一直在画面中间 | 重录 A：让板出现在画面的上下左右四条边和四个角 |
| 内参：重投影误差偏大 | 画面有拖影，或标定板不平 | 检查板是否贴平；重录 A，动作更慢 |
| 内参：焦距 / 主点和出厂标定差很多 | 相机模式不是 4K60，或 A 段只在画面中间拍 | 确认相机模式；重录 A |
| B 段：每帧用上的角点数太少 | 板离得太远，或动得太猛画面糊、板经常出画面 | 重录 B：按 2.3 节的距离，快但不要甩 |
| B 段：转动太慢 | 动作幅度太小、太慢 | 重录 B：按"B 段动作"做足 |
| 相机–IMU：和出厂标定差很多 | B 段运动不够，或标定板经常出画面 | 重录 B |
| D 段：重力偏差超限，或朝向数不够 | 某个朝向没放稳、时间太短、只换了两三个朝向 | 重录 D：6 个朝向，每个手离开 12 秒以上 |
| C 段：轨迹算不出来 | C 段太短，或开头没有静止和环顾 | 重录 C：按第 3 节，开头静止、环顾，全长 65 秒以上 |
| C 段：能认出标定板的帧太少，或移动范围太小 | 离板太远，或在板前停留、移动得太少 | 重录 C：在板前（2.3 节的距离）慢慢移动 15 秒以上 |
| C 段：误差或尺度超限 | 前面某一段有问题（看其它 WARN / FAIL），或标定板尺寸填错了 | 核对 `--tag-size-mm`；按其它提示重录 |
| 提示"需要正好 4 个 .insv" | 文件夹里有重录留下的多余文件 | 删掉录坏的，或用 `--a --b --c --d` 分别指定 |

只重录了其中一段也要重新运行 `./umi-calib run`（换一个 `--out`，或加 `--force`）。

## 7. 夹爪尖相对镜头的位置（另一项标定）

`umi-traj` 给出的是夹爪尖（两指合拢时的接触点）的轨迹，它是用"镜头的轨迹 + 夹爪尖相对镜头的位置"换算出来的。
后者已经实测过，写在 `software/trajectory/calib/t_tcp_camera_nominal_cad.json` 里，`umi-calib` 不处理它。

**只有当夹爪尖合拢时相对镜头光心的位置变了**（换了夹爪、换了相机的安装件、改了相机的安装位置或角度），才需要重新标定这一项。
这种情况请联系维护者。
