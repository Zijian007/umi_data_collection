# 双手采集操作手册

本手册按实际操作顺序说明：**一只相机拍建图视频 → 上传并建图保存 → 双手录制任务 → 上传并配对 → 定位、融合与抽取轨迹 → 查看、验收、导出。**

采用默认 `shared_front` 模式：两只相机在同一张场景地图中定位，各自融合自己的 IMU，输出同一场景坐标系中的轨迹。建图视频可以由任意一只已标定相机录制。双手任务处理不需要重新建图。

## 1. 本手册的路径和命名

服务器上的项目根目录为：

```text
/home/zijianwang/umi_data_collection
```

除特别注明外，命令都在服务器的项目根目录执行：

```bash
cd /home/zijianwang/umi_data_collection
```

全文使用以下示例，实际使用时统一替换：

| 名称 | 示例 | 含义 |
|---|---|---|
| 场景 | `shelf` | 一个需要复用地图的工作环境 |
| 套件 | `kit_001` | 本场景使用的左右手相机及其标定、夹爪配置 |
| 建图批次 | `map_20261026_001` | 建图原片的归档批次 |
| 任务采集批次 | `20261026_001` | 一次采集活动，可以包含多次任务 |
| 单次任务 | `take_001` | 一次双手操作，对应左右各一段原片 |
| 左右相机 | `LEFT_SERIAL`、`RIGHT_SERIAL` | 必须换成各相机的完整序列号 |

下面的 `VID_...insv` 文件名只是举例。上传时保留自己的原始文件名，命令中换成对应文件名。

### 文件分别放在哪里

| 位置 | 用途 | 谁写入 |
|---|---|---|
| `/home/zijianwang/umi_uploads/` | 本手册建议的上传接收区，可换成其它路径 | 操作人员上传 |
| 项目内 `recordings/` | 原始视频的正式归档 | 建图、导入命令自动复制；首次标定原片按下文直接上传 |
| 项目内 `registry/` | 已登记的相机标定与夹爪资产 | 标定安装命令 |
| 项目内 `scenes/` | 场景地图、套件、批次、任务和处理结果 | 场景命令 |
| 项目内 `exports/` | 人工验收后的交付文件 | 导出命令，路径由 `--out` 指定 |

上传接收区是人为约定，程序不会自动监控它。原片上传完成后，还要执行相应的 `build` 或 `ingest`。这些命令保留接收区原片，正式归档使用复制。

## 2. 首次准备：安装、相机标定和夹爪配置

已经完成安装和设备登记时，直接检查设备，再进入第 3 步。

```bash
bash install.sh
./umi-traj check
./umi-calib check
./umi-calib devices
```

完整安装说明见 [安装指南](安装.md)。

### 每只相机分别标定一次

标定上传的是四组**原始 `.insv` 视频**，分别放入 A/B/C/D 目录。以左手相机为例：

```text
recordings/calibration/LEFT_SERIAL/20261026/front/
├── A/    内参标定视频
├── B/    相机与 IMU 联合标定运动视频
├── C/    验证视频
└── D/    多个姿态的静止视频
```

每组的录制方式、标定板和质量要求按 [标定指南](标定/说明.md) 执行。每个 A/B/C/D 子目录恰好放一个视频，保留原始文件名。右手使用同样的结构，路径中的序列号改为 `RIGHT_SERIAL`。

```bash
# 24.0 只是示例，必须改成实际测量的标记尺寸，单位 mm
./umi-calib run recordings/calibration/LEFT_SERIAL/20261026/front --tag-size-mm 24.0
./umi-calib run recordings/calibration/RIGHT_SERIAL/20261026/front --tag-size-mm 24.0
```

两只相机各自产出 `front/umi_calib_out/`，其中有 `report.txt`、`bundle/` 和 `diagnostics/`。阅读报告并确认标定合格后登记：

```bash
./umi-calib install recordings/calibration/LEFT_SERIAL/20261026/front/umi_calib_out
./umi-calib install recordings/calibration/RIGHT_SERIAL/20261026/front/umi_calib_out
./umi-calib devices
```

安装后的资产保存于 `registry/cameras/<完整序列号>/calibrations/<版本>/`。

还要确认实际夹爪的 TCP 几何和遮手图已经登记，资产位于 `registry/grippers/<夹爪ID>/versions/<版本>/`。相机标定不会测出 TCP；项目提供的 CAD 几何不能视为已经完成实物测量。登记方式见 [设备与目录](设备与目录.md)。

相机或安装几何改变后，应更新对应测量并登记新配置。仅更换拍摄场景不需要重新标定相机。

## 3. 拍摄并上传场景建图视频

拿一只已标定相机在场景中拍摄，使用 **Insta360 X3、360 模式、4K60**。覆盖之后双手活动会看到的区域，从不同方向观察，并包含平移和转动；尺度恢复需要足够的运动信息，只站在原地转动不够。

上传相机原始 `.insv` 文件，文件内含图像和 IMU。无需另交 IMU 文件，不使用 LRV 预览或 Studio 导出的 MP4 代替原片。

在服务器准备接收目录：

```bash
mkdir -p /home/zijianwang/umi_uploads/shelf/mapping/20261026_001
```

通过文件传输工具上传，最终例如：

```text
/home/zijianwang/umi_uploads/shelf/mapping/20261026_001/
└── VID_20261026_090000_00_001.insv
```

这一阶段只上传建图原片，不需要上传地图文件或任务视频。

## 4. 在服务器建图并保存

首次创建场景，执行一次：

```bash
./umi-scene init scenes/shelf
```

然后建图：

```bash
./umi-scene build scenes/shelf \
  --mapping /home/zijianwang/umi_uploads/shelf/mapping/20261026_001/VID_20261026_090000_00_001.insv \
  --mapping-session map_20261026_001
./umi-scene inspect scenes/shelf
```

`--mapping` 指定用于建图的原片；`--mapping-session` 指定该原片的归档批次名。它与后面双手干活的采集批次是两件事。

程序从视频建立视觉地图，利用建图录像及 IMU 恢复米制尺度、对齐重力并完成检查，成功后自动保存并发布地图。无需另执行“保存”命令。

**原片归档到：**

```text
recordings/scenes/shelf/map_20261026_001/mapping/<建图相机完整序列号>/
└── VID_20261026_090000_00_001.insv
```

**地图保存到：**

```text
scenes/shelf/
├── scene.yaml
└── maps/
    ├── current.json
    └── versions/<地图版本>/
        ├── manifest.json    输入、配置和地图资产清单
        ├── maps/            定位使用的地图资产
        ├── devices/         该地图使用的设备配置
        ├── map.json         查看器使用的展示地图
        └── report.txt       建图报告
```

版本名例如 `20261026_093000-a1b2c3d4`，由本机建图开始时间和 8 位随机标识组成。`current.json` 指向当前发布版本。失败建图保留诊断证据，不会替换已有成功地图。成功建图默认清理中间 `work/`，需要排障时可加 `--keep-work`。

同一场景后续任务复用地图。环境明显变化或原地图覆盖不足时再建新版本；不同地图版本不保证坐标一致。

## 5. 登记双手套件，创建本次采集批次

首次在本场景使用这套设备时登记：

```bash
./umi-scene kit scenes/shelf kit_001 --left LEFT_SERIAL --right RIGHT_SERIAL
```

产出 `scenes/shelf/kits/kit_001/kit.yaml`，记录左右相机及其当前标定、夹爪版本。后续使用同样配置时可直接复用套件。

每次新的采集活动创建一个新的批次：

```bash
./umi-scene session scenes/shelf --name 20261026_001 --kit kit_001
```

产出 `scenes/shelf/kits/kit_001/sessions/20261026_001/session.yaml`，保存设备配置快照。之后更新套件不会改变这个批次。地图版本在首次实际处理时固定，创建批次时地图也可以尚未建立。

## 6. 双手录制任务并上传

左右相机都使用 **360 模式、4K60**。每次任务双手同时开始、同时结束录制，开头尽量保持约 2 秒静止。未配置同步时按未经确认的零偏移处理；支持人工核验固定偏移，不自动估计同步或时钟漂移。自动文件配对不能代替录制同步，训练前按 [训练数据指南](训练数据.md) 核验并填写配置。

一次双手操作上传**左手一段原始 `.insv` 和右手一段原始 `.insv`**。保留原始文件名；多次操作可以放在同一个采集批次中。

在服务器创建接收目录：

```bash
mkdir -p /home/zijianwang/umi_uploads/shelf/tasks/20261026_001/left
mkdir -p /home/zijianwang/umi_uploads/shelf/tasks/20261026_001/right
```

上传后例如：

```text
/home/zijianwang/umi_uploads/shelf/tasks/20261026_001/
├── left/
│   └── VID_20261026_100000_00_002.insv
└── right/
    └── VID_20261026_100000_00_008.insv
```

左右分目录可避免原片同名覆盖。程序最终按视频内部序列号识别设备身份，不靠目录名判断左右。这一接收目录只放本场景、本采集批次的任务原片，建图视频保留在第 3 步的目录。

## 7. 导入原片并建立双手任务

先预览，再实际导入：

```bash
./umi-scene ingest /home/zijianwang/umi_uploads/shelf/tasks/20261026_001 \
  --session scenes/shelf/kits/kit_001/sessions/20261026_001 --dry-run
./umi-scene ingest /home/zijianwang/umi_uploads/shelf/tasks/20261026_001 \
  --session scenes/shelf/kits/kit_001/sessions/20261026_001
```

程序递归读取原片，按文件名中的开始时间和实际时长匹配左右。默认开始时间容差 2 秒、时长差容差 1 秒，仅双方候选都唯一时自动配对。这些容差只用于找文件，不会修正时间轴。

**原片正式归档到：**

```text
recordings/scenes/shelf/kit_001/20261026_001/
├── LEFT_SERIAL/VID_20261026_100000_00_002.insv
└── RIGHT_SERIAL/VID_20261026_100000_00_008.insv
```

**批次中新增：**

```text
scenes/shelf/kits/kit_001/sessions/20261026_001/
├── session.yaml
├── imports/              本次导入报告及 latest.json
└── take_001/
    ├── episode.yaml      左右原片引用和预期使用手
    └── state.json        处理和验收状态
```

多组配对会继续生成任务，以实际导入报告中的任务名为准。此时尚未抽取轨迹。相同内容重复导入会去重；缺手或有歧义的原片保留待确认，不会随便凑对。补传缺片后再次导入即可。

如果确需人工配对，可跳过该组的自动配对，明确登记一个尚未使用的任务名和操作描述：

```bash
./umi-scene episode scenes/shelf/kits/kit_001/sessions/20261026_001 --name take_manual_001 \
  --left /home/zijianwang/umi_uploads/shelf/tasks/20261026_001/left/VID_20261026_100000_00_002.insv \
  --right /home/zijianwang/umi_uploads/shelf/tasks/20261026_001/right/VID_20261026_100000_00_008.insv \
  --instruction '取出商品并放入篮子'
```

上面是自动配对的替代操作；已经自动分配给 `take_001` 的同一对原片不要再登记成另一个任务。更多补片、单手任务和配对规则见 [场景指南](场景.md#导入原片与任务配对)。

## 8. 定位并抽取双手轨迹

```bash
./umi-scene run scenes/shelf/kits/kit_001/sessions/20261026_001 --dry-run
./umi-scene run scenes/shelf/kits/kit_001/sessions/20261026_001
./umi-scene status scenes/shelf
```

程序自动检查录制条件，从原片准备图像与 IMU，在已发布地图中定位，分别融合左右 IMU，再根据夹爪几何转换到 TCP。双手共用固定场景坐标，当前没有左右手之间的联合优化因子。

首次实际处理将地图版本固定到本批次。之后发布新地图，已有批次仍使用原版本；确需换图时显式使用 `run ... --map-version <已发布版本>`，并重新处理和验收。

**每次任务的结果入口：**

```text
scenes/shelf/kits/kit_001/sessions/20261026_001/take_001/
├── episode.yaml
├── state.json
├── cache/                         可重建的准备、定位等缓存
├── runs/<运行版本>/                各次运行产物或失败诊断
└── results -> runs/<运行版本>/     当前成功结果入口
```

**成功的 `results/` 中包含：**

```text
results/
├── report.txt                     先读这个总报告
├── episode.json                   本次结果的任务和坐标元数据
├── preflight_report.json          原片检查报告
├── bimanual.csv                   两只手在共同时间轴上的 TCP 位姿
├── left/
│   ├── traj_tcp.txt               左手 TCP 轨迹
│   ├── front.mp4                  左手前镜头查看视频
│   ├── report.txt
│   └── details/
│       ├── traj_camera.txt        相机轨迹
│       ├── traj_imu.txt           IMU 轨迹
│       ├── frames.csv
│       ├── run_settings.json
│       └── summary.json           指向场景展示地图的引用等信息
└── right/                         与 left/ 对应的右手结果
```

`traj_tcp.txt` 使用 `t x y z qx qy qz qw` 格式，位置单位米，四元数顺序为 xyzw，位姿表示 TCP 在场景坐标系中的位置和朝向。左右使用同一地图坐标 ID；它不是机器人基座坐标，接机器人时还需要场景到基座的外参。

当前默认 TCP 原点在闭合指尖中点，采用机器人机械轴向：+X 外侧指向内侧指（前镜头画面左侧）、+Z 本体指向指尖、+Y 按右手规则确定。已有批次可能固定旧夹爪轴向，以结果记录的实际资产为准；定义与更新方法见 [TCP 坐标系](TCP坐标系.md)。

`bimanual.csv` 按任务配置的时间偏移，将两手结果插值到共同时间轴；旧任务默认偏移为零且未经确认。不同地图版本的结果不能直接视为同一坐标系。

重复执行会复用输入和算法一致的成功结果。新尝试失败时，失败证据留在 `runs/`，已有成功的 `results` 入口保留；应结合 `state.json` 和 `status` 判断最新状态，旧结果仍存在不代表新尝试成功。原片检查失败时先按报告修正，不将 `--skip-preflight` 当作日常处理步骤。

## 9. 查看并人工验收

在服务器执行并保持运行：

```bash
./umi-view scenes/shelf
```

服务器上的访问地址为 `http://127.0.0.1:9091`。如果人在自己的电脑上查看，在**自己电脑的另一个终端**建立 SSH 隧道，把 `SERVER` 换成服务器地址：

```bash
ssh -N -L 9091:127.0.0.1:9091 zijianwang@SERVER
```

然后在自己电脑的浏览器打开 `http://127.0.0.1:9091`。更详细的查看器操作见 [三维查看](查看.md)。

对照左右视频、轨迹、地图和 `report.txt`，检查是否持续定位、是否出现跳变或明显漂移，以及两手相对位置是否合理。轨迹覆盖率等内部指标不能代替绝对精度测量。目前还没有真实双机新采数据完成物理回归验证。

确认合格后，对每个要导出的任务验收：

```bash
./umi-scene review scenes/shelf/kits/kit_001/sessions/20261026_001/take_001 \
  --accept --reviewer reviewer_001
```

不合格时登记拒绝原因：

```bash
./umi-scene review scenes/shelf/kits/kit_001/sessions/20261026_001/take_001 \
  --reject --reviewer reviewer_001 --reason '具体原因'
```

验收绑定具体成功结果；更改输入、生成新结果或新尝试失败后，需要重新确认。

## 10. 导出交付文件

以下导出整个批次，要求所选任务均为当前有效且人工验收通过的结果：

```bash
./umi-scene export scenes/shelf/kits/kit_001/sessions/20261026_001 \
  --out exports/shelf_20261026_001 --with-video
```

如果只验收了一个任务，将命令的输入路径改为该任务目录，例如末尾加 `/take_001`。已有导出目录不会被覆盖，再次导出时使用新的 `--out` 路径。

**导出到：**

```text
exports/shelf_20261026_001/
├── manifest.json
└── shelf/kit_001/20261026_001/take_001/
    ├── report.txt
    ├── episode.json
    ├── bimanual.csv
    ├── left/
    │   ├── traj_tcp.txt
    │   └── front.mp4
    └── right/
        ├── traj_tcp.txt
        └── front.mp4
```

`--with-video` 决定是否包含前镜头视频。导出提供 TCP、报告、元数据和双手表，不是完整工程备份，也不是直接生成 LeRobot 数据集。

## 11. 备份与后续重复操作

完整复现应一起备份项目中的 `registry/`、`recordings/` 和 `scenes/`，保留相对目录关系以及 `results` 符号链接对应的运行目录。还需保留所用代码和参数版本。展示地图由任务引用场景地图，单独搬走 `results/` 不能保证完整查看与复现。`exports/` 用于交付，不能替代原片和工程资产备份。

日常继续采集同一场景、同一套设备时，只需：**新建采集批次 → 录制上传左右原片 → 导入 → 处理 → 查看验收 → 导出**。同一批次还有新任务时，可继续导入该批次，无需另建套件、重新标定或每次建图。

需要使用后镜头和多张地图的 `dual` 模式时，另见 [场景指南](场景.md#离线建图与抽取)。独立 `umi-traj <录像.insv>` 每段自行建图，不提供这里的双手共享场景坐标。
