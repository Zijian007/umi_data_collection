# 安装与日常使用

本文是从首次安装到任务结果的唯一日常入口。项目的主线是：安装依赖 → 标定设备 → 配置套件 → 准备批次 → 运行 → 查看、验收和导出。

## 安装与环境

[文档导航](README.md) · [下一步：标定相机](标定.md)

## 机器要求

| 项目 | 要求 |
|---|---|
| 平台 | 推荐 Linux x86_64；既有安装记录覆盖 Ubuntu 20.04 / 22.04。自带 Basalt 标定程序仅支持 Linux x86_64 |
| CPU / 内存 | 建议至少 4 核、8 GB；不需要 GPU |
| 磁盘 | 轨迹环境约 5 GB，标定组件额外约 400 MB；标定过程中还需约 10–20 GB 临时空间，另留录像与结果空间 |
| 网络 | 安装需访问 GitHub、conda.anaconda.org、pypi.org；处理录像时离线运行 |
| 系统工具 | `bash`、`curl`、`tar`；安装器将项目依赖放在 `.deps/`，已有这些系统工具时无需 sudo |

轨迹安装器另有 aarch64 分支，但未按 x86_64 同等验证；该分支也不提供自带 Basalt。Windows 用户推荐在 WSL2（Ubuntu 22.04）中运行。

## 本机安装

```bash
git clone https://github.com/Zijian007/umi_data_collection.git
cd umi_data_collection
bash install.sh
./umi-scene check
```

安装器下载 micromamba，按锁定清单安装 Python、FFmpeg、OpenCV 和编译器，安装 GTSAM，再编译 Pangolin 与 ORB-SLAM3。首次安装通常约 15–40 分钟，取决于下载速度与机器性能。中断后可以重跑，已完成的步骤会跳过。

首次执行 `./umi-calib` 会补装标定组件；也可以提前安装并检查：

```bash
bash software/calibration/setup/install.sh
./umi-calib check
```

标定安装器解压仓库内的 Basalt 预编译包，并创建 `.deps/calib_env/`；不需要再编译 Basalt。环境检查终端以 `[完成] 环境检查通过` 收尾。

## 安装位置与日志

默认日志在 `.deps/logs/`。安装失败时先看终端给出的日志；网络恢复后直接重跑安装命令。

```bash
# 自定义依赖目录；以后运行工具也要使用同一个 UMI_DEPS
UMI_DEPS=/data/umi-deps bash install.sh
UMI_DEPS=/data/umi-deps ./umi-scene check
UMI_DEPS=/data/umi-deps ./umi-calib check
```

`JOBS=8 bash install.sh` 可限制编译并行数。默认按本机 CPU 编译，换到其他机器应重新安装。删除依赖目录可卸载环境，录像、标定批次结果与 `registry/` 分别存放。

## Windows (WSL2) 运行说明

对于 Windows 机器（如 Intel i7/i9 或 AMD Ryzen），推荐使用 Windows Subsystem for Linux 2 (WSL2)：
1. 安装并进入 Ubuntu 22.04：`wsl --install -d Ubuntu-22.04`；
2. 建议分配至少 8 GB 内存；
3. 进入 WSL2 终端后按照上方【本机安装】标准流程执行 `bash install.sh` 即可。

## 常见安装问题

| 问题 | 检查方式 |
|---|---|
| 提示尚未安装 | 确认 `.deps/env.sh` 存在，或运行时指定正确的 `UMI_DEPS` |
| 下载失败 | 核对网络或代理，查看 `.deps/logs/` 后重跑安装 |
| 标定组件缺失 | 运行标定安装器，再执行 `./umi-calib check` |
| 迁移环境后引擎无法运行 | 在目标机器重新安装，避免复用按另一台 CPU 编译的依赖目录 |

安装后按 [设备与目录](设备与坐标.md) 放置录像，再开始 [相机标定](标定.md)。

## 日常处理

在 `/home/zijian/umi_data_collection` 工作。只用三个入口：`umi-calib` 管设备标定，`umi-scene` 处理场景轨迹并导出，`umi-view` 查看。

## 1. SD 卡视频放在哪里

SD 卡插在 Windows 后，可通过资源管理器把原始 `.insv` 复制到 WSL 项目。地址形如 `\\wsl.localhost\<发行版>\home\zijian\umi_data_collection`；发行版名称以本机为准。也可从 WSL 已挂载的 Windows 盘符复制，如 `/mnt/e/DCIM`。保留原始文件名和内容。

标定原片按相机分开：

```text
recordings/calibration/CAMERA_SERIAL/20261105/front/
├── A/原始文件名.insv
├── B/原始文件名.insv
├── C/原始文件名.insv
└── D/原始文件名.insv
```

建图与任务原片按场景、批次组织：

```text
scenes/shelf/20261105_001/
├── batch.yaml
├── mapping/原始建图文件名.insv
├── take_001/
│   └── videos/
│       ├── left/原始任务文件名.insv
│       └── right/原始任务文件名.insv
└── take_002/videos/...
```

一段建图＋随后几次操作放在同一批次；新采集轮次可新建 `20261105_002`。同批次替换 mapping/ 原片或修改 kit 后，重跑会自动采用当前输入。每个 take 是一次操作，每只手一段原片。只有左手的套件只需 `videos/left/`。程序用视频内部序列号核对左右身份，不靠文件夹名称猜设备。

无需另外建立上传文件夹。`recordings/` 主要保存标定原片，任务视频直接放在所属场景的 take 内。

## 2. 首次标定并登记设备

```bash
cd /home/zijian/umi_data_collection
./umi-calib run recordings/calibration/CAMERA_SERIAL/20261105/front --tag-size-mm 24.0
```

替换相机完整序列号、日期和实测标签边长。查看 `front/umi_calib_out/report.txt`，通过后登记：

```bash
./umi-calib install recordings/calibration/CAMERA_SERIAL/20261105/front/umi_calib_out
./umi-calib devices
```

另一台相机单独做一次。详细录制要求见[标定指南](标定.md)。结果进入 `registry/`，不用自己复制矩阵。相机标定与场景无关；夹爪 TCP 几何与安装关系有关，拆装后需重新核对。

## 3. 定义套件

准备 `kits/kit_001/kit.yaml`，例如：

```yaml
arms:
  left:
    serial: LEFT_CAMERA_SERIAL
    calibration: '001'
    gripper: handheld_v1
    gripper_version: '003'
  right:
    serial: RIGHT_CAMERA_SERIAL
    calibration: '001'
    gripper: handheld_v1
    gripper_version: '003'
```

只填实际使用的手，标定和几何编号必须已经存在于 `registry/`。编号保留引号。手动换标定时修改对应的 `calibration`；换 TCP 几何时修改 `gripper_version`。保存后重新运行当前批次即可生效；程序比较输入变化，自动复用或重算，历史结果保留。

也可用 `./umi-scene kit kit_001 --left LEFT_CAMERA_SERIAL --right RIGHT_CAMERA_SERIAL` 根据设备默认值生成套件。手写配置与这条命令二选一。

## 4. 声明本批次使用的套件

在已经放好视频的 `scenes/shelf/20261105_001/batch.yaml` 中写：

```yaml
kit: kit_001
```

默认使用套件全部手。双手套件本批次只录左手时明确增加 `arms: [left]`；少放右手视频不会自动变成单手任务。

默认 `mapping/` 中恰好一段原片用于共享前地图。复用已有地图时不放新建图视频，增加 `map_version: 已发布地图版本`。程序不会自行选择别的批次最近发布的地图。每次运行都会读取 `map_version`；修改后重跑即可切换。`run --map-version <版本>` 仅覆盖本次命令，下次仍以 batch.yaml 为准。

`scene.yaml` 可省略，默认运行不会生成空配置；需要覆盖场景参数时再创建它。视频的裁切、取帧、尺寸、编码与音轨选项集中在 `config/trajectory.yaml` 的 `video:`，也可使用场景的 `trajectory_config` 覆盖，见[参数管理](../config/README.md#视频处理参数)。日常不用预先填写设备快照、原片哈希或地图哈希。

## 5. 启动处理

```bash
./umi-scene run scenes/shelf/20261105_001
```

自动完成：读取套件 → 保存设备和建图来源快照 → 登记 take 原片 → 检查原片 → 构建并固定本轮地图 → 提取每个 take 的轨迹。

本地视频直接引用，不重复复制；预先分好的 take 不会混配。缺片、同一手多段候选或设备不匹配会报告问题并以失败状态退出，保留已有原片。补齐后运行同一条命令继续。

可选只读预览：

```bash
./umi-scene run scenes/shelf/20261105_001 --dry-run
```

预览只校验和列出计划，不创建清单、锁、地图或结果；它不能证明后续 SLAM 一定成功。实际算法仍会执行原片质量检查。

运行后，内部文件统一收在各级 `.umi/`：

```text
scenes/shelf/
├── scene.yaml                         # 可选：非默认场景参数
├── .umi/maps/                         # 自动保存的地图
└── 20261105_001/
    ├── batch.yaml                     # 用户声明
    ├── mapping/                       # 建图原片
    ├── .umi/manifest.yaml             # 自动记录当前设备、来源和地图
    └── take_001/
        ├── videos/                    # 任务原片
        ├── results/                   # 成功后生成
        └── .umi/                      # 清单、状态、缓存、运行记录
```

无新原片时重跑不新增导入报告；同一输入和原因的重复失败只保留一份诊断。错误详情和调用栈集中在任务 `.umi/runs/<失败运行>/error.json`，保留本次预检报告。成功结果和人工验收记录独立保留。

`batch.yaml` 和当前 `kit.yaml` 是配置来源；每次 run 都重新读取。`.umi/manifest.yaml` 只是当前输入的自动解析记录，不要手动编辑。换标定、套件或替换 mapping/ 中的原片后，直接重跑同一批次；输入未变时复用，改变时重算相关阶段，原有成功结果和运行记录保留。

结果先读 `take_001/results/report.txt`，文件布局和帧号定义见[结果说明](结果查看与验收.md)。各手 `results/left/traj_tcp.txt`、`results/right/traj_tcp.txt` 是位姿轨迹；双手另有 `bimanual.csv`。重新运行复用有效成功结果，失败不覆盖此前成功结果。

## 6. 查看、验收与导出

```bash
./umi-view scenes/shelf
```

按终端提示在 Windows 浏览器打开 `http://127.0.0.1:9091`，对照视频、轨迹与报告检查。不同建图批次的坐标不保证一致。查看器关闭后，明确记录人工验收再导出：

```bash
./umi-scene review scenes/shelf/20261105_001 --accept --reviewer zijian
./umi-scene export scenes/shelf/20261105_001 --with-video --out exports/shelf_20261105
```

需要训练包时，用同一个程序：

```bash
./umi-scene export scenes/shelf/20261105_001 --format training --out datasets/shelf_20261105
```

训练包要求非空指令和已确认的双手同步；可在生成的 `.umi/episode.yaml` 中填写，修改后重新运行并验收。宽度标定和训练就绪说明见[训练数据](训练数据.md)。不自动猜指令、不把文件配对当成同步确认。

日常必须准备的只有 `kit.yaml`、`batch.yaml` 和原片。`registry/` 的测量资产及批次快照由程序维护；高级登记、补片、状态查询和排障命令见[场景指南](场景处理.md)。

## 任务录像建议

[场景流程](场景处理.md) · [独立轨迹抽取](场景处理.md) · [标定指南](标定.md)

## 相机与文件

使用 Insta360 X3 的 **360 视频、4K60** 模式，保留原始 `.insv`，不要剪辑、改内容或经 Studio 导出。尽量保留原始文件名，自动双手配对需要其中的开始时间。

固定安装相机、夹爪与 TCP。记录完整序列号和左右手归属，登记到套件。双手尽量同时开始、同时结束录制。训练数据需要核验共同事件的时间差，并检查首尾是否漂移；人工偏移配置见 [训练数据指南](训练数据.md)。当前不自动估计同步，不要求制造碰撞脉冲。

尽量锁定曝光，光线允许时使用 1/240 秒或 1/120 秒快门，减少运动模糊。确认镜头干净、无遮挡，保留有纹理且相对静止的背景。原片模式和曝光检查规则见 `config/scene_parameters.yaml`；缺少曝光信息会标为 UNKNOWN。

## 一段任务

1. 开始后尽量静止约 2 秒，帮助惯性初始化；当前场景检查中不够静止给出 WARN。
2. 自然完成操作，让背景特征持续可见，避免长时间只看到白墙、手或移动的人。
3. 结束前适当静止，再同时停止双手机位。

独立 内部逐段轨迹引擎 需要每段建图，宜包含带平移的环视和足够长度；纯转动难以恢复尺度。共享场景任务复用已有地图，不要求每段重新完成建图动作。场景的建图参考录像仍需要平移、旋转与足够环境覆盖。

## 采完之后

每次场景采集分别建立批次，按批次向 `umi-scene ingest` 提交原片。套件跨场景采集时不要将不同场景文件混成一个批次；软件无法仅靠序列号判断场景。缺手任务留待补齐，确实只采一手需显式声明 `--arms left` 或 `--arms right`。

```bash
./umi-scene ingest /media/sd/this_session --session scenes/<场景>/<批次>
./umi-scene run scenes/<场景>/<批次>
./umi-view scenes/<场景>
```

原片自动按场景、批次、完整序列号归档，SD 卡源文件保留。录制时记下操作指令和异常情况，处理后结合视频、轨迹、地图检查结果。

## 安装变化

更换相机要完成该设备标定并手动登记。相机相对夹爪的位置、TCP 或遮手区域改变，要更新夹爪几何与遮手图并登记新版本，再更新套件；不要直接修改已固定的历史资产。原有 TCP 采用 CAD 名义值，标定报告不能替代 TCP 几何测量。
