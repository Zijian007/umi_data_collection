# 安装与日常使用

按本页完成一次采集：**准备设备 → 手写配置 → 放视频 → run → 查看和验收 → 导出**。首次使用完成第 1–3 步；设备和套件已经准备好时，从第 4 步开始。

[文档导航](README.md) · [标定录制要求](标定.md) · [高级配置与排障](场景处理.md)

以下命令从项目根目录执行，示例序列号、日期和路径替换为实际值。

三个入口的参数由各自 `--help` 说明，可先查看常用子命令：

```bash
./umi-view --help
./umi-scene run --help
./umi-calib run --help
```

## 1. 安装并检查环境

推荐 Linux x86_64，至少 4 核、8 GB 内存，不需要 GPU。Windows 使用 WSL2，推荐 Ubuntu 22.04，可先执行 `wsl --install -d Ubuntu-22.04`。既有安装记录覆盖 Ubuntu 20.04 / 22.04。

```bash
git clone https://github.com/Zijian007/umi_data_collection.git
cd umi_data_collection
bash install.sh
./umi-scene check
```

安装需要 `bash`、`curl`、`tar`，以及访问 GitHub、conda.anaconda.org、pypi.org 的网络。依赖安装到 `.deps/`；已有上述系统工具时无需 sudo。处理录像可离线运行。

轨迹环境约占 5 GB，标定组件额外约 400 MB；标定还需约 10–20 GB 临时空间，另留原片和结果空间。首次安装通常约 15–40 分钟，取决于机器与网络，中断后可重跑。

正式执行 `umi-calib run <front或rear目录>` 时，会在解析命令、校验输入方式及执行选项后补装缺失的标定组件。`check` 只检查现有环境，帮助、未知命令、参数解析失败和 `--dry-run` 不触发补装。也可提前安装：

```bash
bash software/calibration/setup/install.sh
./umi-calib check
```

检查以 `[完成] 环境检查通过` 收尾。自带 Basalt 标定程序只支持 Linux x86_64；轨迹安装器的 aarch64 分支尚未获得同等验证。

## 2. 标定并登记每台相机

按[标定指南](标定.md)录制 A/B/C/D 四段，保留原始 INSV 名称和内容：

```text
recordings/calibration/CAMERA_SERIAL/20261105/front/
├── A/原始文件名.insv
├── B/原始文件名.insv
├── C/原始文件名.insv
└── D/原始文件名.insv
```

```bash
./umi-calib run recordings/calibration/CAMERA_SERIAL/20261105/front --tag-size-mm 24.0
```

`--tag-size-mm` 填 AprilGrid 标定板标签的实测黑色外框边长（mm，不含白边）；夹爪标签边长另在套件 `gripper.tag_distance` 引用的 JSON 配置。结束后查看 `front/calibration_result/report.txt`，验收可安装时登记：

```bash
./umi-calib install recordings/calibration/CAMERA_SERIAL/20261105/front/calibration_result
./umi-calib devices
```

左右相机分别完成一次。标定结果进入 `registry/`，无需手动复制矩阵。相机标定描述机身内部关系；相机相对夹爪的安装变化还需要核验 TCP 几何，见[夹爪标定](标定.md#7-夹爪尖相对镜头的位置另一项标定)。

以上默认使用实测 A 内参。工作镜头 `run <front目录>` 与环境镜头 `run <rear目录>` 可加 `--intrinsics-source factory` 使用工厂 MEI 拟合的 KB4，仍需录 A 做独立验证，并重新实测 B/C/D。工厂结果目录带 `_factory` 后缀，独立登记；验收与安装见[来源选择](标定.md#选择实测或工厂内参)。

## 3. 手动填写套件

创建 `kits/kit_001/kit.yaml`：

```yaml
arms:
  left:
    serial: LEFT_CAMERA_SERIAL
    intrinsics:
      front: measured
      rear: factory
    gripper:
      tcp: tcp_camera.json
  right:
    serial: RIGHT_CAMERA_SERIAL
    intrinsics:
      front: measured
      rear: factory
    gripper:
      tcp: tcp_camera.json
```

只保留实际使用的手，为前后镜头分别选择 measured / factory；使用该设备对应来源的当前参数。将当前安装的 TCP 变换保存到套件目录的 `tcp_camera.json`；左右安装不同时分别引用各自文件。套件可跨场景复用。字段与可选测量见[套件配置说明](../kits/README.md)。

需要在两来源间切换时，先按[双来源套件配置](../kits/README.md#同时保存实测与工厂来源)分别填写已安装的工作/环境镜头版本，再用 `umi-scene run <批次> --intrinsics-source measured|factory` 选择。旧的单个 `calibration` 字段仍固定原版本；开关不会替换它或补装缺失测量。

## 4. 准备本次配置和视频

一段建图录像和随后几次操作组成一个批次。创建 `scenes/shelf/20261105_001/batch.yaml`：

```yaml
kit: kit_001
```

默认使用套件全部手；双手套件本批次只采左手时增加 `arms: [left]`。默认共享工作镜头地图模式无需创建 `scene.yaml`。

从 SD 卡复制原始视频，按一次操作一个 take 分组，每只手一段：

```text
scenes/shelf/20261105_001/
├── batch.yaml
├── mapping/原始建图文件名.insv
├── take_001/
│   ├── left/原始任务文件名.insv
│   └── right/原始任务文件名.insv
└── take_002/...
```

保留相机文件名、视频内容和 SD 卡源文件。程序读取 INSV 内部序列号核对左右身份。单手套件只放对应侧；新采集轮次使用新的批次目录。

Windows 可通过 `\\wsl.localhost\<发行版>\home\<用户>\umi_data_collection` 复制到 WSL，也可在 WSL 中读取 `/mnt/e/DCIM` 等已挂载目录。

### 录像要求

- 使用 X3 的 **360 视频、4K60** 模式，保留原始 `.insv`，不要剪辑或经 Studio 导出。
- 固定相机与夹爪安装，保持镜头清洁。尽量锁曝光，光线允许时采用 1/240 秒或 1/120 秒快门。
- 建图录像应包含平移、旋转和充分的环境覆盖；任务操作时保持有纹理的静态背景可见。
- 每次任务开始后尽量静止约 2 秒，结束前适当静止；双手尽量同时开始和结束。开头静止不足会给出 WARN。

每个批次只放同一场景的录像。任务视频无需重新扫图；未分组视频、混合单手任务或地图复用见[场景处理](场景处理.md)。

## 5. 运行批次

```bash
./umi-scene run scenes/shelf/20261105_001
```

程序自动登记视频、检查原片、建立共享地图并抽取各任务轨迹。已有本地原片直接引用，预先分好的 take 保留分组。

缺片、同一手多段候选或设备不匹配会报告问题。补齐对应目录后，执行同一命令继续。输入未变时复用有效结果；失败不会覆盖已有成功结果。需要查看处理计划时加 `--dry-run`，预览不写文件，也不保证后续 SLAM 一定成功。

先读 `<任务>/results/report.txt`，再查看视频与轨迹。目录和结果字段见[结果说明](结果查看与验收.md)。设备快照、地图、缓存和运行记录由程序保存在 `.pipeline/`，无需提前填写。

## 6. 查看、验收和导出

```bash
./umi-view scenes/shelf
```

按终端提示在浏览器打开 `http://127.0.0.1:9092`，对照视频、轨迹、地图与报告检查。确认通过后记录人工验收，再导出：

```bash
./umi-scene review scenes/shelf/20261105_001 --accept --reviewer operator
./umi-scene export scenes/shelf/20261105_001 --with-video --out exports/shelf_20261105
```

完整验收规则、拒绝操作和数据搬运要求见[结果查看与验收](结果查看与验收.md#人工验收与导出)。准备训练数据时，先按[训练数据指南](训练数据.md)填写指令、核验同步并配置所需宽度测量，再处理、验收和导出训练包。

## 安装参数与常见问题

安装器下载 micromamba 和锁定的 Python、FFmpeg、OpenCV、编译器，安装 GTSAM，再编译 Pangolin 与 ORB-SLAM3。标定安装器解压仓库内的 Basalt 预编译包并创建 `.deps/calib_env/`。

### 自定义依赖目录

```bash
UMI_DEPS=/data/umi-deps bash install.sh
UMI_DEPS=/data/umi-deps ./umi-scene check
UMI_DEPS=/data/umi-deps ./umi-calib check
```

后续运行使用同一个 `UMI_DEPS`。`JOBS=8 bash install.sh` 可限制编译并行数。默认按本机 CPU 编译，换机器时重新安装；删除依赖目录可卸载环境，原片与 `registry/` 单独保存。

| 问题 | 处理方式 |
|---|---|
| 提示尚未安装 | 检查 `.deps/env.sh` 或运行时的 `UMI_DEPS` |
| 下载失败 | 查看 `.deps/logs/`，检查网络或代理后重跑安装器 |
| 标定组件缺失 | 运行标定安装器，再执行 `./umi-calib check` |
| 环境迁移后引擎无法运行 | 在目标机器重新安装 |

处理阶段的问题见[场景排障](场景处理.md#故障排查)，标定失败见[标定排障](标定.md#6-结果不好怎么办)。
