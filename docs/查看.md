# UMI Trace：本地轨迹工作台

同时查看 UMI 的三维轨迹、环境稀疏地图、姿态、前镜头视频和速度曲线。读取 UMI 自己的结果格式，无需 Node 构建或加载外网资源。

`./umi-view scenes/<场景名>` 也可查看 `umi-scene` 已发布的任务：同一三维画面显示左右手，配两路同步视频，只回放共同有效时间。场景操作见 [场景与双手任务](场景.md)。

[文档导航](README.md) · [结果格式](轨迹/结果.md) · [查看器代码](../software/viewer/README.md)

从项目根目录启动：

```bash
./umi-view
```

浏览器打开 **http://127.0.0.1:9091**。默认扫描项目的 `recordings/`，自动打开最新一段成功轨迹。新录像抽取完成后，点击录像库旁的刷新按钮即可。

也可以指定设备目录或单个结果目录：

```bash
./umi-view recordings/IAQEB26097M4CP/tasks
./umi-view recordings/IAQEB26097M4CP/tasks/20261023/umi_traj_out/VID_20261022_225713_00_005
./umi-view --port 9092
```

`umi-view` 的服务器使用 Python 标准库。旧地图转换自动调用项目 `.deps/env/bin/python` 与已安装的 ORB 地图导出器；自定义依赖目录时设置 `UMI_DEPS`，或将 `KIWI_PY` 指向对应环境的 Python。`UMI_VIEW_PYTHON` 仍可指定服务器使用的 Python。

默认监听本机；如果查看器运行在实验室服务器、浏览器在另一台电脑，可用 SSH 转发：

```bash
ssh -L 9091:127.0.0.1:9091 zijianwang@lab1
```

然后在电脑上打开 http://127.0.0.1:9091。也可以显式使用 `--host 0.0.0.0`，通过服务器 IP 访问。

## 操作

- 左侧选择录像，或搜索文件名、路径、序列号。
- 左键拖动旋转，右键或 Shift 拖动平移，滚轮缩放；双击或 `R` 复位。
- 顶部切换 TCP／相机／IMU；打开“对照轨迹”查看其他轨迹的虚线轮廓。
- “环境地图”控制稀疏点云显示，下拉框切换前镜头子地图；“关键帧”显示代表性相机位置与朝向。
- “地图坐标轴”显示所选子地图的 `O_map` 原点及红 X、绿 Y、蓝 Z 轴，标签注明轴长（原始地图单位）。已对齐地图的轴与点云使用同一变换，其原点和方向可以不同于轨迹世界坐标；右下角方向提示会单独注明世界／地图方向。
- “世界坐标轴”显示轨迹世界系的 `O_world` 原点及 XYZ 轴，Z 朝上，长度单位为米。两套轴默认同时显示、分别开关：世界轴用虚线，地图轴用实线，并以 `_world`／`_map` 标签区分。未对齐子地图使用原始地图坐标时，世界轴自动隐藏且开关禁用；切回已对齐地图或隐藏原始地图后恢复。
- 开关坐标轴保持当前旋转、缩放和平移；需要按当前显示内容重新取景时，按 `R`、双击画布或点击“透视”。
- 当前位置的红、绿、蓝姿态轴分别是局部 X、Y、Z，经四元数转换到该录像的世界坐标。
- 空格播放／暂停，左右箭头逐帧；拖时间轴或点击速度图、三维轨迹可定位时间。
- 视频、三维位置、姿态和速度使用同一时间轴；支持倍速和循环。
- “查看本次记录”显示当前标定、目录、运动范围和诊断摘要。

## 环境地图

地图异步加载，轨迹和视频先显示。新的抽取结果自动保留 `details/map.json`；旧结果如果保留了选中轮次的 `map.osa`，首次查看会自动转换，不需要重建地图，也不会修改旧结果。若地图已清理且没有轻量地图产物，界面会提示，仍可独立查看轨迹。

旧地图的转换结果会持久缓存，重启查看器后直接复用；地图、轨迹或转换实现变化时自动重新准备。

可靠对齐的地图叠加在米制轨迹上，并显示用于展示的拟合残差。它表示地图与融合轨迹的一致性，不是独立真值误差。静止、近直线运动、对应点不足或拟合残差过大时，子地图按原始地图单位单独显示，隐藏轨迹叠加；时间轴、视频和下方轨迹位姿读数仍可使用。

每张子地图独立选择，不混合不同坐标系的点。每图最多展示 50000 个点，较大的地图抽样绘制；完整地图仍在原始 `.osa` 中。当前展示前镜头地图，不提供稠密表面重建或后镜头地图显示。更新前已经启动的服务需要重启，再刷新页面。

## 视频加载与兼容播放

查看器优先使用单独缓存的浏览器预览视频，原始建图视频保持不变。预览最大 720 像素宽、码率约 1.5 Mbps，保留鱼眼视野、帧率和视频时间轴。首次查看新录像时在后台生成，期间仍能看原视频或兼容画面；准备好后自动切换并保持当前时间和播放状态，之后再次打开可直接播放。

首帧同样持久缓存，不必每次启动 FFmpeg。查看器缓存默认在 `~/.cache/umi-view/`（设置 `XDG_CACHE_HOME` 时跟随该目录），不增加录像结果目录中的文件；可用 `UMI_VIEW_CACHE` 更换位置。清理缓存后会重新生成。

部分浏览器无法原生播放结果里的 H.264 视频。查看器会自动切换“兼容模式”，也可以点击视频下方的“兼容播放”。服务器用项目已有的 FFmpeg 解码 JPEG 画面；视频画面和三维位姿按同一个轨迹点更新。

兼容模式的画面帧率由服务器解码速度决定，会低于原生视频；播放时跳过来不及显示的中间画面，暂停、逐帧和拖动后会显示所选轨迹点对应的画面。最近读取过的画面会在内存复用，不生成整段抽帧目录，不改变轨迹数据。手动点击“兼容播放”后会保持该模式，重新选择录像可恢复自动选择。

如服务在更新前已经启动，需要在原终端按 Ctrl+C，然后重新运行 `./umi-view`，并刷新浏览器页面。如果提示找不到 FFmpeg，先安装项目的轨迹组件，或把系统 `ffmpeg` 加入 PATH。缺少视频文件本身时仍只能独立查看三维轨迹。

## 数据约定

支持新的 `details/` 布局、旧 `diagnostics/` 布局和历史平铺布局；不修改轨迹、设备档案或原始录像。

- 必须有 `traj_tcp.txt`，每行 `t x y z qx qy qz qw`；跳过注释，检查有限数值、递增时间和四元数。
- 相机／IMU 轨迹可选，时间戳必须与 TCP 对齐。
- `frames.csv` 提供约束类型、原视频帧号和跟踪状态；缺失或无效的帧显示“未知”。
- 视频优先读取结果根目录的 `front.mp4`。该文件独立于 `debug/`，成功后清理中间数据也能播放；它是前镜头裁切视频，默认 720×720，可通过 `video.size_px` 配置边长，保留鱼眼畸变。兼容旧 `diagnostics/work/kiwi*/front/front.mp4` 和 `work/` 路径，按摘要里的选中轮次读取。没有保留视频时仍能独立回放轨迹。
- 环境地图来自 ORB 的稀疏三维特征点，不是完整物体模型。TCP 是 CAD 名义几何，地图约束比例不是实际误差。
- 每段录像的世界原点和水平朝向独立，不能直接跨录像拼接坐标。
