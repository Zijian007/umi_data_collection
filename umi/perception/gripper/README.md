# 夹爪开合宽度

`marker_detection.py` 处理灰度图上的标签检测。`frame_detection.py` 的 `FrameDetector` 统一处理原片 ROI、灰度转换和坐标恢复，供像素开口宽度、三维标签中心距及 `video_tools.py` 中的两个调试命令使用。

## 夹爪标签中心三维间距

`tag_pose.py` 计算 KB4 标签位姿和三维中心距离。`distance.py` 组织采样、缓存、补检与验收。测量从夹爪标签 ID 0/1 的原始四角点、工作镜头 KB4 内参及各自标签边长，求两枚夹爪标签中心在相机坐标系中的位置，输出其三维欧氏距离（mm）。不使用夹持面偏置、零点或像素—毫米 anchors，不据此生成 `close_01` 或闭合状态。

套件配置 `gripper.tag_distance: tag_distance.json`，文件包含 `{"tag_sizes_mm":{"0":6.0,"1":6.0}}`；两枚边长分别配置，必须为正数。测量黑色外框，不含白边；尺寸变化线性改变尺度，不能借用标定板尺寸。原片检测缓存保存 `[帧, ID, 角点, xy]`，重复/缺失 ID 的角点保留 NaN。标签中心距按最终轨迹时间点检测，像素锚点宽度沿用原片逐帧检测；两者分别缓存。改尺寸或内参会复用角点重算几何，有效比例不足时再补检尚未尝试的帧。

场景测距、像素宽度提取、`preview-width` 和 `detect-width` 共用 `config/operations/gripper_tag_detection.yaml` 的 `roi_px`。初始值为 `LEFT TOP RIGHT BOTTOM = 600 980 1350 1250`，原点在 1920×1920 工作镜头半幅左上角。场景中心距测量可在专家配置中用 `measurements.gripper_tags.roi_px` 覆盖，两个宽度命令可用 `--roi` 覆盖。检测先裁剪源像素平面，再将 ROI 转灰度，最终恢复原始半幅坐标。`recording.video.crop` 用于轨迹视频准备。

共享灰度转换保留颜色空间、亮度量程及色度采样对齐；奇数 ROI 坐标先对齐后取回精确边界，高位深转 8 位保留抖动相位。视频仍需解码源帧，减少的是灰度转换和检测的像素量；预览视频的彩色显示转换独立于标签检测图像。

场景同时启用宽度、中心距、环境海报中的两类以上时，首次扫描通过 `umi/perception/decoding.py` 共用一次顺序解码，检测和缓存仍分别维护。只启用一类时沿用独立入口；缓存全部命中时不解码。中心距的有界补检仍按需从关键帧开始，不改变补检顺序或验收门限。

三维计算再将原始角点减去 240 像素边距，转换到已标定的 1440 中心裁切坐标；不使用 720 视频内参直接解释原片角点。超出标定裁切或前向 85° 射线范围、退化/过小四边形、无正深度解、重投影误差超限的观测保持缺失。使用 IPPE_SQUARE 两解并按鱼眼重投影误差选择；两解误差相差不超过 0.25 px、中心差超过配置门限时保留 `ambiguous_pose`。

质量参数在 `reconstruction/common.yaml` 的 `measurements.gripper_tags`：`maximum_reprojection_error_px` 默认 2.0（每角点二维残差的 RMS），`maximum_center_ambiguity_mm` 默认 2.0；用 `--expert-config` 按同一字段路径覆盖。原片测量按最近的实际帧对齐轨迹时钟，限制在半个源帧周期内；不补缺口或用前帧值代替当前缺失。`trajectory.csv` 增加 `tag_distance_mm`、`tag_distance_valid`、`tag_distance_source`，无效数值留空；来源包括 `two_tags`、`missing`、`outside_calibration`、`invalid_geometry`、`pose_failed`、`high_reprojection_error`、`ambiguous_pose`、`ambiguous_detection`、`unmatched_time`。

`measurements.gripper_tags.verified_gap_recovery` 在场景处理中默认开启。长缺口从两端跟踪标签，也在每帧做局部对比度增强解码。增强候选先对照原图黑框精化角点，再用原帧验码和 KB4 几何检查复核。多个候选的对应角点差异超过 1.5 个原始像素时保留歧义标记。模板候选也要求两个方向的角点一致。系统还会用 `recovery_batch_size` 限制每手短缺口的额外补检数，优先处理已找到两枚标签的帧。报告在 `detection.verified_gap_recovery` 和 `detection.short_gap_recovery` 记录接受帧、冲突和缓存键。

`TagDistanceRequest` 将原片、尺寸、相机、哈希、`TagPoseQuality`、ROI 和验收要求组合为具名输入。`frame_detection.py` 按真实 PTS 为每个最终轨迹帧选择最近源帧，裁剪到配置 ROI 后检测，不缩小检测像素；解码仍读取压缩视频，非输出时间点不执行标签检测。超出源时钟范围或帧间隔过大时保持 `unmatched_time`。

先用快速模式扫描全段全部输出帧并完成三维检查。每只手同时满足两项才通过：`two_tags` 有效帧数除以最终 CSV 总帧数达到 `measurements.gripper_tags.minimum_valid_fraction`（默认 0.5，范围 `(0, 1]`），且连续没有有效三维中心距的帧数不超过 `measurements.gripper_tags.maximum_missing_frames`（默认 15，非负整数，0 表示不允许缺失）。恰好等于上限通过；开头、结尾、所有无效原因都计入连续缺失。该上限按最终输出帧计数，当前约 30 帧/秒时 15 帧约为 0.5 秒；调整输出频率后帧数上限不自动改变。

两项中任一不满足就执行有界补检，优先处理最长超限缺口中间的小窗口；只需提高总比例时，优先已有标签的帧并分散补检时间点。根据全段已识别标签学习 ROI 内的活动子区域，每 30 个输出帧中的固定时间点重新搜索整个配置 ROI。每帧最多放大补检 16 个候选，保留 2 倍、3 倍和锐化 3 倍尝试；总比例已通过但仍有长缺口时继续补检，两项同时达标才停止。若已有连续超过上限的帧完成补检后仍无效，或已知重复 ID/源时间缺失使其无法恢复，其他帧不能桥接这段缺口，提前以 `unrecoverable_gap` 失败，不再尝试无关帧。补检解码从目标前的关键帧开始，保留邻帧做最近 PTS 匹配。快速扫描已得到的其余有效帧全部保留，重复 ID 或两轮识别冲突不会通过补检变成有效测量。

快速角点与补检角点保存在批次 `.pipeline/tasks/<任务>/cache/sampled_tags/`。角点身份包含原片、输出时间点、ROI 和检测设置。几何缓存绑定角点内容与当前测量。收紧覆盖要求时复用已有角点，继续补检尚未尝试的帧。双向补检遇到反光时用局部对比度增强来定位，再根据原帧黑边消除亮度梯度，并逐格校验编码。覆盖验收与轨迹验收分别记录；`data/episode.json` 保存各手的测距比例、门限、超限缺口帧号和原片时间，CSV 保留缺失标记。配置了 `gripper.tag_distance` 的手会执行这项验收。

夹爪检测和测距共用 `umi/infra/file_store.py` 的 NPZ 缓存读写。裁剪后的任务先查自己的快速角点缓存，首次缺失时才从完整时间轴的检测结果复制对应帧。补检跟踪当前有效帧、仍可补检的帧和超限缺口，停下后生成完整验收报告。

`episode.json` 的 `tag_distance.<手>` 唯一保存尺寸、内参、检测设置、有效比例和拒绝原因数量。`umi-view` 同步显示当前帧间距，双手分别显示。重投影与双解检查是内部质量检查，实际毫米精度仍需独立测量核验。

## 像素锚点开口宽度

像素到毫米的双标签映射由 `calibration.pixel_distances_to_widths()` 实现。

```text
umi/perception/gripper/
├── calibration.py       开口锚点/标签边长读取、像素—毫米映射
├── width_estimation.py  开口换算、时间对齐与报告
├── video_tools.py       预览、采样监测与标签叠加视频
├── detection/
│   ├── markers.py       灰度图检测、角点和歧义处理
│   ├── frames.py        源像素检测入口、逐帧像素距离缓存
│   └── sampling.py      输出时刻采样、快速角点与有界补检缓存
└── distance/
    ├── pose_estimation.py KB4 标签位姿、中心距离与位姿质量策略
    └── measurement.py   测距输入输出、几何缓存、时钟对齐与验收
```

像素锚点宽度的原片提取默认也限制在 `600 980 1350 1250` 范围。通用 `MarkerDetector` 仍支持显式不指定 ROI 的自动活动区域模式；正式场景中心距及两个宽度 CLI 均提供固定 ROI，范围外的标签不参与当前检测。不把前帧位置作为当帧测量。

像素锚点宽度提取使用级联检测：先执行快速模式，唯一的 ID 0/1 均解码成功时直接使用；目标缺失时，在同一帧、同一搜索区域执行完整模式。快速检测已发现的重复目标保留为歧义；两次检测的同 ID 位置冲突、或同一物理标签被赋予不同 ID 时，拒绝该帧测量。原片仍逐帧解码，不减少采样或沿用前帧距离。检测器身份变化会生成新的缓存，旧缓存保留。

完整模式的主检测沿用 main 的双 ArUco 参数；目标缺失时，在当前搜索区域的同帧锐化图上以较小的自适应阈值常量补检。仍缺失时，从两次检测返回的未解码四边形中选择候选区域，保留周围边距后放大 2 倍、3 倍重试，最后尝试锐化的 3 倍图。

detect-width 的快速模式针对小标签使用 7～23 像素、步长 4 的五个阈值窗口，每个解码格子取 8×8 像素并忽略 25% 的格子边缘。主检测的阈值常量为 7，同帧锐化补检使用 2，以保留暗标签边缘；去掉 3 像素窗口减少噪声候选的开销。不模糊或放大源图，不增加检测轮次和纠错位数；高密度格子采样只发生在候选四边形的规范图像内。完整模式保持原有阈值设置，并作为场景级联检测的补检路径。两种模式的补检均拒绝给已识别的同一物理标签追加另一个 ID。检测策略改变可能使共有检出帧的中心估计略有变化，测量锚点应使用一致的处理方式核验。

`umi-scene run/build` 默认把 OpenCV 限为 4 个线程，避免小区域检测启用整机全部 CPU 线程；可用环境变量 `UMI_OPENCV_THREADS` 覆盖（正整数）。该设置在任务并发前生效，任务内部不反复修改进程级线程数。

快速补检使用 `2 × 灰度图 − GaussianBlur(灰度图, sigma=2)` 增强局部对比度，使暗标签格子更容易解码；完整模式的 sigma 仍为 1。模糊图仅用于锐化差分，不作为独立的平滑检测输入。该设置无需额外 CLI 参数；单纯放大 --contrast 并非越大越好，应结合实际标签框检查饱和和漏检。

候选区域合并嵌套框，过滤过小、过大和过细的区域，每帧最多处理 96 个；补检仍须通过同一字典的 ID 解码，不放宽编码纠错。局部放大坐标按 OpenCV 像素中心关系 `(scaled + 0.5) / scale - 0.5 + crop_origin` 换回搜索区域，再加活动区域偏移还原原始半幅坐标；只接受中心落在候选附近的结果。重叠裁剪读出的同一物理标签合并，不能给已有标签分配另一个 ID；分离的同 ID 标签仍视为歧义。补检无法保证每帧成功。

分段线性像素—毫米映射由 `calibration.pixel_distances_to_widths()` 计算。使用原片工作镜头的完整 1920×1920 半幅，标记字典为 `DICT_4X4_50`，ID 为 0 和 1；不使用缩小/裁切后的 `front.mp4` 估计毫米宽度。

| 文件 | 场景集成职责 |
|---|---|
| `calibration.py` | 校验 anchors 与开口范围 |
| `frame_detection.py` | 统一原片 ROI 和坐标，按原片及检测器缓存逐帧像素距离 |
| `video_tools.py` | 标签叠加预览、按视频时间采样的快速检测及 CSV/MP4 输出 |
| `width_estimation.py` | 换算毫米、邻近三帧中位数、短缺口插值、内存宽度序列与报告构造 |

宽度测量直接保存在套件目录，由 kit.yaml 各手的 gripper.width 引用相对 JSON 路径。run 在输入入口读取文件，并保存副本与内容哈希，episode.json 保留一份规范化测量与宽度报告，修改文件后重跑即可。插值上限和闭合阈值由 reconstruction/common.yaml 管理，原片检测缓存不依赖它们或测量 JSON。width_estimation.process() 返回对齐后的 WidthSeries 和报告，由场景结果写入器与 TCP 一次合写 trajectory.csv。

无标定的任务继续只输出轨迹；已配置的标定缺失、格式无效或检测出错时任务失败，保留上次成功入口。没有找到标记会保存缺失值，不会当作闭合。超出最大标定开口的结果不作为有效测量，不用短缺口插值掩盖。


像素距离预览入口为 `./umi-calib preview-width INPUT.insv [--out OUTPUT.mp4]`，使用基础环境，无需宽度 JSON 或 Basalt。预览使用完整模式，与场景共用灰度转换和基础检测实现；场景级联优先使用快速模式，检出帧和距离可能略有差别。保留原片帧间时间，输出的 960×960 画面标注原始 1920×1920 像素距离；缺失/重复目标 ID 显示 N/A。编码失败不发布半成品，已有目标文件拒绝覆盖。

预览支持 `--roi LEFT TOP RIGHT BOTTOM`，默认 `600 980 1350 1250`，以原始工作镜头半幅坐标固定检测区域；先裁剪再检测，恢复范围偏移后叠加到完整预览。固定范围不自动扩展或全图重定位。CLI 覆盖仅影响此次运行，不写入套件或场景参数。

无界面检测使用 `./umi-calib detect-width INPUT.insv [--roi LEFT TOP RIGHT BOTTOM] [--hz 30] [--out OUTPUT.csv] [--video-out OUTPUT.mp4 | --no-video] [--benchmark]`，ROI 默认 `600 980 1350 1250`。默认按原片 PTS 以目标频率采样，按原速输出；落后时跳过过期采样，缺失值不沿用前帧。`--benchmark` 不等待、不丢弃计划采样，用来测量包含解码和可选编码的吞吐量。CSV 默认写标准输出，统计摘要写标准错误。

CLI 默认在原片旁保存 `<原名>_width_detect.mp4`，可指定视频路径或关闭视频。MP4 与 CSV 共用同次检测，逐帧显示标签框、ID、中心距离、原片时间和蓝色 ROI 框。检测坐标恢复为原始半幅，显示单独缩小至 960×960；采样或丢样的 PTS 保留，首帧时间归零。CSV 和视频均使用临时文件，成功后发布，拒绝覆盖已有输出。Python `video_tools.monitor()` 的 `video_output=None` 可供只需 CSV 的调用者使用。

PreviewWriter 集中处理图像缩小、叠加、原始 PTS 和 H.264 编码，供 preview-width 与 detect-width 共用；快速监测默认使用 veryfast 预设，开启对比度增强时使用 ultrafast 为检测预留时间，两者均为两个编码线程。增强视频可能更大。CSV 的 detect_ms 不包含编码，最终吞吐统计包含编码及文件关闭。

两个宽度 CLI 均支持 `--contrast GAIN`，默认 1，暗光建议先试 2。只对检测区域做线性灰度增益和饱和裁剪，再执行原有检测与同帧锐化，不追加检测轮次；MP4 对相同 ROI 施加显示增益并标注倍率。几何坐标和源文件不变，但解码结果可变化。快速增强模式将最小标记周长提高到 24 原始像素以抑制噪声；未增强时保持原有门限。增益仅用于此次运行，未接入场景宽度配置。

monitor 与场景、预览共用裁剪和灰度转换；YUV 平面、半平面及 RGB 打包像素都在源格式中先裁剪，保留颜色空间和量程，支持奇数坐标。快速检测跳过候选放大，按原始半幅的最小像素周长限制过滤微小噪声。该入口使用 4 个解码线程，运行期间将 OpenCV 限为单线程，结束恢复调用前设置；不修改场景流程的线程策略或测量锚点。输出坐标恢复为原始半幅像素，不使用毫米换算。

配置、标定格式和轨迹输出字段见[夹爪宽度标定与接入](../../../docs/05-任务同步与夹爪测量.md#夹爪宽度标定与接入)。任务时间以视频时间戳为准，原片帧号与处理后视频帧号分别记录。
